# 第一部分 · 知识讲解

## 1. 程序的三种基本结构

几乎所有程序都由这三种结构组合而成：

| 结构 | 含义 | 本节用到的语法 |
|---|---|---|
| **顺序** | 从上到下逐行执行 | 默认行为 |
| **分支** | 根据条件走不同的路 | `if / elif / else` |
| **循环** | 重复执行某段代码 | `while` |

本节一次把三种都用上了，所以「猜数字」这个题目选得好——它是能同时练到三种结构的最小程序。

## 2. `input()`：读取用户输入

```python
name = input("请输入你的名字：")
```

三个要点：

**一、括号里的字符串是提示语**，会原样打印出来，不会自动换行。所以提示语末尾习惯上加一个空格或冒号，让用户输入的内容不紧贴着文字。

**二、它会暂停程序**，一直等到用户按下回车才继续。这种「等待外部输入」的行为叫**阻塞**。

**三、返回值永远是字符串。** 这是最容易忘的一点：

```python
age = input("年龄：")      # 用户输入 18
print(type(age))          # <class 'str'>  ← 不是 int
age > 10                  # TypeError: '>' not supported between 'str' and 'int'
```

**不管用户输入的看起来多像数字，拿到的都是 `str`。** 想参与数值运算必须先转换。

## 3. 类型与类型转换

Python 是**动态类型**语言：变量不需要事先声明类型，类型由当前存的值决定。

```python
x = 10        # 现在 x 是 int
x = "hello"   # 现在 x 是 str，完全合法
```

常用的转换函数：

| 函数 | 作用 | 失败时 |
|---|---|---|
| `int("42")` | 转整数 | 抛 `ValueError` |
| `float("3.14")` | 转浮点数 | 抛 `ValueError` |
| `str(42)` | 转字符串 | 基本不会失败 |
| `bool(x)` | 转布尔值 | 不会失败 |

**转换失败是会抛异常的**，不是返回 `None`：

```python
int("abc")        # ValueError: invalid literal for int() with base 10: 'abc'
int("")           # ValueError
int("3.14")       # ValueError  ← 注意：带小数点的字符串不能直接转 int
int(3.99)         # 3           ← 但浮点数转 int 可以，直接截断（不是四舍五入）
```

`int("3.14")` 报错而 `int(3.99)` 不报错，这个区别容易踩：前者是「解析字符串」，格式必须是整数；后者是「数值转换」，直接丢掉小数部分。

## 4. 条件分支

```python
if 条件1:
    # 条件1 成立时执行
elif 条件2:
    # 条件1 不成立、条件2 成立时执行
else:
    # 以上都不成立时执行
```

四个要点：

**一、冒号不能省。** `if` 这一行末尾必须有 `:`。

**二、缩进决定代码块。** Python 不用大括号，靠缩进表示「哪些代码属于这个分支」。惯例是 **4 个空格**，而且同一个文件里不能混用空格和 Tab（会抛 `TabError`）。

**三、分支是互斥的。** `elif` 只在前面所有条件都不成立时才判断。所以这两段含义不同：

```python
if x > 0:  print("正")
elif x > 10: print("大于10")     # x=20 时只打印「正」，不会打印「大于10」

if x > 0:  print("正")
if x > 10: print("大于10")       # x=20 时两句都打印
```

**四、`elif` 和 `else` 都是可选的。** 只有一个 `if` 也合法。

### 比较运算符

| 运算符 | 含义 |
|---|---|
| `==` | 相等 |
| `!=` | 不相等 |
| `>` `<` | 大于、小于 |
| `>=` `<=` | 大于等于、小于等于 |

注意 `=` 是**赋值**，`==` 才是**比较**。在 `if` 里写 `=` 会直接语法错误（这是 Python 的好设计，C 语言里 `if (x = 1)` 能编译通过，是经典 bug 来源）。

## 5. 布尔值与真值测试

布尔类型只有两个值：`True` 和 `False`（**首字母大写**，写成 `true` 会报 `NameError`）。

但 Python 里**任何对象都能放在 `if` 后面**，它会自动判断真假。假值只有这几种：

| 假值 | 说明 |
|---|---|
| `False` | 布尔假 |
| `None` | 空值 |
| `0`、`0.0` | 数字零 |
| `""` | 空字符串 |
| `[]`、`{}`、`()`、`set()` | 空容器 |

**除此之外全是真值。** 所以可以这样写：

```python
if items:              # 等价于 if len(items) > 0
    ...
if not name:           # 等价于 if name == "" or name is None
    ...
```

这种写法叫**真值测试**，比显式比较更简洁，是 Python 的惯用法。

> 但要小心一个坑：**非空字符串都是真值**，包括 `"False"`、`"0"`、`"no"`。
> 从文件或环境变量读来的「false」是字符串，`if value:` 会判为真。这个问题在 Day19 会正面遇到。

### 逻辑运算符

| 运算符 | 含义 |
|---|---|
| `and` | 两边都真才真 |
| `or` | 任一边真就真 |
| `not` | 取反 |

Python 用这三个**英文单词**，不是 `&&` `||` `!`。（`&` 和 `|` 在 Python 里是按位运算，含义完全不同——这个区别在 Day14 会造成一个真实的 bug。）

## 6. `while` 循环

```python
while 条件:
    # 条件为真时反复执行
```

先判断条件，为真则执行一次循环体，然后回到开头再判断，直到条件为假。

**最常见的写法是 `while True`**——无限循环，靠循环体里的 `break` 来退出：

```python
while True:
    user_input = input("请输入（q 退出）：")
    if user_input == "q":
        break
    print("你输入了", user_input)
```

为什么不把退出条件写在 `while` 后面？因为很多时候**条件要等循环体执行一部分才能判断**（这里得先读到输入才知道是不是 `q`）。`while True` + `break` 把「什么时候退出」放在它真正能被判断的位置。

> `while 1` 也能工作（`1` 是真值），但应该写 `while True`——Python 有真正的布尔类型，用它表达意图更清楚。

## 7. 四个「结束」：break / continue / return / exit

这四个关键字都会中断当前的执行流，但**作用范围层层扩大**：

| 关键字 | 结束什么 | 之后执行哪里 |
|---|---|---|
| `continue` | 本轮循环 | 回到循环开头，继续下一轮 |
| `break` | 整个循环 | 循环后面的代码 |
| `return` | 整个函数 | 调用该函数的地方 |
| `exit()` | 整个程序 | 什么都不执行了 |

**混用会出问题，而且往往不报错**。比如想退出循环却用了 `exit()`，循环后面的所有代码（保存记录、打印统计、再来一局）都会被跳过——程序看起来「正常结束」了，但实际上少做了事。

这个坑在第二部分会实际遇到。

> 嵌套循环里的 `break` 只跳出**最内层**那一层。想跳出多层得用标志变量，或者把循环抽成函数后用 `return`。

## 8. `is` 与 `==`：身份与相等

这是初学时最容易混的一对：

| 运算符 | 比较什么 |
|---|---|
| `==` | **值**是否相等 |
| `is` | 是否为**同一个对象**（内存中同一份） |

```python
a = [1, 2, 3]
b = [1, 2, 3]
a == b        # True   ← 值一样
a is b        # False  ← 两个独立的列表对象

c = a
a is c        # True   ← c 和 a 指向同一个列表
```

**`is` 只该用在三个地方**：

```python
x is None          # 判断是否为 None（标准写法）
x is True          # 判断是否为 True 本身
type(x) is int     # 精确判断类型（见下）
```

### 判断类型不要用 `is` 比较值

初学时容易写出这种代码：

```python
if user_input is int:     # 永远是 False
```

这是在问「`user_input` 这个对象是不是 `int` 这个类型对象本身」，当然不是。正确写法是：

```python
isinstance(user_input, int)     # 推荐：支持子类
type(user_input) is int         # 精确：不接受子类
```

两者的区别在 Day11 会很重要（因为 `bool` 是 `int` 的子类）。

## 9. 字符串的判断方法

字符串自带一组 `isXxx()` 方法，返回布尔值：

| 方法 | 判断 | 边界 |
|---|---|---|
| `s.isdigit()` | 是否全是数字字符 | **不认负号和小数点** |
| `s.isalpha()` | 是否全是字母 | 中文也算字母 |
| `s.isalnum()` | 是否全是字母或数字 | |
| `s.isspace()` | 是否全是空白字符 | |
| `s.startswith(x)` | 是否以 x 开头 | |
| `s.strip()` | 去掉首尾空白 | 返回新字符串，不改原值 |

`isdigit()` 的边界要记住：

```python
"123".isdigit()      # True
"-5".isdigit()       # False  ← 负号不是数字字符
"3.14".isdigit()     # False  ← 小数点也不是
"".isdigit()         # False  ← 空字符串
```

**它判断的是「每个字符都是数字字符」，不是「能不能转成数字」。** 这两件事不等价，Day03 会给出更通用的做法。

## 10. 代码风格：PEP 8 基础

Python 有官方风格指南 PEP 8，几条现在就该遵守的：

- **缩进用 4 个空格**，不用 Tab
- **变量名用小写加下划线**：`input_num`，不是 `inputNum` 或 `InputNum`
- **运算符两边加空格**：`a = 1`、`x > 10`，不是 `a=1`、`x>10`
- **逗号后面加空格**：`f(a, b)`，不是 `f(a,b)`
- 名字要表达含义，`input_num` 比 `n` 好

风格不影响程序能否运行，但影响**别人（和三个月后的你）能否快速读懂**。后面会用 `ruff` 这类工具自动检查。

# 第二部分 · 当天的练习

## 一、题目

写一个程序，让用户输入数字并与 10 比较：大于 10 输出「太大了」，小于输出「太小了」，相等输出「猜对了」。

**升级一：** 没猜中就一直让用户重新输入。
**升级二：** 允许用户输入 `q` 主动退出。

这三步是同一个程序的递进，不是三道独立的题。后面十几天的练习也都在这个「猜数字」上继续加码，所以第一版的代码结构值得写清楚。

## 二、第一版：分支判断

```python
input_num = int(input("请输入数字"))

if input_num > 10:
    print("输入的数字太大了")
elif input_num < 10:
    print("输入的数字太小了")
else:
    print("猜对了")
```

这一版是对的，用到了四个基础点：`input()` 取输入、`int()` 转类型、`if/elif/else` 分支、`>` 与 `<` 比较。

唯一的建议是提示语后面留个空格，`input("请输入数字： ")`，输出好看一些。

## 三、升级一：循环

当时的写法：

```python
while 1:
    input_num = int(input("请输入数字"))
    if input_num > 10:
        print("输入的数字太大了")
    elif input_num < 10:
        print("输入的数字太小了")
    else:
        exit(0)
```

能跑，但有两处值得改。

### 坑 1：`while 1` 不如 `while True`

`1` 在布尔上下文里等价于 `True`，所以 `while 1` 能正常工作。但 Python 有真正的布尔值，`while True` 表达的是「无限循环」这个意图，可读性更好。这是风格问题，不是 bug。

### 坑 2：用 `exit(0)` 退出循环

```python
else:
    exit(0)        # ← 退出的是整个程序
```

应该是：

```python
else:
    print("猜对了")
    break          # ← 只结束当前循环
```

**区别在作用范围**：`break` 结束的是**当前这一层循环**，程序继续往下走；`exit()` 直接**终止整个进程**，循环后面的代码一行都不会执行。

这题里两者表现一样，是因为猜中之后本来就没有后续逻辑了。但一旦后面要加「再来一局吗」或者「保存本局记录」，用 `exit()` 就会把这些代码全部跳过——而且很难调试，因为程序看起来「正常结束」了。

> 规律：**想结束一个循环用 `break`，想结束一个程序才用 `exit()`。** 在函数里想提前返回，用 `return`。

## 四、升级二：输入校验

这一步引入了新问题：用户输入 `q` 时，`int("q")` 会直接抛 `ValueError` 让程序崩掉。所以**不能一上来就 `int()`**，得先判断输入是什么。

当时的写法：

```python
from pydantic.v1.validators import Number

while 1:
    input_num = input("请输入数字")
    if input_num is Number:          # ← 这里是错的
        input_num = int(input_num)
        ...
```

思路对了（先判断再转换），但判断的写法错了两处。

### 坑 3：`is` 不是类型判断

`is` 判断的是**两个变量是否指向同一个对象**，不是「是不是某种类型」。`input_num is Number` 永远为假，所以那个分支一次都不会进。

顺带记住：判断类型该用 `isinstance(x, int)`，不要用 `type(x) == int`，后者遇到子类会判错。

### 坑 4：`input()` 的返回值永远是字符串

不管用户敲 `123` 还是 `q`，`input()` 拿到的都是 `str`。所以压根不存在「输入的是数字类型」这回事——只存在「这个字符串看起来像不像数字」。

判断它该用字符串自己的方法：

```python
"123".isdigit()   # True
"abc".isdigit()   # False
```

### 坑 5：为一个不需要的功能引入依赖

`from pydantic.v1.validators import Number` 这行是多余的。这道题只需要标准库，而且 `pydantic` 的 `Number` 本来也不是用来做这种判断的。

> 习惯：**先问标准库有没有现成的**。多一个第三方依赖就多一份安装、版本和安全负担，而这题的答案 `str.isdigit()` 就在字符串类型自带的方法里。

## 五、最终代码

```python
while True:
    input_num = input("请输入数字")

    if input_num.isdigit():
        input_num = int(input_num)
        if input_num > 10:
            print("输入的数字太大了")
        elif input_num < 10:
            print("输入的数字太小了")
        else:
            break
    else:
        if input_num == 'q':
            break
```

结构是**先校验、再转换、后比较**，这个顺序在后面处理文件读写和 HTTP 响应时会反复出现。

还可以继续改进的地方（后面几天会做）：

- 猜中和主动退出都走 `break`，但没区分提示语，外面分不清是哪种情况结束的
- 输入既不是数字也不是 `q` 时（比如 `abc`），程序静默重来，没有任何提示
- 负数输入 `-5` 时 `isdigit()` 返回 `False`，会被当成非法输入——`isdigit()` 不认负号

## 六、复习自测

1. `input()` 的返回值是什么类型？用户输入 `42` 时，`input() > 10` 能正常比较吗？
2. `break`、`exit()`、`return` 三者分别结束什么？
3. 为什么 `if x is Number` 判断不出 x 是不是数字？判断类型该用什么？
4. `"-5".isdigit()` 返回什么？如果要支持负数输入，该怎么改？
5. `while 1` 和 `while True` 有功能差别吗？该用哪个？

<details>
<summary>参考答案</summary>

1. 永远是 `str`。不能比较，`str` 和 `int` 之间用 `>` 会抛 `TypeError`，必须先 `int()` 转换。
2. `break` 结束当前所在的那一层循环；`exit()` 终止整个程序进程；`return` 结束当前函数并返回值。
3. 因为 `is` 比较的是对象身份（是否同一个对象），不是类型。判断类型用 `isinstance(x, int)`。
4. 返回 `False`，因为 `isdigit()` 不认负号。要支持负数可以用 `lstrip('-').isdigit()` 先剥掉负号，或者直接 `try: int(s) except ValueError:` ——后者是 Day9 之后的标准做法。
5. 没有功能差别，`1` 在布尔上下文里就是真值。但应该用 `while True`，意图更明确。

</details>
