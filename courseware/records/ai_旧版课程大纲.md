# Python 工程化实战

> 从一个猜数字程序，到一个有测试、有日志、有配置管理的 API 客户端。

这门课不教「Python 语法大全」。它只回答一个问题：**一个能跑的脚本，怎么一步步变成能交付的代码。**

## 这门课的特点

**一个项目贯穿全程。** 第 1 章写的猜数字游戏，第 33 章会变成一个带单元测试、Mock、Fixture 的 API 客户端。每一章都在上一章的代码上加东西，不换例子。

**所有「常见错误」都是真实踩过的。** 附录 A 那份错误手册里的每一条，都来自一次真实的 bug，而且**每一条都在本地复现过**，附带真实报错输出。比如：

- `assert` 在 `python -O` 下会被完全删除，用它校验用户输入等于没校验
- `except` 顺序写错，后面的分支成为死代码，Python 不报错也不警告
- 测试一次都没跑过，但你以为跑过了（`pytest` 输出 `collected 0 items`）

**每章都能动手。** 配套代码仓 [`code/`](../ai/code/) 里每章有示例、练习骨架（带 `TODO`）、参考答案和测试。练习分两级：**基础**（跟着做）和**进阶**（自己想）。

## 适合谁

| | |
|---|---|
| **适合** | 学过一点 Python 语法，但不知道「工程化」要做什么；能写脚本，但代码一改就崩 |
| **也适合** | 完全零基础，愿意从第 1 章顺序学完（M1 模块不跳过） |
| **不适合** | 想学 Web 开发、爬虫、数据分析的具体框架。这门课讲的是它们下面那一层 |

**需要准备的**：一台装得上 Python 3.10+ 的电脑，和一个能敲命令的终端。不需要数学基础。

## 学完能做什么

这是可以验证的清单，不是「理解了 XX」：

1. 把一个几百行的单文件脚本拆成合理的多模块项目，并说清每个模块的职责
2. 给任意一个纯函数写出覆盖正常值、边界值、异常值的测试，并验证测试本身有效
3. 看懂 Python 的异常继承层次，写出顺序正确的 `except` 链
4. 区分「返回空值」和「抛异常」两种错误处理策略，并为具体场景选对
5. 用 `logging` 替代 `print`，并说清为什么模块里只 `getLogger`、配置只在入口做
6. 调用一个 HTTP API，正确处理超时、连接失败、状态码错误、响应格式错误四类问题
7. 把密钥从代码里移出去，并支持开发/测试/生产三套配置
8. 用 `MagicMock` 隔离网络依赖，给 API 客户端写出不联网就能跑的单元测试
9. 用 `pytest` fixture 管理测试资源，保证测试之间互不影响

## 时长

**33 章，合计约 35 小时。** 完整版章节（0.1 - 3.2）每章 1~2 小时，精简版章节（3.3 起）每章 30~50 分钟。有基础的话跳过 M1，可以再省 12 小时左右。

模块之间有依赖，**顺序学**。M1 已经会的可以快速翻过，但 M1.8（字典元组集合）和 M1.9（边界条件）别跳——后面模块反复用到。

## 配套代码

全部代码在 [`code/`](../ai/code/)，按模块分目录：

```
code/
  pyproject.toml              依赖与工具配置
  m01_basics/
    ch01_01_example.py        讲解里的可运行示例
    ch01_01_exercise.py       练习骨架，带 TODO
    ch01_01_solution.py       参考答案
  ...
  tests/
    test_m01.py               每个模块的测试
```

跑起来：

```powershell
# 1. 建虚拟环境（第 0.2 章详细讲）
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. 安装依赖
pip install -e ".[dev]"

# 3. 跑某一章的示例
python -m m01_basics.ch01_01_example

# 4. 跑测试
pytest
```

**练习的做法**：打开 `*_exercise.py`，按 `TODO` 写，然后 `pytest tests/test_m01.py -k ch01_01` 验证。卡住了再看 `*_solution.py`。

## 这门课从哪来

它是从一份真实的学习记录整理出来的：一个人用 23 天、每天 1 小时跟 ChatGPT 学 Python 工程化的全部对话。原始记录保留在 [`../../python/`](python/)，按学习日编号，包含每天的提问、代码演进和讲评。

**两者的区别：**

| | 学习记录（`courseware/python/`） | 这门课（`course/python-engineering/`） |
|---|---|---|
| 编号 | 按学习日（Day01-Day22） | 按知识模块（M0-M8） |
| 顺序 | 当时怎么学的 | 怎么教更顺 |
| 内容 | 含个人练习、小测、提问 | 只留可复用的知识与练习 |
| 完整性 | 有缺口（字典、类、装饰器没系统讲） | **补齐了 6 章** |
| 代码 | 练习状态，含已知 bug | 修正版，可运行、有测试 |

**想看「当时是怎么踩坑的」就去读学习记录，想系统学一遍就读这门课。**

整理时所有代码和结论都在本地复跑验证过，查出 5 处当时没发现的真问题——它们现在是附录 A 的主要内容。
