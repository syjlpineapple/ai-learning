## 一个重要的结构转折：课程被重新设计过

B 线最初不是「第 N 课」的形式，而是「第 N 天练习」——直接上 NumPy 数学题。两天之后出现了转折：

```
2026-10-20 16:54  我已经感觉有难度了，正常吗，是不是我不适合，基础太薄弱
2026-10-20 16:56  我学习 NLP 时感觉有难度。最难的部分是：数学公式；
                  我的学习感受是：能看懂一点，但需要反复读很多遍。
                  请据此调整我的 NLP 学习节奏，从适合初学者的基础开始带我学习。
2026-10-20 16:57  我完成了第1课的小练习，选择了B。请继续用这种拆解字母、
                  解释含义、生活例子和小练习的方式，带我学习下一个基础概念。
```

**从这里开始，教学方式换成了「拆解字母 → 解释含义 → 生活例子 → 小练习」的渐进模式**，
并重新从「第 1 课」开始编号。所以：

| 体系 | 时间 | 形式 | 难度 |
|---|---|---|---|
| **第 N 天练习** | 10-19 ~ 10-20 | 直接做 NumPy 数学题 | 偏陡 |
| **第 N 课**（第 1-33 课） | 10-20 ~ 11-17 | 一课一概念 + 选择题小测 | 渐进 |

两套编号并存，这也是代码文件 `day_N.py` 和课时「第 N 课」对不上的根本原因。

**这个转折本身值得记**：学不动的时候，调整的不该是「硬扛」，而是**要求换一种讲法**。
那句反馈里说清了三件事——难在哪（数学公式）、当前水平（能看懂但要反复读）、期望（从基础开始），
所以调整后的节奏才对得上。

## 整理时实测查到的几件事

### 第一个发现：L2 归一化掩盖了第二处差异

第 23 课那次「手算 TF-IDF 和 sklearn 对不上」的排查，当时查出原因是 **L2 归一化**，结论正确。
但实测发现**其实有两处差异**：

| | 手算 | sklearn |
|---|---|---|
| TF | `count / 文档长度` = 1/3 | **`count` = 1**（不除长度） |
| IDF | $\ln\frac{N+1}{df+1}+1$ | 相同 |
| 归一化 | 无 | L2 |

两边的原始 TF-IDF 差了 3 倍（文档长度），但 **L2 归一化会消掉整行的公共缩放因子**，
所以默认情况下最终结果仍然一致。开 `norm=None` 之后差异就暴露了。

**结果对上了，不代表每一步的理解都对。** 详见 [05_文本向量化](05_文本向量化.md) 第二部分。

### 第二个发现：数据泄漏在第 27 课那组数据上有多严重

`course_27.py` 先 `fit_transform(全量)` 再划分，当时课件提醒过「应该先划分再 fit」，但没展示后果。实测：

| 写法 | 词汇表大小 | 测试集第一条的特征 |
|---|---:|---|
| 泄漏（先 fit 全量） | 18 | 有非零特征 |
| 规范（只 fit 训练集） | 15 | **全零向量** |

泄漏的 3 个词是 `['不好', '拍照', '效果']`，正好是测试集两条评论独有的词，其中 **`不好` 是区分好评差评的关键词**。

按规范写法训练逻辑回归，准确率仍是 **1.0**，但第一条测试样本是全零向量，模型只剩截距
$b=-0.034$ 可用，$P(0)=0.5086$ 对 $P(1)=0.4914$ ——**差 0.017，靠抛硬币猜对的**。

**所以「数据量不足、结论不成立」这条，在第 27 课就已经成立了**，不用等到第 32 课。
规范写法反而暴露了真问题：训练集和测试集的词汇几乎不重叠。详见
[06_机器学习流程](06_机器学习流程.md) 第二部分。

### 第三个发现：第 29 课那个 16.7% 的根因，和 `max_iter` 无关

`course_28.py` 里写的是 `LogisticRegression(max_iter=10)`，当时的建议是「设置为 10 可能不够，
可能出现模型尚未收敛的警告」。**这个解释在这组数据上不成立**：

```text
max_iter = 10    →  n_iter_ = [5]，测试准确率 0.1667
max_iter = 100   →  n_iter_ = [5]，输出完全相同
max_iter = 1000  →  n_iter_ = [5]，输出完全相同
```

**模型第 5 次迭代就收敛了，没有 ConvergenceWarning。** 验证收敛的权威方法是打印 `model.n_iter_`。

真正的根因是**词汇覆盖**，实测 6 条测试评论的情感词**全部未登录**：
`慢`、`不错`、`棒`、`模糊`、`很差`、`屏幕显示`。模型只能看到中性词，6 个好评概率
全挤在 0.42~0.60 之间——这组概率本身就是「没有判别能力」的证据。

还查到三件当时没发现的事：

| 发现 | 证据 |
|---|---|
| **标注错误** | `model_b.py` 把「这个手机屏幕非常清晰」标成 0（差评），而「拍照效果非常清晰」标 1，`清晰` 的权重被压到 **+0.063** |
| **「好」「差」都不在训练词汇表** | 训练集只切出 `好用`/`不好`/`太差`/`很差`，所以 `model_b` 的 4 条好评全部误判，**好评 F1 = 0** |
| **「电池」被学成好评词** | 权重 **+0.427**，把两条含「电池」的差评推过了 0.5；「这个」被学成 -0.315 |

阈值实验也得重新解释：阈值 0.42 让好评 F1 从 0 升到 0.4，看着像改善，实际是**从「全错」
变成「蒙对一部分」**；而阈值 0.3 和 0.7 都能拿 0.5 的准确率——在 4:4 平衡的测试集上，
**0.5 就是抛硬币**。详见 [07_模型评估](07_模型评估.md) 第二部分。

### 第四个发现：第 30-32 课那个 0.83 的 gap 不是过拟合

第 30-32 课连续三课在调 `C`，训练 100% / 测试 16.7% / gap 83.3% 始终不动，结论是「符合过拟合的典型表现」。
**这个判断站不住。**

过拟合的测试表现应该**接近随机**。实测：

| | 准确率 |
|---|---:|
| 模型预测 | **0.1667** |
| 全部预测同一类（基线） | 0.5000 |
| **把模型预测整体取反** | **0.8333** |

测试集是 3:3 平衡的，瞎猜能拿 0.5，模型只拿 0.17——**比瞎猜差 3 倍**。
取反能到 0.83，说明模型**稳定地学到了一个反向规律**，不是「没学到」。
真实根因是第 07 节查到的那个：情感词全部未登录，模型只能靠「电池」（+0.427）、
「这个」（-0.315）这类中性词的巧合权重做判断。

**诊断错了就会吃错药。** 两种手段的对比：

| 手段 | 幅度 | 测试准确率 |
|---|---|---|
| 调 `C` | 跨 **10 个数量级**（100 → 1e-8） | **0.1667 → 0.1667**（完全不动） |
| 补训练数据 | **12 条**（覆盖未登录词） | **0.1667 → 0.3333**（翻倍） |

另外两件实测查到的事：

- **L2 怎么压都不改变预测。** C 很小时权重**等比例缩小**（1.664e-4 → 1.664e-5 → 1.664e-6），
  方向不变，而线性分类器只看 $w\cdot x$ 的符号——`sign(k·w·x) = sign(w·x)`。
  **L2 调的是自信度，不是判断。**
- **L1 在 `C=1` 时把 37 个权重全部压成 0**，训练/测试准确率都掉到 0.5。
  这是「欠拟合 = 两边都差」的活标本。原因是 TF-IDF 特征值本来就小（L2 归一化后 0.2~0.5），
  顶不住 L1 的恒定推力。**L1 和 L2 不是强弱关系，是机制不同**——同一个 `C`，L2 温和，L1 毁灭性。

详见 [08_过拟合与正则化](08_过拟合与正则化.md) 第二部分。

### 第五个发现：交叉验证自己也不稳，而且泄漏这次没留下痕迹

第 33 课的五折结果是 `[0.25, 0.5, 0, 0, 0.33]`，平均 21.67%，标准差 19.44%。四件实测：

**一、「学反了」这个结论在 18 条数据上重复出现。** 用 `cross_val_predict` 拿全部
out-of-fold 预测：准确率 0.2222，**取反 0.7778**。第 08 节那个 0.8333 只有 6 条样本、
还能被质疑为巧合，现在它在 18 条数据和 5 个不同的训练集上重复了——不是巧合。

**二、换 `random_state`，平均准确率在 0.15 ~ 0.3833 之间漂，极差 0.2333。**
`StratifiedKFold` 自己也有随机种子。**交叉验证只是把偶然性从「一次划分」缩小到
「一组划分」，没有消除它。** 解法是 `RepeatedStratifiedKFold`，第 33 课没讲到。

**三、用 CV 选 `C`，选出来的是噪声。** 各种影响的量级排下来：

| 改动 | 对平均准确率的影响 |
|---|---:|
| 改 `C`（跨 4 个数量级） | 0.0667 |
| 改折数 K（3 / 5 / 9） | 0.1722 |
| **改 `random_state`（同一个 C）** | **0.2333** |
| 单折标准差 | 0.16 ~ 0.19 |

**超参数的影响比随机种子还小。** 判断标准很朴素：**两组参数的平均分差距小于标准差，
就不能说哪个更好**——单次划分给不了这个判断，这正是交叉验证最有价值的地方。

**四、Pipeline 写法和泄漏写法分数完全相同**（连每折分数都一样，差 0.0000），
尽管每折确实泄漏了 3~6 个词。**但这不能证明 Pipeline 可以省**：你事前不知道这次会不会有影响，
而且这个模型本来就全错，泄漏也救不了它。

这已经是第三次遇到同一类现象了：

| 节 | 现象 |
|---|---|
| 05 | L2 归一化**掩盖**了 TF 定义差异，结果却对上了 |
| 07 | `max_iter=10` 看起来像根因，实测 5 步就收敛 |
| 09 | 泄漏确实存在，分数却完全相同 |

**结果对了不代表过程对了，结果相同不代表没有问题。** 详见 [09_交叉验证](09_交叉验证.md) 第二部分。

> 原计划 8 节，第 7-17 课的内容密度太高，拆成了「导数与梯度」和「梯度下降」两节，共 9 节。

### 数学地基这四节的脉络

```text
01  向量、矩阵、点积          ——  计算工具
02  公式 → 变量 → 函数 → 参数 → 损失  ——  问题是什么
03  导数 → 链式法则 → 梯度公式   ——  怎么知道往哪调
04  更新公式 → 学习率 → 训练循环  ——  真的跑起来
```

**第 04 节的那五步训练循环，和 PyTorch 的写法一一对应。** 手写过这五步，
后面看深度学习框架就不是黑盒——区别只是梯度不用手推（自动求导）、优化器更聪明。
