# 第一部分 · 知识讲解

## 1. 为什么 NLP 要从 NumPy 开始

计算机不能直接处理文字，必须先把文字变成数字。而「一段文字」变成的不是一个数字，是**一串数字**——也就是向量。

```text
"我喜欢这部电影"  →  [1, 0, 2, 0, 1, ...]
```

多条文本摆在一起就成了矩阵。于是整条 NLP 技术栈都建立在**向量和矩阵运算**上：

| NLP 里的操作 | 底层是什么数学 |
|---|---|
| 把文本变成特征 | 构造向量 |
| 模型计算预测分数 | 向量点积 |
| 一次处理一批文本 | 矩阵乘法 |
| 统计每个特征的平均值 | 按轴求均值 |
| 判断两段文本有多像 | 余弦相似度（基于点积） |

NumPy 是 Python 做这些运算的标准工具。**不懂 NumPy，后面的 sklearn、PyTorch 全是黑盒。**

## 2. `ndarray` 与 Python 列表

```python
import numpy as np

X = np.array([
    [1, 0, 2],
    [0, 1, 1],
    [2, 1, 0]
])
```

`np.array()` 创建的对象叫 `ndarray`（N 维数组），和 Python 列表有三个本质区别：

| | Python `list` | NumPy `ndarray` |
|---|---|---|
| 元素类型 | 可以混杂 | **必须统一** |
| 运算 | `[1,2] + [3,4]` → 拼接成 `[1,2,3,4]` | `+` 是**逐元素相加** |
| 性能 | 慢（纯 Python 循环） | 快（底层 C 实现，向量化） |
| 维度概念 | 嵌套列表，没有正式的「形状」 | 有 `shape`、`ndim`、`dtype` |

```python
[1, 2] + [3, 4]                      # [1, 2, 3, 4]        列表：拼接
np.array([1, 2]) + np.array([3, 4])  # array([4, 6])       数组：逐元素相加
```

**这个区别是初学时最大的认知跳跃**：NumPy 的运算符作用在「每个元素」上，而不是整个容器上。

### 打印格式不同

```python
print(np.array([1, 2, 3]))     # [1 2 3]      空格分隔
print([1, 2, 3])               # [1, 2, 3]    逗号分隔
```

`ndarray` 打印时**不带逗号**。这不是出错，是 NumPy 为了让大矩阵对齐得更整齐而做的设计：

```python
print(X)
# [[1 0 2]
#  [0 1 1]
#  [2 1 0]]
```

想要逗号可以 `.tolist()` 转回列表，或者用 f-string 控制格式：

```python
", ".join(f"{v:.2f}" for v in result)      # '1.00, 0.67, 1.00'
```

> 看到 `[1.         0.66666667 1.        ]` 这种带一堆空格的输出不用奇怪——那是为了小数点对齐补的空格。

## 3. `shape`：形状

```python
X.shape       # (3, 3)
```

`shape` 返回一个元组，表示**每个维度的大小**：

| 对象 | `shape` | 读法 |
|---|---|---|
| 标量 | `()` | 零维 |
| `[1, 2, 3]` | `(3,)` | 一维，3 个元素 |
| `[[1,2,3], [4,5,6]]` | `(2, 3)` | 二维，2 行 3 列 |
| 一批图片 | `(100, 28, 28)` | 三维 |

二维数组的 `shape` 是 `(行数, 列数)`，顺序固定，**行在前**。

### 为什么要时刻关注 shape

机器学习里 90% 的报错是形状不匹配。而且很多时候**不报错但结果是错的**——比如本该按列算却按行算了。

所以有个实用习惯：**写一行矩阵运算，就 `print(x.shape)` 一次**。看形状比看数字快得多，一眼就能发现「怎么变成 3 个数了，应该是 2 个」。

## 4. `axis`：沿哪个方向汇总

```python
X = np.array([
    [1, 2, 3],
    [4, 5, 6]
])

X.mean(axis=0)      # [2.5, 3.5, 4.5]    对每一列求平均
X.mean(axis=1)      # [2.0, 5.0]         对每一行求平均
```

算一遍就清楚了：

- `axis=0`：第 1 列 `(1+4)/2=2.5`，第 2 列 `(2+5)/2=3.5`，第 3 列 `(3+6)/2=4.5`
- `axis=1`：第 1 行 `(1+2+3)/3=2`，第 2 行 `(4+5+6)/3=5`

### 记忆方法

初学时最容易把 `axis=0` 记成「对行操作」，因为 0 对应「行」这个维度。但结果恰好相反。

**准确的说法是：`axis=0` 表示「沿着第 0 个维度（行的方向）汇总，把这个维度压扁」。** 行被压扁了，剩下的就是列。

两个更好用的判断方法：

| 方法 | `axis=0` | `axis=1` |
|---|---|---|
| **看方向** | 沿行的方向（上下）汇总 | 沿列的方向（左右）汇总 |
| **看结果个数** | 等于**列数** | 等于**行数** |

第二个方法最可靠：形状 `(2, 3)` 的矩阵，`mean(axis=0)` 得到 **3** 个数（列数），`mean(axis=1)` 得到 **2** 个数（行数）。

```python
X.shape              # (5, 4)
X.mean(axis=0).shape # (4,)   ← 4 个数，等于列数
X.mean(axis=1).shape # (5,)   ← 5 个数，等于行数
```

> `sum`、`max`、`min`、`std` 都接受 `axis` 参数，规则完全一样。不传 `axis` 则对所有元素汇总成一个数。

## 5. 点积（dot product）

```python
x = np.array([1, 2, 3])
w = np.array([0.2, 0.5, -0.1])

np.dot(x, w)         # 0.9
```

计算方法是：**对应位置相乘，再把乘积全部加起来。**

$$
x \cdot w = 1 \times 0.2 + 2 \times 0.5 + 3 \times (-0.1) = 0.2 + 1.0 - 0.3 = 0.9
$$

两个要点：

- **两个向量长度必须相同**，否则没法对应
- **结果是一个数**（标量），不是向量

### 点积在机器学习里是什么

点积就是**线性模型的核心计算**：

$$
\text{score} = x_1 w_1 + x_2 w_2 + \cdots + x_n w_n + b = x \cdot w + b
$$

含义是：每个特征乘上它的重要程度（权重），加起来得到一个分数。

| 符号 | 在 NLP 里是什么 |
|---|---|
| `x` | 一条文本的特征向量（比如每个词出现了几次） |
| `w` | 模型学到的权重（每个词对判断结果有多重要，正数倾向正面、负数倾向负面） |
| `x · w` | 这条文本的得分 |

**所以逻辑回归、神经网络的每一层，本质都是在做点积。** 这是后面所有内容的地基。

> 点积不是「两个向量相加」，也不是「所有数字相乘」。这三种运算完全不同：
>
> ```python
> a + b          # [6, 8]      逐元素相加
> a * b          # [8, 15]     逐元素相乘
> np.dot(a, b)   # 23          点积（逐元素相乘后求和）
> ```

## 6. 矩阵乘法 `@`

点积处理「一条样本」，矩阵乘法处理「一批样本」：

```python
X = np.array([[3, 0],
              [0, 2],
              [2, 1]])        # 3 条样本，每条 2 个特征

w = np.array([2, -1])         # 2 个权重

scores = X @ w                # [6, -2, 3]
```

计算过程就是**矩阵的每一行分别与向量做点积**：

| 行 | 计算 | 结果 |
|---|---|---|
| 第 1 行 `[3, 0]` | `3×2 + 0×(-1)` | `6` |
| 第 2 行 `[0, 2]` | `0×2 + 2×(-1)` | `-2` |
| 第 3 行 `[2, 1]` | `2×2 + 1×(-1)` | `3` |

**一行代码算完了 3 条样本的分数。** 这就是向量化——不用写循环，底层用 C 批量计算，几万条样本也是一行。

### 形状规则

数学里的规则有两条，很好记：

$$
(3 \times 2)(2 \times 1) = (3 \times 1)
$$

- **中间的数字必须相同**，不同就不能相乘
- **结果保留外侧的数字**

```python
A.shape = (3, 2)
B.shape = (2, 4)
(A @ B).shape        # (3, 4)   ← 中间的 2 对上了，结果取外侧的 3 和 4
```

中间对不上就报错：

```python
# ValueError: matmul: Input operand 1 has a mismatch in its core dimension
```

### 矩阵乘法不能交换顺序

$$
AB \ne BA
$$

甚至 `A @ B` 能算而 `B @ A` 根本算不了（因为维度对不上）。这和普通数字乘法不同（`2×3 = 3×2`），是初学时容易忽略的一点。

## 7. 关键区别：`(n,)` 不等于 `(n, 1)`

这是本节最容易困惑的地方。

```python
w = np.array([2, -1])
w.shape                # (2,)      ← 一维数组

X @ w                  # [6, -2, 3]
(X @ w).shape          # (3,)      ← 结果也是一维
```

而数学上，`(3×2) @ (2×1)` 应该得到 `(3×1)` 的**列向量**。为什么 NumPy 给的是 `(3,)`？

因为 **NumPy 的一维数组没有「行向量」或「列向量」的身份**——它就是 2 个数，没有行列概念。要严格对应数学里的列向量，得显式写成二维：

```python
w = np.array([[2],
              [-1]])
w.shape                # (2, 1)    ← 二维，2 行 1 列

(X @ w).shape          # (3, 1)    ← 现在和数学一致了
```

### 形状对照表

| 左边 | 右边 | 结果 |
|---|---|---|
| `(3, 2)` | `(2,)` | `(3,)` |
| `(3, 2)` | `(2, 1)` | `(3, 1)` |
| `(3, 2)` | `(2, 4)` | `(3, 4)` |

`(3,)` 和 `(3, 1)` 装着相同的数字，但**维度结构不同**，后续运算的行为会不一样（尤其在广播时）。

> 这是实际会踩的坑：某个函数要求 `(n, 1)`，你传了 `(n,)`，可能不报错但结果是错的。
> 转换方法：`w.reshape(-1, 1)` 或 `w[:, None]`。

### 怎么判断 `[6 -2 3]` 是 `(3,)` 还是 `(1, 3)`

光看打印输出分不清，得看方括号的层数：

```python
print(np.array([6, -2, 3]))        # [ 6 -2  3]       一层方括号 → (3,)
print(np.array([[6, -2, 3]]))      # [[ 6 -2  3]]     两层方括号 → (1, 3)
```

**最可靠的办法还是 `print(x.shape)`。** 这也是为什么前面说「写一行矩阵运算就打一次 shape」。

## 8. `@` 和 `*` 完全不同

```python
A = np.array([[1, 2], [3, 4]])
B = np.array([[10, 20], [30, 40]])

A @ B        # 矩阵乘法：[[70, 100], [150, 220]]
A * B        # 逐元素相乘：[[10, 40], [90, 160]]
```

| 运算符 | 含义 | 要求 |
|---|---|---|
| `@` | 矩阵乘法（`np.matmul`） | 左列数 = 右行数 |
| `*` | 逐元素相乘（哈达玛积） | 形状相同，或符合广播规则 |
| `np.dot()` | 一维时是点积，二维时等价于 `@` | |

**写错了往往不报错**（如果形状恰好兼容），只是结果完全不对。这类 bug 最难查，因为程序正常运行、数字看起来也「像」对的。

> `@` 是 Python 3.5 引入的专用运算符（PEP 465），就是为了把矩阵乘法和逐元素乘法在写法上彻底分开。
> 在那之前只能写 `np.dot(A, B)`，容易和 `A * B` 混淆。

## 9. 机器学习的命名约定

```python
X = np.array([...])     # 大写
x = X[0]                # 小写
```

语法上大小写都合法，但机器学习界有一套约定：

| 变量 | 代表什么 | 维度 |
|---|---|---|
| `X` | 特征矩阵（多个样本） | 二维 `(样本数, 特征数)` |
| `x` | 单个样本的特征向量 | 一维 |
| `y` | 标签 / 目标值 | 一维 |
| `w` | 权重向量 | 一维或二维 |
| `b` | 偏置（bias） | 标量 |
| `n` | 样本数量 | |

**大写表示矩阵、小写表示向量或标量**，这来自线性代数的书写传统。

遵守它的好处是：看到 `X.shape` 就知道该是二维的，看到 `X @ w` 就知道在算一批样本的分数。**代码读起来像数学公式。**

## 10. 这些数学在 NLP 里对应什么

| 数学概念 | NLP 中的用途 |
|---|---|
| `shape` | 检查特征矩阵和模型输入的维度是否匹配 |
| `mean(axis=0)` | 统计每个特征（每个词）在整个数据集上的平均值 |
| 点积 | 线性模型计算单条文本的得分 |
| 矩阵乘法 | 一次性计算一批文本的得分 |
| 向量长度 `norm` | 后面算余弦相似度要用（第 20 课） |

一条典型的流程：

```text
3 条句子  →  向量化  →  X (3, 词表大小)  →  X @ w  →  3 个分数  →  判断正负面
```

**本节学的就是这条流程里「→」后面发生的事。**

## 一个值得记住的发现：例子要有区分度

第 1 天用的矩阵是：

```python
X = np.array([
    [1, 0, 2],
    [0, 1, 1],
    [2, 1, 0]
])
```

讲 `axis` 时用这个矩阵有个问题——**它恰好是对称的**，所以 `mean(axis=0)` 和 `mean(axis=1)` 算出来一模一样，都是 `[1, 0.667, 1]`。

当时直接指了出来：

> 所以你这个例子举得不好，这个是对称的看不出来

这个判断是对的。换成这个矩阵，区别立刻清楚：

```python
X = np.array([
    [1, 2, 3],
    [4, 5, 6]
])
X.mean(axis=0)      # [2.5, 3.5, 4.5]    3 个数
X.mean(axis=1)      # [2.0, 5.0]         2 个数
```

**学新概念时，例子不仅要正确，还要能体现概念之间的区别。** 一个两种做法结果相同的例子，看起来讲清楚了，实际上什么都没区分出来——而且会让人误以为自己懂了。

> 这条也适用于自己写测试：Day07（A 线）那个「`assert check_num(30, 50)` 永远通过」的假测试，
> 本质是同一个问题——**无法区分对错的验证等于没有验证。**

## 第 2 天练习（10-20）

代码换成了矩阵乘法：

```python
X = np.array([[3, 0],
              [0, 2],
              [2, 1]])
w = np.array([2, -1])
scores = X @ w
print(scores.shape)     # (3,)
print(X.shape)          # (3, 2)
```

三道小测全对（练习1：b、练习2：a、练习3：b）。

### 当时的四个追问

这四个问题串起来，正好覆盖了形状这个主题最容易混的部分：

**一、「结果为什么是 `(3,)` 和 `(3, 2)`？」**

`X` 是 3 行 2 列，所以 `(3, 2)`。每行与 `w` 做一次点积得到一个分数，3 行得到 3 个数，所以 `(3,)`。

**二、「二维乘以一维得到一维吗？」**

在这个形状组合下是的。但这不是通用规则，而是 `(m, n) @ (n,)` 这种特定形状的行为。换成 `(n, 1)` 结果就是二维了。

**三、「数学中矩阵乘法呢？」**

规则一致，但数学严格区分行向量 `(1×2)` 和列向量 `(2×1)`，而 NumPy 的一维数组两者都不是。这正是 `(3,)` 和 `(3, 1)` 差异的来源。

**四、「`[6 -2 3]` 怎么判断是 `(3,)` 还是 `(1, 3)`？」**

看方括号层数，或者直接 `print(shape)`。这个问题问得很实际——**光看打印的数字是分不清维度的**。

> 这四问的共同点是：**都在追问「形状」而不是「数值」**。这个关注点是对的，
> 因为后面所有的报错和隐性错误，大部分都出在形状上。

1. 列表的 `+` 是**拼接**（`[1,2]+[3,4]` → `[1,2,3,4]`）；数组的 `+` 是**逐元素相加**（→ `[4,6]`）。
2. `mean(axis=0)` 返回 **4** 个（等于列数），`mean(axis=1)` 返回 **5** 个（等于行数）。
3. 看结果个数：`axis=0` 的结果个数等于列数，`axis=1` 等于行数。比记「0 是行还是列」可靠。
4. `a+b = [6, 8]`（逐元素相加）；`a*b = [8, 15]`（逐元素相乘）；`np.dot(a,b) = 23`（相乘后求和）。
5. 对应「每个特征乘以它的权重，再加起来得到一个分数」，也就是 `score = x·w + b`。逻辑回归和神经网络的每一层本质都在做这件事。
6. 结果是 `(3, 4)`。规则：中间的数字必须相同（这里都是 2），结果保留外侧的数字（3 和 4）。
7. `(2,)` 是一维数组，没有行列身份；`(2, 1)` 是二维的列向量。用 `w.reshape(-1, 1)` 可以从前者转成后者。
8. `@` 是矩阵乘法（左列数 = 右行数），`*` 是逐元素相乘（形状相同或可广播）。**如果形状恰好兼容，写错不会报错**，只是结果完全不对——这类 bug 最难查。
9. 约定：大写表示矩阵（多个样本），小写表示向量或标量。好处是代码读起来像数学公式，看到 `X` 就知道是二维的。
10. 因为对称矩阵的 `mean(axis=0)` 和 `mean(axis=1)` 结果相同，**无法区分两者的差别**——例子看起来讲清楚了，实际什么都没区分出来，还会让人误以为懂了。
