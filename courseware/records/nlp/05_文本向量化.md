# 第一部分 · 知识讲解

## 1. 为什么要把文字变成数字

前四节学的全是数字运算：点积、矩阵乘法、梯度下降。但 NLP 的输入是**文字**。

```text
"我喜欢猫"   ← 人能读懂
```

计算机做数学运算需要数字。所以整条 NLP 流程的第一步，永远是**把文本转成向量**：

```text
文本  →  [向量化]  →  数字向量  →  模型（点积、梯度下降）  →  预测
```

本节学的就是中间那个 `[向量化]`。

## 2. 分词与 token

第一步是把一句话切成单位：

```python
text = "我 喜欢 NLP"
tokens = text.split()        # ['我', '喜欢', 'NLP']
```

切出来的每个单位叫 **token（词元）**。

**英文和中文的难度完全不同：**

| | 英文 | 中文 |
|---|---|---|
| 词之间 | 有空格天然分隔 | **没有分隔符** |
| 分词 | `text.split()` 基本够用 | 需要专门的分词器 |

中文的「我喜欢猫」要切成「我 / 喜欢 / 猫」，靠的是词典和统计模型，不是简单规则。所以 `day_5.py` 里的例子是 `"我 喜欢 NLP"`——**手动加了空格**，用 `split()` 绕过了分词问题。

> 真正处理中文要用 **jieba** 这类分词库，第 26 课会用到。
> 现在用 `split()` 是为了先把注意力放在「向量化」上，不被分词细节分散。

## 3. 词表与 token ID

有了 token，下一步给每个词编号：

```python
vocab = {"我": 0, "喜欢": 1, "NLP": 2}
token_ids = [vocab[token] for token in tokens]      # [0, 1, 2]
```

**词表（vocabulary）** 就是「所有认识的词 → 编号」的映射。

### 关键认识：ID 不代表含义

这一点很容易误解。`"猫"` 的 ID 是 2、`"狗"` 的 ID 是 3，但这**不意味着**：

- 猫和狗很接近（因为 2 和 3 相邻）
- 猫比狗「小」（因为 2 < 3）

**ID 只是一个任意编号**，换一个词表顺序，所有 ID 都会变，但词的含义没变。

ID 还有第二个问题：**它表示不了「出现了几次」**。`"猫 猫 猫"` 的 token ID 是 `[2, 2, 2]`，长度和 `"我 喜欢 猫"` 的 `[0, 1, 2]` 一样，但没法直接比较。

所以需要下一步：词袋。

## 4. 词袋模型（Bag of Words）

思路很简单：**固定词表，统计每个词出现了几次，组成向量。**

词表 `[我, 喜欢, 猫, 狗]`：

| 文本 | 我 | 喜欢 | 猫 | 狗 | 向量 |
|---|---:|---:|---:|---:|---|
| 我喜欢猫 | 1 | 1 | 1 | 0 | `[1,1,1,0]` |
| 我喜欢狗 | 1 | 1 | 0 | 1 | `[1,1,0,1]` |

代码（`day_6.py` 里的实现）：

```python
vocab = ["我", "喜欢", "狗", "猫"]
text = ["我", "喜欢", "猫"]

vector = []
for v in vocab:
    count = text.count(v)
    vector.append(count)
print(vector)        # [1, 1, 0, 1]
```

三个要点：

- **向量长度 = 词表大小**，和文本长短无关
- **每个位置的含义固定**（第 0 位永远是「我」出现几次）
- 词表里有、文本里没有的词，对应位置是 **0**

这解决了 ID 的两个问题：现在「猫 猫 猫」是 `[0,0,0,3]`，和「我 喜欢 猫」的 `[1,1,0,1]` 可以直接比较了——**因为它们在同一个坐标系里**。

### 词袋的根本局限：丢掉了词序

```text
"我喜欢猫"  →  [1, 1, 1, 0]
"猫喜欢我"  →  [1, 1, 1, 0]      ← 完全一样
```

两句话意思不同，但词袋向量**一模一样**。这是「袋子」这个名字的来源：**把词扔进袋子里摇一摇，顺序就没了。**

这个局限在真实任务里会出问题，最典型的是**否定**：

```text
"这个不好"     →  [不, 好] 都出现了
"这个好，不贵"  →  [不, 好] 也都出现了
```

**词袋分不清「不好」和「好」+「不贵」。** 根 `README.md` 的待办里提到的 `ngram_range=(1,2)`（bigram）就是为了解决这个——把「不好」作为一个整体特征，而不是拆成两个独立的词。

> 词序问题是 NLP 的核心难题之一，整条技术路线的演进很大程度上就是在解决它：
> 词袋（丢序）→ n-gram（局部序）→ RNN（顺序建模）→ Transformer（注意力机制）。

## 5. 余弦相似度

有了向量，怎么判断两段文本有多像？

**余弦相似度比较的是两个向量的「方向」：**

$$
\text{similarity} = \frac{A \cdot B}{\|A\| \times \|B\|}
$$

| 部分 | 含义 |
|---|---|
| $A \cdot B$ | 点积（第 01 节学的） |
| $\|A\|$ | 向量 A 的长度（模） |
| 相除 | 消除长度影响，只留方向 |

```python
A = np.array([1, 0])
B = np.array([0.9, 0.1])

dot_product = np.dot(A, B)
length_a = np.linalg.norm(A)          # 向量长度
length_b = np.linalg.norm(B)

similarity = dot_product / (length_a * length_b)
print(f"余弦相似度：{similarity:.4f}")        # 0.9939
```

### 三个关键值

| 余弦值 | 几何含义 |
|---|---|
| `1` | 方向**完全相同** |
| `0` | 方向**垂直**（毫不相关） |
| `-1` | 方向**完全相反** |

### 为什么用余弦而不是直接算距离

因为**文本长度不该影响相似度判断**。

```text
文档 A：「猫 喜欢 鱼」           → [1, 1, 1]
文档 B：「猫 喜欢 鱼 猫 喜欢 鱼」 → [2, 2, 2]
```

B 只是 A 重复了一遍，主题完全相同。但两个向量的**欧氏距离**不为 0（差了一倍长度），而**余弦相似度是 1**（方向完全一致）。

**余弦关注「说的是什么」，不关注「说了多少」。** 这对文本相似度是对的选择。

> 一个重要提醒（第 18 课第 3 题考的就是这个）：**余弦相似度高 ≠ 两个词同义。**
> 「苹果」和「手机」可能因为经常出现在相似语境里而相似度很高，但它们不是同一个概念。
> 相似度衡量的是「在当前这个向量表示下有多接近」，而表示方式本身决定了它能捕捉什么。

## 6. TF：词频

词袋用的是**原始计数**，这有个问题：长文档的所有计数都更大。

**TF（Term Frequency，词频）** 用「占比」代替「次数」：

$$
TF(t, d) = \frac{\text{词 } t \text{ 在文档 } d \text{ 中出现的次数}}{\text{文档 } d \text{ 的总词数}}
$$

```python
words = ["猫", "喜欢", "吃", "鱼"]
word = "猫"

tf = words.count(word) / len(words)
print("词频TF:", tf)                   # 0.25
```

这样「猫」在 4 词文档里出现 1 次（TF=0.25）和在 100 词文档里出现 1 次（TF=0.01）就区分开了。

## 7. IDF：逆文档频率

TF 还有个更大的问题：**常见词的 TF 很高，但它们没有区分能力。**

```text
文档 1：「猫 喜欢 吃 鱼」
文档 2：「狗 喜欢 吃 肉」
```

「喜欢」和「吃」在两篇文档里都出现，TF 都是 0.25，和「猫」「鱼」一样高。但显然：

- **「猫」「鱼」能区分这两篇文档**
- **「喜欢」「吃」毫无区分能力**（到处都有）

**IDF（Inverse Document Frequency，逆文档频率）** 衡量一个词有多「稀有」：

$$
IDF(t) = \ln\left(\frac{N}{df(t)}\right)
$$

| 符号 | 含义 |
|---|---|
| $N$ | 文档总数 |
| $df(t)$ | **包含**词 t 的文档数（document frequency） |

**$df$ 越小（越少文档有这个词）→ 比值越大 → IDF 越高。** 稀有词权重高，常见词权重低。

### 为什么要取对数

这是当时追问过的点（第 01 节也提过）。不取对数的话：

```text
N=10000 篇文档
某词只出现在 1 篇里  →  N/df = 10000
某词出现在 100 篇里  →  N/df = 100
```

**差距 100 倍。** 这会让极罕见词（可能只是拼写错误或人名）的权重爆炸式增长，压过所有正常词。

取对数后：

```text
ln(10000) ≈ 9.2
ln(100)   ≈ 4.6
```

**差距压缩到 2 倍。** 对数把「倍数关系」压成「加法关系」，既保留了「越稀有越重要」的次序，又不让差距失控。

> 这是对数在工程里的典型用途：**压缩量级**。类似的场景还有声音的分贝、地震的里氏震级——都是因为原始数值跨度太大。

### 平滑 IDF

实际用的公式多了两处调整：

$$
IDF(t) = \ln\left(\frac{N+1}{df(t)+1}\right) + 1
$$

| 调整 | 作用 |
|---|---|
| 分子分母 **+1** | 防止 $df=0$ 时除以零（这叫**平滑**） |
| 最后 **+1** | 保证 IDF 不为 0，否则在所有文档都出现的词权重会归零、特征直接消失 |

验证第二条：某词在所有文档都出现时 $df=N$，于是 $\ln\frac{N+1}{N+1}=\ln 1 = 0$，加上最后的 +1 得到 **IDF=1**。权重不高，但没被完全抹掉。

**这正是 sklearn 默认用的公式**，所以手算时要用它才能和 sklearn 对上。

## 8. TF-IDF

把两者相乘：

$$
TF\text{-}IDF(t,d) = TF(t,d) \times IDF(t)
$$

含义是：**一个词在这篇文档里出现得多（TF 高）、同时在整个文档集里比较稀有（IDF 高），它的权重才高。**

| 情况 | TF | IDF | TF-IDF | 解读 |
|---|---|---|---|---|
| 本文高频、全局稀有 | 高 | 高 | **高** | 这篇文档的关键词 |
| 本文高频、全局常见 | 高 | 低 | 中/低 | 像「的」「是」 |
| 本文低频 | 低 | —— | 低 | 顺带提了一句 |

手算代码（`day_7.py`）：

```python
import math

documents = [
    ["猫", "喜欢", "吃", "鱼"],
    ["狗", "喜欢", "吃", "肉"]
]

N = len(documents)
word = "猫"

df = sum(word in doc for doc in documents)        # 包含该词的文档数
idf = math.log((N + 1) / (df + 1)) + 1

doc = documents[0]
tf = doc.count(word) / len(doc)
tf_idf = tf * idf
```

> `sum(word in doc for doc in documents)` 这个写法值得记：`word in doc` 返回布尔值，
> 而 **Python 里 `True` 等于 1**（A 线 Day11 讲过 `bool` 是 `int` 的子类），
> 所以直接 `sum()` 就能统计「有多少篇文档包含这个词」。

## 9. `math.log()` 就是 $\ln$

这是当时专门确认过的一个点，容易搞错：

| Python | 数学 | 底数 |
|---|---|---|
| `math.log(x)` | $\ln x$ | **e ≈ 2.71828**（自然对数） |
| `math.log10(x)` | $\log_{10} x$ | 10 |
| `math.log2(x)` | $\log_2 x$ | 2 |
| `math.log(x, base)` | $\log_{base} x$ | 自己指定 |

**`math.log()` 不指定底数时是自然对数，不是以 10 为底。** 这和很多计算器上的 `log` 键（通常是 $\log_{10}$）相反，是个常见误解来源。

TF-IDF 公式里的对数就是 $\ln$，所以 `math.log((N+1)/(df+1)) + 1` 写法正确。

## 10. L2 归一化

这是让手算和 sklearn 对不上的**直接原因**。

**L2 归一化**把整行向量缩放到长度为 1：

$$
x_i' = \frac{x_i}{\sqrt{\sum_j x_j^2}}
$$

分母是整行向量的长度（第 5 节算余弦时用过的那个 `norm`）。

### 为什么要做归一化

和余弦相似度同一个理由：**消除文档长度的影响**。

归一化之后，所有文档向量的长度都是 1，落在同一个「单位球面」上。此时：

- 比较两个文档只需看方向
- **点积直接等于余弦相似度**（因为分母都是 1）

这让后续计算变得简单且可比。

### 关键性质：改变数值，不改变比例

```text
归一化前：[0.4685, 0.4685, 0.3333]
归一化后：[0.632,  0.632,  0.449 ]
```

每个数都变了，但**它们之间的比例没变**（0.4685/0.3333 = 0.632/0.449 = 1.406）。

**所以归一化不影响「哪个词更重要」的判断**，只是统一了尺度。

# 第二部分 · 当时的练习与那次排查

## 第 22 课：手算 TF-IDF

用 `day_7.py` 算「猫」在文档 1 中的 TF-IDF：

$$
TF = \frac{1}{3}, \qquad IDF = \ln\frac{2+1}{1+1} + 1 = \ln 1.5 + 1 \approx 1.4055
$$

$$
TF\text{-}IDF = \frac{1}{3} \times 1.4055 \approx 0.4685
$$

当时写的代码是：

```python
print(1/3 * (math.log(3/2) + 1))      # 0.4685
```

**公式完全正确。**

## 第 23 课：换成 sklearn，数字对不上

`day_8.py` 用 `TfidfVectorizer` 跑同样的数据：

```python
from sklearn.feature_extraction.text import TfidfVectorizer

documents = ["cat like fish", "dog like meat"]
vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(documents)

print(vectorizer.get_feature_names_out())
print(X.toarray().round(3))
```

输出：

```text
['cat' 'dog' 'fish' 'like' 'meat']
[[0.632 0.    0.632 0.449 0.   ]
 [0.    0.632 0.    0.449 0.632]]
```

**手算 0.4685，sklearn 0.632。对不上。**

于是有了那个追问：

> 那为什么 TfidfVectorizer 计算的是 `[[0.632 0. 0.632 0.449 0.]...]`

### 排查过程

**第一步：列出手算的完整矩阵**（不只是「猫」那一个数）

| 词 | TF | IDF | TF-IDF |
|---|---:|---:|---:|
| cat | 0.333 | 1.405 | **0.4685** |
| fish | 0.333 | 1.405 | 0.4685 |
| like | 0.333 | 1.000 | 0.3333 |

文档 A 的原始向量：`[0.4685, 0, 0.4685, 0.3333, 0]`

**第二步：算这一行的长度**

$$
\sqrt{0.4685^2 + 0.4685^2 + 0.3333^2} \approx 0.7417
$$

**第三步：用长度去除每一项**

$$
\frac{0.4685}{0.7417} \approx 0.632, \qquad \frac{0.3333}{0.7417} \approx 0.449
$$

**得到 `[0.632, 0, 0.632, 0.449, 0]`——和 sklearn 完全一致。**

根因：**`TfidfVectorizer` 默认做 L2 归一化**（参数 `norm='l2'`）。关掉的方法是 `TfidfVectorizer(norm=None)`。

### 实测验证

我把整个过程跑了一遍，确认闭环：

```text
=== 1. sklearn 默认输出 ===
[[0.632 0.    0.632 0.449 0.   ]
 [0.    0.632 0.    0.449 0.632]]

=== 2. 手算的原始 TF-IDF ===
[[0.4685 0.     0.4685 0.3333 0.    ]
 [0.     0.4685 0.     0.3333 0.4685]]

=== 3. 手动做 L2 归一化 ===
每行向量的长度: [0.7417 0.7417]
[[0.632 0.    0.632 0.449 0.   ]
 [0.    0.632 0.    0.449 0.632]]

=== 4. 和 sklearn 对比 ===
完全一致吗: True
最大差异: 0.0
```

**手算 + L2 归一化 = sklearn 默认输出，差异为 0。** 当时的结论正确。

## 实测补充：其实有**两处**差异，归一化掩盖了另一处

这是我整理时发现的，当时没查到这一层。

把 `norm=None` 打开，按理说应该得到手算的原始值。但实测：

```text
=== 5. 关掉归一化 norm=None ===
[[1.4055 0.     1.4055 1.     0.    ]
 [0.     1.4055 0.     1.     1.4055]]
和手算一致吗: False
```

**1.4055 而不是 0.4685——正好差 3 倍。**

原因是 **sklearn 的 TF 用的是原始词频，不除以文档长度**：

```text
=== 6. 只看 TF（norm=None, use_idf=False）===
[[1. 0. 1. 1. 0.]
 [0. 1. 0. 1. 1.]]

而手算用的 TF 是 count/len(doc) = 1/3 ≈ 0.3333
```

| | 手算 | sklearn |
|---|---|---|
| **TF** | $\dfrac{\text{count}}{\text{文档长度}} = \dfrac{1}{3}$ | $\text{count} = 1$ |
| **IDF** | $\ln\frac{N+1}{df+1}+1$ | 相同 ✅ |
| **归一化** | 无 | L2 |

所以两边的原始 TF-IDF 差了一个因子 3（文档长度）。

**但为什么加上归一化就对上了？** 因为 **L2 归一化会消掉整行的公共缩放因子**：手算的每一项都是 sklearn 的 $\frac{1}{3}$，归一化时分子分母同时缩小 3 倍，比例不变，结果相同。

$$
\frac{\frac{1}{3}a_i}{\sqrt{\sum_j (\frac{1}{3}a_j)^2}} = \frac{\frac{1}{3}a_i}{\frac{1}{3}\sqrt{\sum_j a_j^2}} = \frac{a_i}{\sqrt{\sum_j a_j^2}}
$$

> **所以当时的排查只找到了两个差异中的一个，而另一个恰好被第一个掩盖了。**
>
> 这个现象值得记：**结果对上了，不代表每一步的理解都对。** 如果哪天用了 `norm=None`
> 或者换成不等长的文档，这个隐藏的差异就会暴露出来。
>
> 验证方法也很直接——**把每一个可疑参数单独关掉试一次**（`norm=None`、`use_idf=False`），
> 而不是只验证最终结果。

## 「先手算，再调库」为什么重要

这次排查之所以可能发生，前提是**先手算过一遍**。

| | 只用 sklearn | 先手算再对比 |
|---|---|---|
| 得到 0.632 | 「哦，就是这样」 | 「不对，我算的是 0.4685」 |
| 对 TF-IDF 的理解 | 一个黑盒函数 | 知道 TF、IDF、归一化各做了什么 |
| 换参数时 | 不知道改了什么 | 知道 `norm` 影响哪一步 |

**如果直接调库，这个差异根本不会被发现**——因为没有参照物。

这也是根 `README.md` 里把它列为「学得对的地方」的原因：

> **先手算，再调库。** `day_7` 手算 TF-IDF，`day_8` 换 sklearn 发现数字对不上，自己查出原因是 L2 归一化。

`day_8.py` 的最后两行留着当时的痕迹：

```python
# 自己算
print(1/3 * (math.log(3/2)+1))

# 扩展，对不上为什么？ 原因是：TfidfVectorizer 默认不仅计算 TF-IDF，
# 还会对每篇文档的向量进行归一化（Normalization）。
```

**把疑问和结论都写在代码注释里**，这个习惯让三个月后还能看懂当时在纠结什么。

## 复习自测

1. token ID 能表示词的含义吗？能表示出现次数吗？
2. 词袋向量的长度由什么决定？
3. 「我喜欢猫」和「猫喜欢我」的词袋向量有区别吗？这说明什么局限？
4. 余弦相似度的公式是什么？三个关键值 1、0、-1 分别代表什么？
5. 为什么文本相似度用余弦而不用欧氏距离？
6. TF 和词袋的原始计数有什么区别？
7. IDF 为什么要取对数？不取会怎样？
8. 平滑 IDF 公式里的两个 +1 分别解决什么问题？
9. `math.log(100)` 是多少？它是 $\ln$ 还是 $\log_{10}$？
10. 手算 TF-IDF 得 0.4685，sklearn 给 0.632，差异从哪来？怎么验证？
11. L2 归一化改变了权重之间的比例吗？
12. 开了 `norm=None` 之后，手算和 sklearn 就一致了吗？为什么？

<details>
<summary>参考答案</summary>

1. 都不能。ID 只是任意编号，换个词表顺序 ID 全变而含义不变；它也无法表示次数（`[2,2,2]` 和 `[0,1,2]` 长度相同但没法直接比较）。
2. 由**词表大小**决定，和文本长短无关。
3. **没有区别**，两者都是 `[1,1,1,0]`。说明词袋**丢失了词序**——这是它的根本局限，最典型的后果是分不清否定（「不好」vs「好」）。
4. $\frac{A\cdot B}{\|A\|\|B\|}$。1 = 方向完全相同，0 = 方向垂直（无关），-1 = 方向完全相反。
5. 因为文本长度不该影响相似度。同一主题重复一遍得到 `[2,2,2]`，欧氏距离变了但余弦相似度仍是 1——余弦关注「说的是什么」而不是「说了多少」。
6. 词袋用原始计数，TF 用占比（`count / 文档长度`），这样长文档和短文档可以比较。
7. 为了**压缩量级**。不取对数时，出现在 1 篇和 100 篇文档的词权重差 100 倍，会让极罕见词（甚至拼写错误）的权重爆炸。取对数后差距压到 2 倍，保留次序但不失控。
8. 分子分母的 +1 是**平滑**，防止 $df=0$ 时除以零；最后的 +1 保证 IDF 不为 0，否则在所有文档都出现的词权重归零、特征直接消失。
9. `math.log(100)` ≈ 4.605，是**自然对数** $\ln$。要算 $\log_{10}$ 得用 `math.log10()`。这和计算器上的 `log` 键习惯相反。
10. 直接原因是 **sklearn 默认做 L2 归一化**。验证方法：算出手算向量这一行的长度（0.7417），用它去除每一项，得到 0.632，和 sklearn 完全一致。
11. **没有改变比例**，只改变了数值。归一化前后 0.4685/0.3333 = 0.632/0.449 = 1.406，所以不影响「哪个词更重要」的判断。
12. **不一致，会差一个文档长度的倍数**（这个例子里是 3 倍）。因为 sklearn 的 TF 用**原始词频**，手算用的是 `count/文档长度`。默认情况下能对上，是因为 L2 归一化消掉了整行的公共缩放因子——**归一化掩盖了第二个差异**。

</details>
