## 2. 读懂 TF-IDF 矩阵

第 23 课已经能生成矩阵了，但只会生成不算会用。**算法工程师的基本功是能解释模型的输入。**

```python
from sklearn.feature_extraction.text import TfidfVectorizer

documents = ["cat likes fish", "dog likes meat"]

vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(documents)
words = vectorizer.get_feature_names_out()

print(words)
print(X.toarray().round(3))
```

```text
['cat' 'dog' 'fish' 'likes' 'meat']
[[0.632 0.    0.632 0.449 0.   ]
 [0.    0.632 0.    0.449 0.632]]
```

**三样东西必须对得上：**

| 对象 | 含义 |
|---|---|
| `words` | 词汇表，**顺序就是列的顺序** |
| `X.toarray()` | 稠密矩阵，形状 `(文档数, 词表大小)` |
| `X.toarray()[0]` | 第 1 篇文档的那一行权重 |

**`words[i]` 和 `row[i]` 是同一个词的「名字」和「权重」。** 这个对应关系是后面所有解读的基础。

> `fit_transform` 返回的是**稀疏矩阵**（大部分元素是 0，只存非零位置）。
> 真实文本任务里词表动辄几万列、每篇文档只有几十个词，稀疏存储能省掉 99% 以上的内存。
> `toarray()` 把它展开成普通 NumPy 数组，**只适合小数据查看**，几万列的矩阵别随便展开。

## 3. `argmax()`、`max()`、索引：三个容易混的东西

```python
row = [0.2, 0.8, 0.5]
```

| 写法 | 作用 | 结果 |
|---|---|---|
| `np.argmax(row)` | 最大值的**位置** | `1` |
| `np.max(row)` / `row.max()` | 最大值**本身** | `0.8` |
| `row[1]` | 取索引 1 的元素 | `0.8` |

`arg` 是 argument（自变量）的缩写，`argmax` 的数学含义是「让函数取到最大值的那个自变量」。所以它返回的是**下标**，不是值。

查词的套路固定是两步：

```python
index = np.argmax(row)      # 先拿位置
print(words[index])         # 再用位置去查名字
```

### `argmax()` 的局限：并列最高只返回第一个

`course_24_1.py` 的数据恰好撞上了这个情况：

```text
词汇表: ['cat' 'dog' 'fish' 'likes' 'meat']
第一行: [0.632 0.    0.632 0.449 0.   ]
         ↑cat           ↑fish
```

`cat` 和 `fish` 的权重**完全一样**（两个词都只出现在 1 篇文档里，TF 和 IDF 都相同）。但：

```python
np.argmax(row)      # 0  →  只给 cat
```

**`argmax()` 默认返回第一个最大值的索引，`fish` 被漏掉了。**

要找出所有并列最高的词，得先取最大值、再遍历比较：

```python
max_weight = row.max()

for i, weight in enumerate(row):
    if np.isclose(weight, max_weight):
        print(words[i], weight)
```

```text
cat 0.6316672
fish 0.6316672
```

## 4. `enumerate()`：同时拿索引和值

```python
for i, weight in enumerate(row):
```

`enumerate()` 在遍历时把元素包成 `(索引, 元素)` 的二元组：

```python
row = [0.2, 0.8, 0.5]
list(enumerate(row))        # [(0, 0.2), (1, 0.8), (2, 0.5)]
```

`for i, weight in ...` 这个写法叫**解包（unpacking）**——Python 自动把元组里的两个值分别赋给 `i` 和 `weight`。

**为什么这里非要用 `enumerate`？** 因为只有权重不够用，还得知道它是**第几个**，才能去 `words` 里查名字：

```python
# 只拿到值，查不出词
for weight in row:
    ...                         # weight 是 0.632，但这是哪个词？

# 拿到索引，才能对上
for i, weight in enumerate(row):
    print(words[i], weight)     # cat 0.632
```

> 对比 A 线的 `range(len(x))` 写法：`for i in range(len(row)): weight = row[i]` 也能实现，
> 但 `enumerate` 更直接、不会越界，是 Python 里的惯用写法。

## 5. 浮点数为什么不能用 `==` 比较

这是第 24 课埋下的一个关键习惯。

### 问题的根源

计算机用二进制存小数，而 **0.1、0.2 这类十进制小数在二进制里是无限循环的**，只能截断保存。于是：

```python
>>> 0.1 + 0.2
0.30000000000000004

>>> 0.1 + 0.2 == 0.3
False
```

不是 Python 的 bug，而是 IEEE 754 双精度浮点的固有行为，所有用它的语言都一样。

### 解决办法：`np.isclose()`

```python
>>> np.isclose(0.1 + 0.2, 0.3)
True
```

`np.isclose(a, b)` 判断的不是「完全相等」，而是「**差距小到可以当作相等**」：

$$
|a - b| \le \text{atol} + \text{rtol} \times |b|
$$

默认 `rtol=1e-05`、`atol=1e-08`，也就是允许大约千万分之一的相对误差。

### 为什么 TF-IDF 场景尤其需要它

TF-IDF 的每个权重都经过了**除法、对数、开平方**（L2 归一化）：

```text
count/len → × ln(...) → ÷ sqrt(Σx²)
```

每一步都在引入舍入误差。两个「数学上应该相等」的权重，算出来可能差在第 17 位小数上。用 `==` 比就会漏掉。

> **为什么要在这节反复强调？** 因为这类 bug 不报错。程序照常运行，只是悄悄少输出了一个词。
> A 线 Day14 的 `100 < item | item < 1` 也是同一类：**语法合法、逻辑错误、没有任何提示。**

## 6. 特征、标签、模型

第 26 课建立的三个概念，是后面所有课的词汇基础。

| 概念 | 是什么 | 在我们任务里 |
|---|---|---|
| **特征 Feature** | 喂给模型的信息 | 评论的 TF-IDF 向量 |
| **标签 Label** | 希望模型预测的正确答案 | 1（好评）/ 0（差评） |
| **模型 Model** | 学规律、做预测的程序 | 逻辑回归（第 28 课） |

```text
原始文本  "这个手机非常好用"
    ↓ 特征提取（TF-IDF）
特征      [0.5, 0.2, 0.8, ...]
    ↓ 模型
预测      1（好评）
```

**标签用 1 和 0 只是人为约定**，反过来定义也行，但一旦定了就不能中途改——否则准确率的解释会全部反掉。

## 7. 监督学习与无监督学习

`course_27.py` 开头那三行注释，是这一课的全部要点：

```python
"""
监督学习 - 有正确答案
无监督学习 - 没有正确答案
"""
```

| 类型 | 有标签吗 | 典型任务 |
|---|---|---|
| **监督学习** | 有 | 判断评论好评/差评（分类）、预测房价（回归） |
| **无监督学习** | 没有 | 把相似评论自动分群（聚类）、降维 |

监督学习的目标写成数学形式就是学一个映射：

$$
X \longrightarrow y
$$

**模型要学的不是「记住每条评论」，而是从训练数据里找出能用在新评论上的规律。** 这个区别就是下一节「过拟合」的全部内容。

NLP 里常见的监督任务：文本分类（情感、新闻类别）、文本匹配、命名实体识别；无监督的代表是文本聚类。

## 8. 为什么要分训练集和测试集

这是机器学习里最重要的工程纪律之一。

```text
         1000 条评论
        ┌──────┴──────┐
    训练集 800        测试集 200
    让模型学规律      检验没见过的数据
```

**考试的类比最贴切：**

| | 类比 | 作用 |
|---|---|---|
| 训练集 | 平时的练习题 | 模型从这里学 |
| 测试集 | 正式考试题 | 检验模型会不会做新题 |

如果只在训练集上评估，模型完全可以靠**死记硬背**拿满分——把每条评论和答案背下来，一个规律都没学到。遇到新评论就全错。

**模型在没见过的数据上的表现，叫泛化能力（generalization）。测试集就是测它的唯一手段。**

> 测试集的纪律是：**它只能用来评估，不能参与任何训练决策。** 一旦你根据测试集结果反复调参，
> 测试集就「被看过了」，它报出的分数也不再可信。这个问题要到第 33 课（交叉验证）才正式解决。

## 9. `train_test_split()` 的四个参数

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X,
    labels,
    test_size=0.25,
    random_state=42,
    stratify=labels
)
```

**返回值顺序是固定的四个，别记错：** `X_train, X_test, y_train, y_test`。

| 参数 | 作用 |
|---|---|
| `X` | 特征矩阵 |
| `labels` | 标签 |
| `test_size=0.25` | 25% 作测试集（8 条 → 测试 2 条、训练 6 条） |
| `random_state=42` | **固定随机划分，保证可复现** |
| `stratify=labels` | **按类别分层抽样，保持好评/差评比例** |

四个变量的分工：

| 变量 | 含义 | 用在哪 |
|---|---|---|
| `X_train` | 训练特征 | `model.fit(X_train, y_train)` |
| `y_train` | 训练标签 | 同上，告诉模型正确答案 |
| `X_test` | 测试特征 | `model.predict(X_test)` |
| `y_test` | 测试标签 | 对答案，算准确率 |

### `random_state` 为什么重要

划分是随机的。不固定的话，每次运行拿到的训练集都不一样：

```text
第一次运行：测试集 = [第2、7条]
第二次运行：测试集 = [第5、8条]      ← 准确率跟着变
```

**实验就没法比较了**——你改了个参数，准确率从 0.83 变成 0.67，到底是参数的功劳还是划分的运气？

`random_state=42` 固定了随机数种子，相同输入永远得到相同划分。**42 没有任何特殊含义**，写 0、7、2024 都一样，它只是教程里的习惯值（出自《银河系漫游指南》的梗）。

### `stratify` 为什么重要

8 条数据里好评 4 条、差评 4 条。不分层的话，随机抽 2 条当测试集，有可能**两条都是好评**：

```text
测试集 = [好评, 好评]
→ 模型全预测「好评」就能拿 100%
→ 这个准确率毫无意义
```

`stratify=labels` 按标签比例抽样，让测试集也保持 1:1。**样本越少、类别越不平衡，这个参数越关键。**

## 10. `X` 大写、`y` 小写

这是提问过的一个细节，答案是：**数学记号的历史约定，Python 本身不要求。**

| 符号 | 代表 | 维度 | 为什么 |
|---|---|---|---|
| `X` | 特征**矩阵** | 二维 `(样本数, 特征数)` | 数学里矩阵习惯用大写 |
| `y` | 标签**向量** | 一维 `(样本数,)` | 向量习惯用小写 |

```python
X = [[0.2, 0.5, 0.8],      # 第 1 条评论的 3 个特征
     [0.1, 0.7, 0.3],      # 第 2 条
     [0.9, 0.2, 0.4]]      # 第 3 条

y = [1, 0, 1]              # 3 条评论各自的标签
```

**行是样本、列是特征**——这个约定从第 01 节的 `X @ w` 一路贯穿到 sklearn 的全部 API。

> 整个 sklearn 生态都遵守这套命名，`fit(X, y)`、`predict(X)` 的参数名就是 `X` 和 `y`。
> 跟着写不是为了好看，是为了别人（和三个月后的自己）一眼看懂哪个是输入哪个是答案。

## 11. 中文分词：默认分词器为什么对中文失效

这是第 27 课撞上的真问题，也是中文 NLP 的第一道门槛。

### 现象

8 条中文评论喂给默认的 `TfidfVectorizer()`，得到 `(8, 8)`：

```text
词汇表: ['手机质量太差' '手机质量很好' '拍照效果不好' '拍照效果好'
        '电池续航很差' '电池续航特别好' '这个手机太差了' '这个手机非常好用']
```

**每一整句话被当成了一个词。** 8 条评论 → 8 个特征，一一对应。

### 原因

`TfidfVectorizer` 的默认分词规则是正则 `token_pattern=r"(?u)\b\w\w+\b"`——**按词边界切，至少两个字符**。这套规则面向英文，依赖空格：

```text
"cat likes fish"  →  按空格切  →  ['cat', 'likes', 'fish']   ✅
"这个手机非常好用"  →  没有空格  →  ['这个手机非常好用']        ❌
```

中文词之间没有分隔符，正则找不到切点，整串连续汉字被视为一个 token。

### 后果：模型学不到任何东西

词表里每个特征只出现在 1 条评论里，于是：

- 模型看到的不是「好用 → 好评」，而是「这个手机非常好用 → 好评」
- **「好用」「太差」「很好」这些真正有判别力的词从来没有被单独表示过**
- 换一条新评论「这个相机非常好用」，词表里查不到，特征**全是 0**

**特征的质量决定模型的上限。** 这一步错了，后面换什么算法都救不回来。

### 解决：接入 jieba

```bash
pip install jieba
```

```python
import jieba
from sklearn.feature_extraction.text import TfidfVectorizer

def chinese_tokenizer(text):
    return jieba.lcut(text)

vectorizer = TfidfVectorizer(
    tokenizer=chinese_tokenizer,
    token_pattern=None
)
```

两个参数要一起写：

| 参数 | 作用 |
|---|---|
| `tokenizer=chinese_tokenizer` | 用自己的函数替换默认分词 |
| `token_pattern=None` | **关掉默认正则**，否则 sklearn 会警告该参数被忽略 |

`jieba.lcut(text)` 返回切好的**列表**（`l` = list）；`jieba.cut()` 返回生成器，用在这里也行但要自己转。

效果：

```text
jieba 切第一句: ['这个', '手机', '非常', '好用']
形状: (8, 18)
```

**从 8 个特征变成 18 个**，「手机」「好用」「太差」终于成了独立特征，可以跨评论共享了。

> jieba 的切分结果受词典和版本影响，不是唯一标准答案。
> 中文分词的其他常见选择：`pkuseg`（领域适应好）、`HanLP`；
> 到 Transformer 阶段会换成 BERT Tokenizer 那类**子词（subword）**切分，连「未登录词」问题一起解决。

## 12. 数据泄漏：先 `fit` 全量再划分，错在哪

`course_27.py` 的写法是**先对全部 8 条文本 `fit_transform`，再划分**：

```python
X = vectorizer.fit_transform(texts)       # ← 全量
X_train, X_test, ... = train_test_split(X, labels, ...)
```

当时的课件里就带了提醒：

> 上面为了让你先理解完整流程，先对全部文本执行了 TF-IDF，再划分数据。
> **正式机器学习实验中，应该先划分训练集和测试集，再只在训练集上 `fit` TF-IDF，
> 并对测试集使用 `transform`**，避免测试集信息泄漏。

### 泄漏了什么

`fit` 这个动作会**从数据里学两样东西**：

1. **词汇表**（有哪些词、各占第几列）
2. **IDF 值**（每个词在多少篇文档里出现过）

对全量 `fit`，意味着这两样东西里混进了**测试集的信息**。模型在训练阶段就间接「见过」了测试集的词汇分布。

### 正确写法

```python
# 1. 先划分原始文本
train_texts, test_texts, y_train, y_test = train_test_split(
    texts, labels, test_size=0.25, random_state=42, stratify=labels
)

# 2. 只在训练集上 fit
vectorizer = TfidfVectorizer(tokenizer=chinese_tokenizer, token_pattern=None)
X_train = vectorizer.fit_transform(train_texts)

# 3. 测试集只 transform，不 fit
X_test = vectorizer.transform(test_texts)
```

**`fit` 只能见训练集，`transform` 才能用在测试集上。** 这是 sklearn 所有预处理器（归一化、编码、向量化）的通用纪律。

### 为什么这个错误很危险

因为它**让模型看起来更准**。泄漏的信息帮了测试集一把，报出的分数比真实泛化能力高。上线之后面对真正没见过的数据，效果会掉下来——而你事前完全不知道。

**一个「偏高但假」的指标，比一个「偏低但真」的指标危险得多。**

## 第 24 课：`course_24_1.py` —— 并列最高与 `np.isclose`

```python
# 第24课 找出TF-IDF权重最高的词
documents = ["cat likes fish", "dog likes meat"]

row = X.toarray()[0]
index = np.argmax(row)
print(index, words[index], row[index])      # 0 cat 0.6316672

for i, weight in enumerate(row):
    if np.isclose(weight, max_weight):
        print(words[i], weight)             # cat / fish 都输出
```

实测：

```text
词汇表: ['cat' 'dog' 'fish' 'likes' 'meat']
第一行: [0.6316672  0.  0.6316672  0.44943642  0. ]
argmax: 0 -> cat
用 isclose 命中: ['cat', 'fish']
```

**`argmax` 漏掉了 `fish`，`enumerate` + `isclose` 两个都找到了。** 代码写对了。

代码末尾还留了一段试验——不要索引、只打印值：

```python
for i in row:
    if np.isclose(i, max_weight):
        print(i)
```

这段能跑，但**只能输出 `0.6316672` 两次，说不出是哪两个词**。它反过来证明了 `enumerate` 的必要性：没有索引就查不到名字。

## 第 24 课实战：`course_24_2.py` —— 退回用 `==`，为什么没出问题

实战巩固把数据加到三篇，代码里把 `np.isclose` 换回了 `==`：

```python
documents = ["cat likes fish", "dog likes meat", "cat likes meat"]

row = X.toarray()[0]
max_weight = np.max(row)

for i, weight in enumerate(row):
    if weight == max_weight:        # ← 退回 ==
        print(words[i], weight)
```

实测结果：

```text
词汇表: ['cat' 'dog' 'fish' 'likes' 'meat']
矩阵:
 [[0.548 0.    0.72  0.425 0.   ]
 [0.    0.72  0.    0.425 0.548]
 [0.62  0.    0.    0.481 0.62 ]]
第一行最高权重词(==): ['fish']
```

**输出正确，但这是数据碰巧帮了忙。** 两个原因：

**原因一：这组数据的最高权重是唯一的。** 加了第三篇文档之后，`cat` 出现在 2 篇里、`fish` 只在 1 篇里，IDF 不同了，`fish`（0.72）单独最高，根本没有并列，`==` 自然不会漏。

**原因二：即使在 `course_24_1` 的并列情况下，`==` 也能用。** 实测两个权重的差值是：

```text
cat 与 fish 权重差: 0.0
```

**精确的 0.0，不是 1e-17。** 因为 `cat` 和 `fish` 的 TF 相同、IDF 相同、归一化除的是同一个数——**两个权重走的是完全相同的浮点运算路径**，位级结果必然一致。

所以结论是：

| | 能用 `==` 吗 | 为什么 |
|---|---|---|
| 并列项由**相同运算路径**算出 | 能 | 位级完全相同 |
| 并列项由**不同运算路径**算出 | **不能** | 舍入误差积累在末位 |

**而你事前并不知道自己属于哪种情况。** `np.isclose` 在两种情况下都对，`==` 只在第一种情况下对——没有理由选 `==`。

> 这是个典型的「测试通过 ≠ 代码正确」。和第 05 节那个「L2 归一化掩盖了 TF 定义差异」是同一类问题：
> **结果对了，不代表每一步都站得住。**

## 第 25 课：`course_25.py` —— 逐篇提取关键词

把单篇的逻辑包进外层循环，处理全部文档：

```python
documents = [
    "phone camera good quality",
    "phone battery good",
    "camera quality excellent",
]

for i in range(len(documents)):
    row = X.toarray()[i]
    max_weight = np.max(row)
    for index, weight in enumerate(row):
        if np.isclose(weight, max_weight):
            print(f"第{i+1}条评论中权重最高的词", words[index], weight)
```

实测：

```text
词汇表: ['battery' 'camera' 'excellent' 'good' 'phone' 'quality']
矩阵:
 [[0.    0.5   0.    0.5   0.5   0.5  ]
 [0.681 0.    0.    0.518 0.518 0.   ]
 [0.    0.518 0.681 0.    0.    0.518]]

第1条: [('camera', 0.5), ('good', 0.5), ('phone', 0.5), ('quality', 0.5)]
第2条: [('battery', 0.681)]
第3条: [('excellent', 0.681)]
```

**三条结果正好演示了 IDF 在干什么：**

| 词 | 出现在几篇 | IDF | 结果 |
|---|---:|---|---|
| `battery` | 1 | 高 | 第 2 条的关键词 |
| `excellent` | 1 | 高 | 第 3 条的关键词 |
| `phone` `camera` `good` `quality` | 各 2 | 低且**彼此相同** | 第 1 条**四个词全部并列** |

第 1 条「phone camera good quality」的四个词 TF 都是 1、IDF 都一样，归一化后各占 0.5（$\sqrt{4 \times 0.5^2} = 1$）。

**也就是说，TF-IDF 对第 1 条评论没能给出任何关键词偏好。** 这不是代码的问题，是数据的问题——三篇文档的语料太小，IDF 区分不出谁更重要。

这一条也顺便解释了为什么第 1 条能出现**四个**并列最高：这种情况下 `argmax` 会漏掉三个词，而不是一个。

> 代码里那段注释值得保留，它把四个方法的区别一次写清了：
>
> ```python
> row.max()       # 最大值：0.9
> np.max(row)     # 最大值
> row.argmax()    # 最大值的索引：2
> np.argmax(row)  # 最大值的索引：2
> ```
>
> 数组方法（`row.max()`）和 NumPy 函数（`np.max(row)`）效果相同，区别只在写法。

**测试集第一条是全零向量。** 它的三个词 `拍照`、`效果`、`不好` 在训练集里一次都没出现过，模型对这条评论**没有任何可用信息**。

### 那个 100% 准确率是怎么来的

接着训练逻辑回归（第 28 课的内容，这里提前跑一下）：

```text
预测: [0, 1]   真实: [0, 1]
准确率: 1.0
截距: [-0.03435626]
全零向量的预测概率: [0.5086, 0.4914]
```

**准确率 100%，但第一条是靠截距猜对的。**

全零向量意味着所有特征的贡献都是 0，模型的输出只剩下截距项 $b = -0.034$。经过 sigmoid 得到 $P(\text{差评}) = 0.5086$，比 $P(\text{好评}) = 0.4914$ 高了 **0.017**——几乎就是抛硬币，恰好偏向了正确的一边。

第二条「拍照效果好」只有 `好` 一个非零特征，靠这一个词预测对了，还算合理。

### 三条结论

1. **泄漏不只是「理论上不规范」。** 这组数据里，泄漏的 3 个词直接决定了测试集样本有没有特征可用。
2. **规范写法反而暴露了真问题**——训练集和测试集的词汇几乎不重叠，8 条数据根本撑不起这个实验。泄漏写法把这个问题藏起来了。
3. **100% 准确率在 2 条测试样本上毫无意义。** 准确率的最小刻度是 1/2 = 50%，一条样本的对错就能让分数从 50% 跳到 100%。

<summary>参考答案</summary>

1. `argmax()` 先给出最大值在哪一列（索引），再用这个索引去 `get_feature_names_out()` 返回的词汇表里查名字；`toarray()[i]` 负责取出第 i 篇文档那一行。三者的共同前提是**词汇表顺序和矩阵列顺序一致**。
2. `argmax` 返回最大值的**位置（索引）**，`max` 返回最大值**本身**。`arg` 来自「自变量」，所以给的是下标。
3. `argmax()` 只返回**第一个**最大值的索引，其余并列项被漏掉。要全部找出来得先 `row.max()` 拿到最大值，再用 `enumerate` 遍历、逐个用 `np.isclose` 比较。
4. `i` 是索引、`weight` 是该位置的值，这叫元组解包。只遍历值的话拿不到索引，就没法去 `words` 里查出是哪个词。
5. `False`。`0.1 + 0.2` 实际是 `0.30000000000000004`——0.1、0.2 在二进制里是无限循环小数，存储时被截断，误差在运算中积累。这是 IEEE 754 浮点的固有行为，不是 Python 的问题。
6. 判断 $|a-b| \le \text{atol} + \text{rtol}\times|b|$，默认 `rtol=1e-05`、`atol=1e-08`，即允许约千万分之一的相对误差。
7. **运气好。** 两个原因：三篇文档时最高权重唯一（`fish` 0.72），没有并列；而即使在两篇文档的并列情况下，`cat` 和 `fish` 的 TF、IDF、归一化除数完全相同，走同一条浮点运算路径，差值精确为 `0.0`。换一组权重来自不同运算路径的数据，`==` 就会漏词——而且不报错。
8. 特征 = 喂给模型的信息（TF-IDF 产出的就是特征）；标签 = 希望预测的正确答案（1 好评 / 0 差评）；模型 = 学规律并做预测的程序。
9. 有没有标签（正确答案）。监督学习有，学的是映射 $X \to y$；无监督学习没有，典型任务是聚类。
10. 模型可以靠死记硬背拿高分——把训练数据和答案背下来，一条规律都没学到，遇到新数据就全错。测试集是检验泛化能力的唯一手段。
11. `X_train, X_test, y_train, y_test`——先 X 的两个，再 y 的两个。
12. 每次运行得到不同的划分，准确率跟着变，实验结果无法比较，也分不清指标变化是参数的功劳还是划分的运气。42 **没有任何特殊含义**，只是教程里的习惯值。
13. 防止随机划分让测试集的类别严重失衡（比如 2 条测试样本全是好评，模型全猜好评就能拿 100%）。**样本越少、类别越不平衡，越关键。**
14. 数学记号的历史约定：`X` 是二维特征矩阵（矩阵用大写），`y` 是一维标签向量（向量用小写）。Python 本身不要求，但整个 sklearn 生态都这么写。
15. 默认 `token_pattern=r"(?u)\b\w\w+\b"` 是按词边界切、面向英文、依赖空格。中文词之间没有分隔符，正则找不到切点，于是**每一整句话被当成一个 token**，8 条评论 → 8 个特征。
16. `tokenizer=chinese_tokenizer` 和 `token_pattern=None`。后者必须写是因为自定义 `tokenizer` 后默认正则不再生效，不显式关掉 sklearn 会发出「该参数被忽略」的警告。
17. 学了**词汇表**（有哪些词、各占第几列）和 **IDF 值**（每个词在多少篇文档里出现）。在测试集上 `fit` 等于把测试集信息混进了模型的输入表示，报出的分数会偏高、不反映真实泛化能力。
18. 多了 `['不好', '拍照', '效果']`，正好是测试集两条评论独有的词。其中 **`不好` 是区分好评差评的关键词**——泄漏它相当于提前把答案的线索给了模型。
19. **全零向量。** 它的三个词 `拍照`、`效果`、`不好` 在训练集 15 个特征里一个都没有。模型只剩截距项 $b=-0.034$ 可用，sigmoid 后 $P(0)=0.5086$ 对 $P(1)=0.4914$，差 0.017，几乎是抛硬币，**恰好猜对**。
20. **什么都说明不了。** 准确率的最小刻度是 1/2 = 50%，一条样本的对错就能让分数从 50% 跳到 100%；而且其中一条还是靠截距猜的。要下结论至少需要每类几百条样本，并保证训练集和测试集的词汇有实质重叠。
