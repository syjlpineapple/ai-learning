# 第 29 课：不要只看准确率

上一课你训出了第一个模型，准确率 16.7%。今天要解决两个问题：

1. **模型到底错在哪？** 只有一个准确率，看不出来。
2. **它为什么错？** 这比把数字调好看重要得多。

这一步是从「会训练模型」走向「会评估模型」。

## 一、先看一个业务场景

假设有 100 条手机评论，50 条好评、50 条差评。模型预测完，结果是这样：

| 实际情况 | 模型预测好评 | 模型预测差评 |
|---|---:|---:|
| 实际好评 | 40 | 10 |
| 实际差评 | 5 | 45 |

这张表叫**混淆矩阵**。四个格子各有名字（这里把「好评」定为**正类**）：

- **TP（真正例）**：实际好评，模型也预测好评，40 条
- **FN（假负例）**：实际好评，模型预测成差评，10 条（漏掉了）
- **FP（假正例）**：实际差评，模型错判成好评，5 条（冤枉了）
- **TN（真负例）**：实际差评，模型也预测差评，45 条

记法：第一个字母看预测**对不对**（True / False），第二个字母看预测**成了什么**（Positive / Negative）。

## 二、四个指标分别衡量什么？

**准确率 Accuracy：整体预测对了多少**

$$
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}=\frac{40+45}{100}=0.85
$$

**精确率 Precision：模型说是好评的里面，有多少真是好评**

$$
Precision=\frac{TP}{TP+FP}=\frac{40}{40+5}\approx 88.89\%
$$

**召回率 Recall：所有真正的好评里，模型找出来多少**

$$
Recall=\frac{TP}{TP+FN}=\frac{40}{40+10}=80\%
$$

**F1：把精确率和召回率合成一个数**

$$
F1=2\times\frac{Precision\times Recall}{Precision+Recall}\approx 84.21\%
$$

F1 用的是调和平均，它会被小的那一项拖住。比如 Precision 是 1、Recall 只有 0.01，算术平均是 0.505，看着还行；F1 只有 0.0198，如实反映了很差。**F1 要高，两项都得高。**

| 指标 | 主要关注 |
|---|---|
| Accuracy | 整体预测对了多少 |
| Precision | 预测为正的结果，有多少是真的 |
| Recall | 真正的正样本，找出来多少 |
| F1 | 综合衡量 Precision 和 Recall |

为什么不能只看准确率？假设 100 条里只有 5 条差评，一个什么都不学、全部预测「好评」的模型，准确率也有 95%，可它一条差评都找不出来。

## 三、用 Python 评估你的模型

在上一课的代码里加上：

```python
from sklearn.metrics import (
    confusion_matrix,
    precision_score,
    recall_score,
    f1_score,
    classification_report
)

print("混淆矩阵:")
print(confusion_matrix(y_test, y_pred))
print("准确率:", accuracy_score(y_test, y_pred))
print("精确率", precision_score(y_test, y_pred))
print("召回率", recall_score(y_test, y_pred))
print("F1分数:", f1_score(y_test, y_pred))
print("分类报告：")
print(classification_report(y_test, y_pred, target_names=["差评", "好评"]))
```

### 读懂这个混淆矩阵

sklearn 的混淆矩阵，**行是真实标签，列是预测标签**，按标签值从小到大排，0 在前：

| 真实情况 | 预测差评(0) | 预测好评(1) |
|---|---:|---:|
| 差评(0) | 0 | 3 |
| 好评(1) | 2 | 1 |

- 3 条真实差评，全部被错判成好评
- 3 条真实好评，只对了 1 条
- 6 条一共对了 1 条，$1/6\approx16.7\%$

数学上没有算错，模型确实很差。

分类报告把每个类别都当一次正类，各算一遍。`support` 是这个类别**真实**有几条。`target_names` 的顺序必须和标签 0、1 对应，写反了不会报错，只会张冠李戴。

### `pos_label`：指标是算给谁的

你的标签是 `1` = 好评、`0` = 差评。`precision_score()` 这几个函数**默认把 1 当正类**，算的是好评的指标。

如果业务目标是**找出差评**，就要指定：

```python
precision_score(y_test, y_pred, pos_label=0)
recall_score(y_test, y_pred, pos_label=0)
f1_score(y_test, y_pred, pos_label=0)
```

**指标要围绕你真正想识别的那一类来算。**

## 四、错误分析：先找错在哪，再决定怎么改

模型效果差，第一反应不该是改参数，而是沿着数据流一层层查：

1. **分词**：切得对不对？否定词保住了吗？
2. **特征**：这些词在训练词汇表里吗？
3. **权重**：模型给这些词学了什么权重？
4. **概率**：离 0.5 有多远？是笃定还是在猜？

先看每条错在哪：

```python
for text, true_label, pred_label in zip(texts_test, y_test, y_pred):
    print("评论：", text, "真实：", true_label, "预测：", pred_label)
```

```text
评论： 手机运行速度很慢 真实： 0 预测： 1
评论： 这个产品真的不错 真实： 1 预测： 0
评论： 屏幕显示效果很好 真实： 1 预测： 1
评论： 电池续航特别棒 真实： 1 预测： 0
评论： 拍照效果非常模糊 真实： 0 预测： 1
评论： 屏幕显示效果很差 真实： 0 预测： 1
```

再看测试集里哪些词**不在训练词汇表**里，这种词叫**未登录词**：

```python
vocab = set(vectorizer.get_feature_names_out())

for text in texts_test:
    words = chinese_tokenizer(text)
    unknown_words = [word for word in words if word not in vocab]
    print(text, words, "未登录词：", unknown_words)
```

```text
手机运行速度很慢 ['手机', '运行', '速度', '很', '慢'] 未登录词： ['慢']
这个产品真的不错 ['这个', '产品', '真的', '不错'] 未登录词： ['不错']
屏幕显示效果很好 ['屏幕显示', '效果', '很', '好'] 未登录词： ['屏幕显示']
电池续航特别棒 ['电池', '续航', '特别', '棒'] 未登录词： ['棒']
拍照效果非常模糊 ['拍照', '效果', '非常', '模糊'] 未登录词： ['模糊']
屏幕显示效果很差 ['屏幕显示', '效果', '很差'] 未登录词： ['屏幕显示', '很差']
```

找到了。**6 条测试评论里，真正表达好坏的那个词，几乎全都不在训练词汇表里。** 训练集有「很快」没有「慢」，有「不好」没有「不错」，有「特别差」没有「棒」，有「清晰」没有「模糊」；训练集切出来的是「差」「太差」，没有「很差」；「屏幕显示」这个词训练集里根本没出现过。

`transform()` 只用训练时建好的词表，**不会为新词创建新的列**。未登录词在特征里等于不存在。模型能看到的只剩「手机」「效果」「电池」这类中性词，它只能拿这些词瞎猜。

第四层也印证了这一点。这 6 条的好评概率是：

```text
[0.5319 0.4166 0.5308 0.4454 0.5926 0.5503]
```

全挤在 0.42 到 0.60 之间。一个真正有判断力的模型，应该给出接近 0 或接近 1 的概率。**全贴着 0.5，说明它每一条都没把握。**

还有一点：TF-IDF 只统计词的权重，并不懂「不」会把「值得购买」变成反义。否定表达也是这种方法的弱点，只是这 6 条里还没轮到它出问题。

## 五、分类阈值：从概率到标签

`predict()` 内部做的就是「好评概率 ≥ 0.5 判 1」。把这一步自己写出来，就能换阈值。

**第一步，拿到每条评论的好评概率：**

```python
# 找到好评对应的类别列
positive_index = list(model.classes_).index(1)

# 获取好评概率
probabilities = model.predict_proba(X_test)[:, positive_index]
```

拆开看：

- `model.classes_` 是 `[0 1]`，表示模型认识的两个类别。
- `list(model.classes_).index(1)` 查类别 1 在第几个位置，结果是 1。
- `predict_proba(X_test)` 返回一个表：每行一条评论，第 0 列是差评概率，第 1 列是好评概率。
- `[:, 1]` 是 NumPy 切片：`:` 表示所有行，`1` 表示只要第 1 列。

**第二步，按阈值把概率变成标签：**

```python
import numpy as np

threshold = 0.42

pred_threshold = np.where(probabilities >= threshold, 1, 0)
```

`np.where(条件, 成立时的值, 不成立时的值)` 对数组里每个元素逐个判断。比如：

```python
probabilities = np.array([0.20, 0.40, 0.45, 0.70, 0.90])
print(np.where(probabilities >= 0.42, 1, 0))
```

```text
[0 0 1 1 1]
```

**阈值往哪调，指标往哪动：**

| 阈值 | 判成好评 | 好评 Recall | 好评 Precision |
|---|---|---|---|
| 降低（0.5 → 0.3） | 更容易 | 上升 | 通常下降 |
| 提高（0.5 → 0.8） | 更难 | 下降 | 通常上升 |

这是此消彼长的权衡。而且要记住：**调阈值不会让模型变聪明**，权重和概率都没变，变的只是切分的那条线。阈值也不能在最终测试集上反复试，那等于拿考试题调参。

## 七、小测

**1.** Precision 衡量什么？

- A. 整体预测正确率
- B. 预测为正类的样本中，真正正类的比例
- C. 所有真实正类中被找到的比例

**2.** Recall 衡量什么？

- A. 所有真实正类中被正确找到的比例
- B. 预测为正类的样本中有多少正确
- C. 模型训练了多少次

**3.** 如果重点识别差评，而差评标签是 0，应该怎么做？

- A. 保持默认 `pos_label=1`
- B. 设置 `pos_label=0`
- C. 删除差评数据

**4.** 模型把「这个手机太差了」预测成好评，第一步应该做什么？

- A. 马上把 `max_iter` 改成 100000
- B. 查看这条评论的分词结果、TF-IDF 特征和模型预测
- C. 直接删除这条评论

**5.** 训练集里没有出现「棒」，测试集出现了「电池续航特别棒」。`vectorizer.transform()` 会怎样处理「棒」？

- A. 自动理解「棒」是好评词
- B. 自动把「棒」加入训练词汇表
- C. 忽略这个未登录词，不为它创建新特征

**6.** 公司的首要目标是尽可能找出所有差评，应该重点看哪个指标？

- A. 好评 Precision
- B. 差评 Recall
- C. Accuracy
- D. 好评 Recall

<details>
<summary>答案</summary>

1. B。分母是「所有被预测为正类的」。
2. A。分母是「所有真实的正类」。
3. B。
4. B。先查链路，再动手。
5. C。
6. B。「尽可能找全」就是 Recall，对象是差评，所以要 `pos_label=0`。

</details>
