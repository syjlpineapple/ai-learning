# 第 35 课：朴素贝叶斯

上一课我们把 11987 条外卖评论看清楚了。今天终于学新模型，就是你 11-16 问过的朴素贝叶斯。

它判断好评差评的方式，其实和你自己读评论时很像。我们就从这里说起。

## 一、先想一个场景

你在外卖平台上随手翻评论，有一条只露出一个字：**「慢」**。

你猜它是好评还是差评？

大多数人会猜差评。为什么？因为你见过太多抱怨「送得太慢」的差评了。

再换一个：这条评论露出来的是 **「难吃」**。这次你几乎可以肯定是差评。

你刚才做的事情，就是贝叶斯的核心思路：**先有一个原来的猜测，看到线索以后，更新这个猜测。**

## 二、先验和后验

把刚才的过程拆成两步：

**第一步，什么都没看到的时候。** 你只知道这个平台上大概三分之二是差评（上一课算过，66.6%）。这时候猜差评，有 0.666 的把握。这个「看到线索之前的把握」，叫**先验概率**，写作 $P(\text{差评})$。

是不是很眼熟？它就是上一课的**基线**。

**第二步，看到了「慢」字以后。** 我在数据里数了一下：

```text
含「慢」的评论：1269 条，其中差评 1118 条
```

$$
P(\text{差评} \mid \text{慢}) = \frac{1118}{1269} \approx 0.881
$$

把握从 0.666 涨到了 0.881。这个「看到线索之后的把握」，叫**后验概率**。

中间那条竖线 $\mid$ 读作「在……的条件下」，$P(\text{差评} \mid \text{慢})$ 就是「在含有『慢』的条件下，是差评的概率」。

同样的方法数一数其他几个词：

| 词 | 含这个词的评论里，差评占 |
|---|---:|
| 难吃 | 0.975 |
| 凉 | 0.908 |
| 慢 | 0.881 |
| 快 | 0.332 |
| 不错 | 0.310 |

「难吃」「凉」把你往差评推，「快」「不错」把你往好评推（低于 0.666 的基线）。

## 三、贝叶斯公式

既然能直接数，为什么还需要公式？

因为真实的评论不止一个词。「送餐太慢了，饭都凉了」，你想知道的是「同时含有这些词」的评论里差评占多少。可一万多条评论里，几乎找不到第二条一模一样的，没法直接数。

贝叶斯公式换了个方向，让我们去数**好数的东西**：

$$
P(\text{差评} \mid \text{慢}) = \frac{P(\text{慢} \mid \text{差评}) \times P(\text{差评})}{P(\text{慢})}
$$

一个字母一个字母看：

- $P(\text{差评})$：先验，所有评论里差评占多少，0.666
- $P(\text{慢} \mid \text{差评})$：**在差评里**，有多少条提到了「慢」，0.140
- $P(\text{慢})$：所有评论里，有多少条提到了「慢」，0.106

代进去：

$$
\frac{0.140 \times 0.666}{0.106} \approx 0.881
$$

和直接数的结果一模一样。公式没有变出新东西，它只是**把「难数的」换成了「好数的」**：「差评里有多少提到慢」，每个词都能单独数出来。

## 四、为什么叫「朴素」

一句话里有很多词，每个词都有自己的 $P(\text{词} \mid \text{差评})$。朴素贝叶斯做了一个很简单、甚至有点天真的假设：

**每个词出现与否，互相没有关系。**

有了这个假设，一句话的概率就可以拆成每个词的概率**相乘**。「慢」往差评推一点，「凉」再往差评推一点，乘起来，推得更狠。

这个假设显然不对。「慢」和「凉」明明是有关系的：送得慢，饭才会凉。所以它叫「朴素」，意思就是「想得太简单」。

但神奇的是，这么天真的假设，效果往往还不错。用整份数据训练好以后，我试了几句话：

| 评论 | 模型给的差评概率 |
|---|---:|
| 送餐太慢了，饭都凉了 | 0.998 |
| 很好吃，下次还点 | 0.003 |
| 一般般吧 | 0.891 |
| 味道还行就是有点慢 | 0.288 |

前三句都判断得很合理。最后一句有点模棱两可，模型觉得偏好评，你可能会觉得偏差评，这种话本来就不好判断。

## 五、一个零带来的大麻烦：平滑

乘法有个危险：**只要有一个数是 0，乘出来就是 0。**

在这份数据里，「米线」这个词出现了 79 次，**全部在差评里**。可能是某家米线店口碑太差了。于是：

$$
P(\text{米线} \mid \text{好评}) = 0
$$

现在来一条明明是好评的评论：「米线很好吃，送得也快，好评」。不管「好吃」「快」「好评」把好评的概率推得多高，乘上「米线」那个 0，好评的概率直接归零。

我把平滑关掉试了一下（`alpha` 设成几乎是 0）：

```text
米线很好吃，送得也快，好评  →  好评概率 0.000000
```

一个菜名，就让模型把一条好评判成了差评。

解决办法叫**平滑**：数次数的时候，给每个词在每一类里都**先加上 1 次**。这样就不会有 0 了，没见过的组合只是概率很小，而不是不可能。sklearn 里这个「加上的数」就是参数 `alpha`，默认是 1：

```text
alpha=1  →  好评概率 0.991
```

又判断对了。

记住：**朴素贝叶斯一定要平滑。** 好在 sklearn 默认就开着，你不用做什么，但要知道它在保护你。

## 六、用 sklearn 跑一遍

朴素贝叶斯数的是「每个词出现了几次」，所以搭配第 19 课讲的词袋（sklearn 里叫 `CountVectorizer`），而不是 TF-IDF。其他部分和第 33 课一模一样：

```python
import csv
from pathlib import Path

import jieba
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import Pipeline

with Path("nlp/data/waimai_10k.csv").open(encoding="utf-8", newline="") as f:
    rows = list(csv.DictReader(f))
texts = [r["review"] for r in rows]
labels = [int(r["label"]) for r in rows]


def chinese_tokenizer(text):
    return jieba.lcut(text)


pipeline = Pipeline([
    ("vec", CountVectorizer(tokenizer=chinese_tokenizer, token_pattern=None)),
    ("nb", MultinomialNB()),            # alpha 默认是 1，平滑已经开着
])

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(pipeline, texts, labels, cv=cv, scoring="accuracy")

print("每一折：", scores)
print("平均：", scores.mean(), "标准差：", scores.std())
```

```text
每一折： [0.87114262 0.8853211  0.88360451 0.86107635 0.87943262]
平均： 0.8761154389887554 标准差： 0.008974823931881983
```

0.876，比 0.666 的基线高出 21 个百分点，而且五折之间很稳。上一课逻辑回归在同一份数据上是 0.888 左右。哪个更好？差了 0.012，这个差距算不算数，正是下一课要回答的问题。

## 八、小测

**1.** 什么都没看，就猜一条评论是差评，把握是 0.666。这个 0.666 叫什么？

- A. 后验概率
- B. 先验概率
- C. 准确率

**2.** 朴素贝叶斯的「朴素」指的是什么？

- A. 模型很简单，所以效果不好
- B. 假设每个词出现与否互相没有关系
- C. 只能用于中文

**3.** 如果把平滑关掉，一个只在差评里出现过的词，会让模型怎样？

- A. 没影响
- B. 含这个词的评论，好评概率直接变成 0
- C. 模型训练时会报错

<details>
<summary>答案</summary>

1. B。看到任何线索之前的概率叫先验，它正好也是上一课说的基线。
2. B。这个假设并不对（「慢」和「凉」明显有关系），但效果往往不错。
3. B。概率要连乘，乘上一个 0，结果就是 0。所以要平滑，sklearn 默认 `alpha=1`。
