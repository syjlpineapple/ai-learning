# 第 34 课：换成真实数据集

按原来的计划，今天该学朴素贝叶斯了。但在学新模型之前，我们得先解决一个更根本的问题：

**为什么第 33 课换一个随机种子，平均准确率就能从 0.15 跳到 0.38？**

你还记得那 24 条手机评论吧。测试集只有 6 条，模型只要多猜对一条，准确率就涨 16.7 个百分点。这就像只抛 6 次硬币，出现了 4 次正面，你没法据此说这枚硬币不公平，6 次实在太少了。

这说明：**数据太少的时候，分数主要由运气决定。** 在这样的数据上比较两个模型，比的其实是谁运气好。

所以今天我们换一份真实的数据：**11987 条外卖评论**。今天不训练模型，只做一件事：把这份数据看清楚。朴素贝叶斯放到下一课，到时候它和逻辑回归的比较才有意义。

## 一、认识这份数据

这份数据叫 waimai_10k，来自一个开源的中文语料合集 [ChineseNlpCorpus](https://github.com/SophonPlus/ChineseNlpCorpus/tree/master/datasets/waimai_10k)，是某外卖平台上用户写的评价。每一行只有两列：

- `label`：1 是好评，0 是差评
- `review`：评论内容

我已经把它下载到了仓库根目录的 `nlp/data/waimai_10k.csv`。它的来源只写着「网上搜集，作者不详」，所以我们只拿来学习，不提交到 GitHub（`nlp/data/` 已经写进 `.gitignore`）。以后换电脑，用这两行重新下载：

```powershell
New-Item -ItemType Directory -Force nlp\data
Invoke-WebRequest "https://raw.githubusercontent.com/SophonPlus/ChineseNlpCorpus/master/datasets/waimai_10k/waimai_10k.csv" -OutFile nlp\data\waimai_10k.csv
```

## 二、拿到数据，先别急着训练

做机器学习的人有个习惯：拿到新数据，先花点时间「看」它。就像医生看病先问症状，不会一上来就开药。

看什么呢？四个问题：

1. 一共有多少条？
2. 好评、差评各占多少？
3. 一条评论大概多长？
4. 标签标得对不对？

其中第 2 个问题会引出今天唯一的新概念：**基线**。

### 基线：什么都不学，也能拿多少分

想象一场选择题考试，一共 100 道题，其中 70 道的正确答案都是 C。有一个学生根本不看题，每道都选 C，他能考多少分？

70 分。

如果另一个学生认认真真答题，考了 72 分，你会觉得他很厉害吗？不会，他只比「闭着眼睛全选 C」多了 2 分。

模型也是一样。**基线就是「全部猜成数量最多的那一类」能拿到的准确率。** 以后看到一个准确率，先别高兴，先问一句：比基线高多少？高出来的那部分，才是模型真正学到的。

## 三、动手看数据

下面每一步的代码你都可以直接抄进作业里，输出是我实际运行的结果。

### 第一步：读进来

用 Python 自带的 `csv` 模块就够了：

```python
import csv
from pathlib import Path

PATH = Path("nlp/data/waimai_10k.csv")     # 在仓库根目录下运行

with PATH.open(encoding="utf-8", newline="") as f:
    rows = list(csv.DictReader(f))          # 每一行变成一个字典

print("一共", len(rows), "条")
print(rows[:3])
```

```text
一共 11987 条
[{'label': '1', 'review': '很快，好吃，味道足，量大'}, {'label': '1', 'review': '没有送水没有送水没有送水'}, {'label': '1', 'review': '非常快，态度好。'}]
```

一万多条，是之前的 500 倍。

顺便留意一下：`label` 读出来是字符串 `'1'`，不是数字 1。以后交给模型之前，要用 `int()` 转一下。

还有，你看第二条：「没有送水没有送水没有送水」，标的是 1，好评。是不是有点奇怪？先记住它，后面会回来说。

### 第二步：好评差评各多少

```python
from collections import Counter

labels = Counter(r["label"] for r in rows)
for k, v in sorted(labels.items()):
    print(f"label={k}: {v} 条，占 {v / len(rows):.1%}")
```

```text
label=0: 7987 条，占 66.6%
label=1: 4000 条，占 33.4%
```

差评几乎是好评的两倍。这份数据的基线就是：

$$
\frac{7987}{11987} \approx 0.666
$$

记住这个数。**在这份数据上，一个模型如果只有 0.67 的准确率，说明它什么都没学会。**

### 第三步：评论有多长

```python
import statistics

lengths = [len(r["review"]) for r in rows]
print("最短", min(lengths), "中位数", statistics.median(lengths), "最长", max(lengths))
```

```text
最短 5 中位数 17 最长 463
```

一半的评论不超过 17 个字，和你之前的手机评论差不多长，都是短评。

再看一个小细节，数据在文件里是怎么排的：

```python
print("前 4000 条里的好评：", sum(r["label"] == "1" for r in rows[:4000]))
print("后面的好评：", sum(r["label"] == "1" for r in rows[4000:]))
```

```text
前 4000 条里的好评： 4000
后面的好评： 0
```

原来文件是**按标签排好的**：前面 4000 条全是好评，后面全是差评。

这有什么关系？想象你把这份数据从中间一刀切开，前一半训练，后一半测试。模型在训练时几乎只见过好评，测试时面对的却几乎全是差评，它怎么可能考好？

所以划分数据之前**一定要先打乱**。`train_test_split` 默认会打乱；交叉验证要像第 33 课那样写 `StratifiedKFold(..., shuffle=True)`。我专门试了一下不打乱的 `KFold(5)`，有一折的准确率只有 0.48，比全猜差评还差得多。

### 第四步：读一读，标签对不对

这一步最朴素，但最重要：随机抽几条，用自己的眼睛读。

```python
import random

rng = random.Random(34)                     # 固定种子，每次抽到的都一样
for r in rng.sample([r for r in rows if r["label"] == "1"], 8):
    print("1 |", r["review"])
```

```text
1 | 辛苦送餐的师傅。好评。
1 | 很好吃,外卖包装赞
1 | 小度骑士，速度很快，服务态度很好。很喜欢点百度外卖。
1 | 服务很好，下次还会订购
1 | 豆腐脑很淡，不太喜欢，猪蹄不错！
1 | 一开始给送错了，要的肘子，给的蔬菜，不过还好，售后做的不错，又给补送了一份，不管味道好不好，起码态度不错，所以必须给个好评！！
1 | 菜太难吃了！一次够了！再也不买了
1 | 满意，速度也非常快。
```

大部分都对。但倒数第二条「菜太难吃了！一次够了！再也不买了」被标成了好评，这显然是标错了。加上第一步看到的「没有送水没有送水没有送水」，我们已经找到两条了。

我还查了一下有没有重复的评论，结果发现有 7 句话在文件里各出现了两次，**一次标好评，一次标差评**，比如「不错很好吃」「就是有点慢」。

这告诉我们一个事实：**真实的数据一定有错。** 它不影响我们用这份数据，但要记住两点：

- 模型的准确率不可能到 100%，那些标错的，模型「猜对」反而是错的
- 以后模型出错时，先看看是不是标签错了，再去怪模型。其实之前的手机评论里也有一条：第 29 课的「这个手机屏幕非常清晰」被标成了差评，当时没发现，是后来整理记录时查出来的

### 最后，看一眼换数据的效果

我把第 33 课那套流水线（TF-IDF + 逻辑回归 + 五折交叉验证）原样放到这份数据上，换了 5 个随机种子：

| | 24 条手机评论 | 11987 条外卖评论 |
|---|---:|---:|
| 平均准确率 | 0.15 ~ 0.38 | 0.888 左右 |
| 换种子，平均分最多差多少 | 0.23 | 0.001 |
| 基线（全猜多数类） | 0.5 | 0.666 |

换种子之后，分数几乎纹丝不动。而且 0.888 比基线高出 22 个百分点，这一次模型是真学到了东西。

这才是我们想要的：**结果稳定，才能拿来比较。** 下一课学朴素贝叶斯，就用这份数据和逻辑回归比一比。

如果你选做这一步，有个小坑提前告诉你：分词函数要像第 33 课那样自己包一层 `def chinese_tokenizer(text): return jieba.lcut(text)`。直接写 `tokenizer=jieba.lcut` 会报错 `cannot pickle '_thread.RLock' object`，原因是交叉验证要把模型复制好几份，而 `jieba.lcut` 身上带着一个复制不了的东西。

## 五、小测

**1.** 在这份数据上，一个模型的准确率是 0.67，说明什么？

- A. 模型很好，三分之二都对了
- B. 和全部猜差评差不多，基本没学到东西
- C. 模型过拟合了

**2.** 文件前 4000 条全是好评。如果划分数据前不打乱，会怎样？

- A. 没影响，结果一样
- B. 训练集和测试集里好评差评的比例差得很远，模型考不好
- C. 程序会报错

**3.** 同一句「不错很好吃」一次标好评、一次标差评，说明什么？

- A. 数据有标注错误，模型的准确率到不了 100%
- B. 这句话是中性的
- C. 读文件的方式不对

<details>
<summary>答案</summary>

1. B。这份数据有 66.6% 是差评，闭着眼睛全猜差评就有 0.666。准确率一定要和基线比。
2. B。实测不打乱的 `KFold(5)` 有一折只有 0.48。所以划分前一定要打乱。
3. A。同一句话不可能既是好评又是差评，至少有一条标错了。
