## 2. 逻辑回归：输出概率的分类器

**名字里有「回归」，但它主要用于分类。** 这是个历史遗留的命名，容易误解。

它的工作方式分两步：

```text
第一步：算概率
   输入特征 → 加权求和 → sigmoid → 一个 0~1 之间的数

第二步：套阈值
   概率 ≥ 0.5  →  预测 1（好评）
   概率 <  0.5  →  预测 0（差评）
```

| 评论 | 模型算出的好评概率 | 预测 |
|---|---:|---|
| 这个手机非常好用 | 0.95 | 好评 |
| 电池续航很差 | 0.08 | 差评 |
| 拍照效果很棒 | 0.89 | 好评 |

**0.5 是默认阈值，不是什么定律**，可以改——这是第 10 小节的内容。

### 它和第 04 节学的梯度下降是什么关系

逻辑回归的训练过程就是第 04 节那套东西：

| 第 04 节 | 逻辑回归 |
|---|---|
| 预测 $\hat y = wx$ | 预测 $\hat y = \sigma(w \cdot x + b)$ |
| 损失 = 平方误差 | 损失 = 交叉熵 |
| 梯度下降更新 $w$ | 同样是梯度下降（默认用 lbfgs 这类拟牛顿法） |

**`model.fit()` 里面跑的就是那个训练循环**，只是梯度不用手推、优化器更聪明。手写过那五步，这里就不是黑盒。

## 3. 完整的五步训练流程

```python
import jieba
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split

def chinese_tokenizer(text):
    return jieba.lcut(text)

# 1. 先划分（注意：划分的是原始文本，不是特征）
texts_train, texts_test, y_train, y_test = train_test_split(
    texts, labels, test_size=0.25, random_state=42, stratify=labels
)

# 2. 只在训练集上 fit
vectorizer = TfidfVectorizer(tokenizer=chinese_tokenizer, token_pattern=None)
X_train = vectorizer.fit_transform(texts_train)
X_test = vectorizer.transform(texts_test)      # 测试集只 transform

# 3. 创建并训练模型
model = LogisticRegression(max_iter=1000)
model.fit(X_train, y_train)

# 4. 预测
y_pred = model.predict(X_test)

# 5. 评估
print("准确率：", accuracy_score(y_test, y_pred))
```

**第 1 步和第 06 节的 `course_27.py` 不同了**：那里划分的是 `X`（已经向量化的特征），这里划分的是 `texts`（原始文本）。这个改动正是为了避免第 06 节讲的数据泄漏。

### 三个核心方法

| 方法 | 作用 | 什么时候用 |
|---|---|---|
| `fit(X_train, y_train)` | 从训练数据学权重 | 只用一次，只用训练集 |
| `predict(X)` | 输出**类别**（0 或 1） | 要最终答案时 |
| `predict_proba(X)` | 输出**概率**（每个类别一列） | 要调阈值、看置信度时 |

```python
probability = model.predict_proba(new_X)

print("类别顺序：", model.classes_)        # [0 1]
print("差评概率：", probability[0][0])
print("好评概率：", probability[0][1])
```

**`predict_proba` 返回的列顺序由 `model.classes_` 决定**，别想当然认为第 0 列就是「差评」。稳妥的写法是：

```python
positive_index = list(model.classes_).index(1)
probabilities = model.predict_proba(X_test)[:, positive_index]
```

`model_b.py` 用的就是这个写法，是对的。

## 4. 准确率为什么不够用

准确率的定义很直观：

$$
Accuracy = \frac{\text{预测正确的数量}}{\text{总数量}}
$$

它的问题是**把所有错误看成一样的**。

设想一个差评识别系统，100 条评论里只有 5 条差评。一个什么都不学、**全部预测「好评」**的模型：

```text
准确率 = 95/100 = 95%
差评找出来的数量 = 0
```

**95% 的准确率，业务价值为零。** 这就是类别不平衡下准确率的失效方式。

所以需要能分别衡量「找得准」和「找得全」的指标。

## 5. 混淆矩阵与四个基础量

把预测结果按「真实 × 预测」分成四格：

| 实际情况 | 模型预测好评 | 模型预测差评 |
|---|---:|---:|
| **实际好评** | TP = 40 | FN = 10 |
| **实际差评** | FP = 5 | TN = 45 |

| 缩写 | 全称 | 含义 | 俗称 |
|---|---|---|---|
| **TP** | True Positive | 实际好评，预测好评 | 抓对了 |
| **FP** | False Positive | 实际差评，**错判成好评** | 冤枉了（误报） |
| **TN** | True Negative | 实际差评，预测差评 | 放过对了 |
| **FN** | False Negative | 实际好评，**错判成差评** | 漏掉了（漏报） |

**记忆方法**：第一个字母看「预测对不对」（True/False），第二个字母看「预测成了什么」（Positive/Negative）。所以 FP = 预测成正类但错了。

这里把**好评定为正类（Positive）**，因为标签是 `1`。正类是谁，决定了后面所有指标的含义。

### sklearn 的混淆矩阵怎么读

```python
from sklearn.metrics import confusion_matrix
print(confusion_matrix(y_test, y_pred))
```

```text
[[0 3]
 [2 1]]
```

**行是真实标签，列是预测标签，顺序按标签值升序（0 在前，1 在后）**：

| | 预测 0（差评） | 预测 1（好评） |
|---|---:|---:|
| **真实 0（差评）** | 0 | 3 |
| **真实 1（好评）** | 2 | 1 |

读出来是：3 条差评全部被误判成好评；3 条好评只对了 1 条。**对角线是对的，非对角线是错的。**

> 想避免记错顺序，可以显式指定：`confusion_matrix(y_true, y_pred, labels=[0, 1])`。

## 6. Precision、Recall、F1

### 准确率 Accuracy：整体对了多少

$$
Accuracy=\frac{TP+TN}{TP+TN+FP+FN} = \frac{40+45}{100} = 0.85
$$

### 精确率 Precision：说是好评的，有多少真是

$$
Precision=\frac{TP}{TP+FP} = \frac{40}{40+5} \approx 88.9\%
$$

**分母是「所有被预测为正类的」。** 它回答：模型说好评的时候，可信度有多高？

### 召回率 Recall：真的好评，找出来多少

$$
Recall=\frac{TP}{TP+FN} = \frac{40}{40+10} = 80\%
$$

**分母是「所有真实的正类」。** 它回答：该找出来的，漏了多少？

### F1：两者的调和平均

$$
F1=2\times\frac{Precision\times Recall}{Precision+Recall} \approx 84.2\%
$$

**为什么用调和平均而不是算术平均？** 因为调和平均会被小的那一项拖住。Precision = 1.0、Recall = 0.01 时：

| | 计算 | 结果 |
|---|---|---|
| 算术平均 | $(1.0+0.01)/2$ | 0.505 看起来还行 |
| **调和平均（F1）** | $2 \times \frac{1.0 \times 0.01}{1.0+0.01}$ | **0.0198** 如实反映很差 |

**F1 高，必须两个都高。** 这就是用它做综合指标的理由。

### 四个指标怎么选

| 指标 | 关注 | 什么业务场景优先看它 |
|---|---|---|
| Accuracy | 整体正确率 | 类别均衡、错误代价相同 |
| **Precision** | 报出来的准不准 | **误报代价高**：垃圾邮件过滤（别把正常邮件扔掉） |
| **Recall** | 该找的漏没漏 | **漏报代价高**：疾病筛查、差评识别、风控 |
| F1 | 综合 | 两者都要，或者要一个单一数字比较模型 |

**先问业务要什么，再选指标。** 这是第 29 课最该记住的一句话。

## 7. `pos_label`：指标是算给谁的

这是个容易踩的坑。标签定义是：

```python
labels = [1] * 12 + [0] * 12        # 1=好评, 0=差评
```

`precision_score()`、`recall_score()`、`f1_score()` **默认 `pos_label=1`**，算的是**好评**的指标。

但差评识别系统关心的是差评。这时必须写：

```python
precision_score(y_test, y_pred, pos_label=0)
recall_score(y_test, y_pred, pos_label=0)
f1_score(y_test, y_pred, pos_label=0)
```

**算错了对象，整个评估都是在回答一个你没问的问题。**

### `classification_report` 一次给全

```python
from sklearn.metrics import classification_report
print(classification_report(y_test, y_pred, target_names=["差评", "好评"]))
```

```text
              precision    recall  f1-score   support

          差评       0.00      0.00      0.00         3
          好评       0.25      0.33      0.29         3

    accuracy                           0.17         6
   macro avg       0.12      0.17      0.14         6
weighted avg       0.12      0.17      0.14         6
```

**它把每个类别都当一次正类，各算一遍**，省掉手写 `pos_label`。

| 列 / 行 | 含义 |
|---|---|
| `support` | 该类别**真实**有多少条（不是预测的） |
| `macro avg` | 各类别指标的**简单平均**（每类等权） |
| `weighted avg` | 按 `support` **加权平均**（大类影响大） |

**`target_names` 的顺序必须和标签升序一致**——`["差评", "好评"]` 对应 `[0, 1]`。写反了，报告会把两个类别的指标张冠李戴，而且不报错。

## 8. 分类阈值：从概率到标签

`predict()` 内部就是「概率 ≥ 0.5 判 1」。把这一步自己写出来，就能换阈值：

```python
import numpy as np

positive_index = list(model.classes_).index(1)
probabilities = model.predict_proba(X_test)[:, positive_index]

threshold = 0.42
pred_threshold = np.where(probabilities >= threshold, 1, 0)
```

### `np.where` 的三参数形式

```python
np.where(条件, 条件为真时的值, 条件为假时的值)
```

它对数组**逐元素**判断：

| 好评概率 | ≥ 0.42？ | 结果 |
|---:|---|---:|
| 0.20 | 否 | 0 |
| 0.40 | 否 | 0 |
| 0.45 | 是 | 1 |
| 0.83 | 是 | 1 |

一行就把整个概率数组变成了标签数组，不需要写 `for` 循环。

### 阈值往哪调，指标往哪动

| 阈值 | 判成好评的条件 | 后果 |
|---|---|---|
| **降低**（0.5 → 0.3） | 更容易 | 好评 Recall ↑、Precision ↓ |
| **提高**（0.5 → 0.8） | 更难 | 好评 Precision ↑、Recall ↓ |

**这是一个此消彼长的权衡，不是免费的改进。**

想象把所有样本按好评概率排成一队，阈值是队伍里的一道线。线往左移，被划成「好评」的变多——真好评抓得更全（Recall↑），但也抓进更多假的（Precision↓）。

### 关键认识：调阈值不会让模型变聪明

**阈值调整只改变判断标准，不改变模型学到的任何东西。** 权重没变、概率没变，只是切分的位置变了。

所以它能做的是：**在既有的判别能力上，按业务需求选一个更合适的折中点**。如果模型本身没有判别能力（概率都挤在 0.5 附近），调阈值调出来的全是噪声——第二部分有实测。

> 还有一条纪律：**阈值不能在最终测试集上反复试。** 那等于用测试集调参，和数据泄漏一个性质。
> 正式做法是在**验证集**上选阈值，测试集只用一次。这个问题到第 33 课（交叉验证）才正式解决。

## 9. 错误分析：沿链路逐层排查

模型效果差的时候，**第一反应不该是调参**，而是查清错在哪一层。

```text
原始文本    "这个手机不值得购买"
   ↓  ① 分词对不对？否定词保住了吗？
分词结果    ['这个','手机','不','值得','购买']
   ↓  ② 这些词在训练词汇表里吗？
TF-IDF 特征  [0, 0.4, 0.5, ...]  ← 未登录词这里是 0
   ↓  ③ 模型给这些词学了什么权重？
加权求和
   ↓  ④ 概率离 0.5 有多远？是笃定还是在猜？
预测结果    好评（错）
```

每一层都有对应的检查代码：

```python
# ① 分词
print(jieba.lcut(text))

# ② 特征与未登录词
vocab = set(vectorizer.get_feature_names_out())
unknown = [w for w in jieba.lcut(text) if w not in vocab]

# ③ 权重
for word, weight in zip(vectorizer.get_feature_names_out(), model.coef_[0]):
    print(word, weight)

# ④ 概率
print(model.classes_, model.predict_proba(X_new))
```

**这套排查顺序值得背下来**，因为它是「从输入到输出」的，哪一层断了就在哪一层修。跳过前面直接调 `max_iter` 或者换算法，是在赌。

> 第 29 课有一道小测正是考这个：
> 「模型把『这个手机太差了』预测成好评，第一步该做什么？」
> 正确答案是 **B. 查看这条评论的分词结果、TF-IDF 特征和模型预测**，
> 而不是 A（把 `max_iter` 改成 100000）或 C（删掉这条数据）。

## 10. 未登录词（OOV）

这是 TF-IDF 这类词表方法的硬限制。

**`transform()` 只使用训练阶段建立的词汇表，不会为新词创建特征列。**

```text
训练集里有「特别差」→ 模型学到「差」偏向差评
测试集出现「特别棒」→ 「棒」不在词汇表 → 这一维根本不存在
                     → 模型对「棒」毫无反应
```

未登录词（Out-Of-Vocabulary）在特征向量里的表现是：**它不贡献任何信息**，等于被静默丢弃。

检查代码：

```python
vocab = set(vectorizer.get_feature_names_out())
for text in texts_test:
    words = chinese_tokenizer(text)
    unknown_words = [w for w in words if w not in vocab]
    print(text, "未登录词：", unknown_words)
```

**这段检查在小数据实验里几乎是必做的。** 第二部分会看到，它一次就定位了模型表现差的主要原因。

> OOV 问题的根本解法不是「加更多数据」（总会有新词），而是换表示方法：
> **词向量**（相似词有相似向量）、**子词切分**（BERT Tokenizer 把未见过的词拆成见过的片段）。
> 这是后面课程的方向。

## 11. 基线模型（Baseline）

第一个跑通的模型叫**基线**。它的作用不是「好」，而是**给后续所有优化提供比较起点**。

| 实验 | 配置 | F1 |
|---|---|---:|
| Baseline | 18 条训练 + TF-IDF + 逻辑回归 | 0.29 |
| 实验 B | 扩充训练数据 | ？ |
| 实验 C | 优化分词 | ？ |
| 实验 D | 调正则化 | ？ |

**做实验必须记录配置和结果，不能只记住最后一个模型的分数。** 否则改了三样东西、效果变好了，你不知道是哪一样起了作用。

一个更基础的基线是**多数类基线**：全部预测样本最多的那个类。如果你的模型打不过它，说明它什么都没学到。

第 28 课小测第 2 题考的正是这个，答案 B：**避免测试集信息泄漏，使用训练集学到的词汇和 IDF**。第 06 节已经把这件事实测过了。

**问号三：`max_iter` 的作用？**

当时得到的答复是：

> `max_iter` 是模型优化参数时允许的最大迭代次数。**设置为 10 可能不够，可能出现模型尚未收敛的警告。** 先用 1000 作为实验基准。

这个解释是对的——但**在这组数据上它不成立**，下面有实测。

## 实测：被推翻的一个猜测

我整理到这里时的第一反应是：`max_iter=10` 太小了，模型根本没训完，这才是准确率 16.7% 的根因。

**跑完发现这个猜测是错的。**

```text
max_iter = 10
  ConvergenceWarning: 无
  实际迭代次数 n_iter_: [5]
  训练集准确率: 1.0
  测试集准确率: 0.16666666666666666

max_iter = 100      →  n_iter_: [5]，所有指标完全相同
max_iter = 1000     →  n_iter_: [5]，所有指标完全相同
```

**模型第 5 次迭代就收敛了，`max_iter=10` 绰绰有余。** 没有 `ConvergenceWarning`，三种设置输出的概率、权重、混淆矩阵一模一样。

原因是这组数据太小太干净：18 个样本、37 个特征、线性可分，lbfgs 几步就走到最优。

| | 猜测 | 实测 |
|---|---|---|
| `max_iter=10` 的影响 | 未收敛，模型没训完 | **无影响**，5 步就收敛 |
| 准确率 16.7% 的根因 | 迭代次数不够 | **另有原因**（见下） |

> **`n_iter_` 是验证收敛的权威方法。** 想知道 `max_iter` 够不够，不要猜，打印 `model.n_iter_`：
> 它等于 `max_iter` 才说明撞上了上限，远小于就说明早就收敛了。
> 另外 sklearn 未收敛时会主动发 `ConvergenceWarning`——**没有警告，就不是收敛问题。**
>
> 这条和 A 线那些坑是同一类教训：**凭「看起来像」下结论，会把排查引到错误方向。**

## 第 29 课：`model_a.py` —— 16.7% 的真正原因

运行结果：

```text
混淆矩阵:
[[0 3]
 [2 1]]
准确率: 0.16666666666666666
精确率 0.25
召回率 0.3333333333333333
F1分数: 0.2857142857142857
```

当时的反应是「正确率好低，这对吗」。得到的回答是：**数学上没错，模型确实很差**，而且紧接着给了一条重要的工作方法——

> 现在先不要修改模型，先做错误分析。
> **模型效果差时，先找到错在哪里，再决定如何优化。**

### 错误分析第一层：逐条看错在哪

```python
for text, true_label, pred_label in zip(texts_test, y_test, y_pred):
    print("评论：", text)
    print("真实标签：", true_label)
    print("预测标签：", pred_label)
    print("是否正确：", true_label == pred_label)
```

| 测试评论 | 真实 | 预测 | |
|---|---|---|---|
| 手机运行速度很慢 | 差评 | 好评 | ✗ |
| 这个产品真的不错 | 好评 | 差评 | ✗ |
| 屏幕显示效果很好 | 好评 | 好评 | ✓ |
| 电池续航特别棒 | 好评 | 差评 | ✗ |
| 拍照效果非常模糊 | 差评 | 好评 | ✗ |
| 屏幕显示效果很差 | 差评 | 好评 | ✗ |

### 错误分析第二层：未登录词检查

这一步直接命中根因。我把 `model_a.py` 的未登录词检查跑了一遍：

```text
手机运行速度很慢 -> ['手机','运行','速度','很','慢']      未登录: ['慢']
这个产品真的不错 -> ['这个','产品','真的','不错']        未登录: ['不错']
屏幕显示效果很好 -> ['屏幕显示','效果','很','好']        未登录: ['屏幕显示']
电池续航特别棒   -> ['电池','续航','特别','棒']          未登录: ['棒']
拍照效果非常模糊 -> ['拍照','效果','非常','模糊']        未登录: ['模糊']
屏幕显示效果很差 -> ['屏幕显示','效果','很差']           未登录: ['屏幕显示','很差']
```

**6 条测试评论，每一条的情感判别词都不在训练词汇表里。**

| 测试集的情感词 | 训练集里有的 | 为什么对不上 |
|---|---|---|
| `慢` | `很快` | 反义词没覆盖 |
| `不错` | `不好` | 反义词没覆盖 |
| `棒` | `差` | 反义词没覆盖 |
| `模糊` | `清晰` | 反义词没覆盖 |
| `很差` | `差`、`太差` | **分词粒度不一致** |
| `屏幕显示` | 无 | 该主题没有训练样本 |

模型能看到的只剩「手机」「效果」「电池」「速度」这些**中性词**——而它们在训练集的好评和差评里都出现，权重接近 0。

**所以模型不是学错了，是什么都看不见。** 它在用一堆中性词瞎猜。

### 错误分析第三层：概率有多笃定

```text
好评概率: [0.5319  0.4166  0.5308  0.4454  0.5926  0.5503]
```

**6 条全部落在 0.42 ~ 0.60 之间，离 0.5 最远的也只有 0.09。**

一个有判别能力的模型应该给出接近 0 或接近 1 的概率。全挤在 0.5 附近，意味着**模型对每一条都没有把握**。这组概率本身就是「模型不具备判别能力」的证据。

**这也解释了为什么后面调阈值会让指标大幅跳动**：所有样本都紧贴着决策线，线稍微一动，一半样本就换了类别。

### 当时的诊断对了多少

| 诊断 | 实测评价 |
|---|---|
| 数据量太少（18 条训练） | ✅ 对，而且 37 个特征 ≈ 2 倍样本数 |
| **词汇覆盖不足** | ✅ **这是最直接的原因**，实测 6/6 条的情感词全部未登录 |
| 测试集太小（错 1 条差 16.7%） | ✅ 对，这是指标不可信的原因 |
| TF-IDF 不理解否定表达 | ⚠️ 这次没触发——6 条里只有「不错」，而它是整词未登录，不是否定没学会 |

当时漏掉的一条是**分词粒度不一致**：训练集切出「差」，测试集切出「很差」，jieba 对这两句的处理方式不同，导致同一个情感概念变成两个互不相干的特征。这不是数据量问题，加数据也不一定能解决。

## `model_b.py` —— 扩充数据之后反而更差

课程设计的实验是：保留原测试集不变，给训练集加 12 条（6 好 6 差），对比 A / B。实际代码换了另一种做法：**把数据集整体扩到 32 条，重新划分**。

实测结果：

```text
规模: 训练 (24, 46)  测试 (8, 46)
训练集准确率: 1.0
测试集准确率: 0.25
混淆矩阵:
 [[2 2]
  [4 0]]
P/R/F1(好评为正): 0.0  0.0  0.0
```

**4 条好评全部被判成差评，好评的 Precision / Recall / F1 全是 0。**

数据从 24 条加到 32 条，测试准确率从 16.7% 到 25%——**在 8 条测试样本上，这个差异就是 1 条样本的事，没有任何意义。**

### 为什么好评一条都没找出来

逐条看：

```text
[错] 这个产品真的不错    真实1 预测0  好评概率0.4830   未登录 []
[错] 这个手机值得购买    真实1 预测0  好评概率0.4107   未登录 []
[对] 手机运行速度很慢    真实0 预测0  好评概率0.4767   未登录 []
[对] 这个手机的屏幕太小了 真实0 预测0  好评概率0.4419   未登录 ['太小']
[错] 屏幕显示效果很好    真实1 预测0  好评概率0.4192   未登录 ['好']
[错] 手机质量非常好      真实1 预测0  好评概率0.4353   未登录 ['好']
[错] 电池续航特别差      真实0 预测1  好评概率0.6293   未登录 ['差']
[错] 电池一点都不耐用    真实0 预测1  好评概率0.5652   未登录 ['一点','都']
```

**三件事同时在起作用：**

**第一，单字「好」不在训练词汇表。** 我专门查了训练集的分词结果：

```text
这个手机非常好用 -> ['这个','手机','非常','好用']
这个产品真的不好 -> ['这个','产品','真的','不好']
（训练集里没有任何一条被切出独立的『好』）
```

训练集的好评用的是「好用」「不错」「优秀」「满意」，jieba 从来没切出单字「好」。于是测试集那两条最直白的好评——「手机质量非常好」「屏幕显示效果很好」——**情感词完全不可见**。

**第二，单字「差」也不在训练词汇表。** 训练集切出的是「太差」「很差」「糟糕」。测试集「电池续航特别差」的「差」未登录，于是这条差评得到 0.6293 的好评概率，**是全场最「自信」的一个预测，而且错了**。

**第三，「电池」被学成了好评词。** 打印权重后看得很清楚：

```text
最偏好评: [('优秀',0.267), ('像素',0.271), ('耐用',0.282), ('很漂亮',0.309),
          ('特别',0.323), ('好用',0.359), ('电池',0.427), ('不错',0.613)]
最偏差评: [('糟糕',-0.495), ('这个',-0.315), ('模糊',-0.294), ('慢',-0.267),
          ('屏幕',-0.265), ('很差',-0.262), ('屏幕显示',-0.262), ('失望',-0.254)]
```

**「电池」权重 +0.427，是第二偏好评的特征。** 因为训练集里「电池非常耐用」是好评。于是测试集两条含「电池」的差评被这一个词推过了 0.5——它们的真正情感词（「差」、「一点都不」）全都未登录或不可见。

**顺便看看「这个」：权重 -0.315，第二偏差评。** 一个纯粹的指示代词，只因为在训练集的差评里出现得多一点，就被学成了判别特征。**这就是过拟合的具体长相。**

> 46 个特征对 24 个训练样本——**特征数接近样本数的两倍**。
> 这种配置下模型必然能把训练集背得一字不差（训练集准确率 1.0），
> 同时学出一堆像「这个」「电池」这样的虚假规律。第 08 节讲的正则化就是针对这个问题。

### 一个被忽略的标注错误

检查 `model_b.py` 的数据时发现，后 16 条（标签全是 0 = 差评）里有一条不对：

```python
"这个手机运行速度非常慢",   # 0  ✅
"这个手机屏幕非常清晰",     # 0  ← 这是好评，标错了
"这个手机使用起来发烫",     # 0  ✅
"这个手机的屏幕太小了",     # 0  ✅
```

「这个手机屏幕非常清晰」是**明确的好评**，却被标成了差评。更糟的是，训练集里同时存在：

```text
标签 1  <-  拍照效果非常清晰      分词 ['拍照','效果','非常','清晰']
标签 0  <-  这个手机屏幕非常清晰   分词 ['这个','手机','屏幕','非常','清晰']
```

**同一个词「清晰」，一条指向好评、一条指向差评。** 模型被两个相反的信号拉扯，学出来的权重是：

```text
清晰  权重 +0.0632
```

**几乎为零。** 一个本该是强好评信号的词，被一条错标注抹成了噪声。模型对那条错标样本的预测是 `0`（概率 0.4268），也就是说它**老老实实学会了这个错误**。

| | 影响 |
|---|---|
| 「清晰」的权重 | 从应有的显著正值被压到 +0.06 |
| 对训练集 | 模型照单全收，把「清晰 → 差评」当规律 |
| 对测试集 | 任何含「清晰」的样本都失去判别信息 |

> **标注质量比模型选择重要。** 32 条数据里错 1 条，就足以毁掉一个关键特征。
> 真实项目里标注错误率通常在百分之几，所以才需要标注规范、交叉标注、一致性检查。
>
> 这一条当时没有被发现——因为注意力都在「模型为什么不准」上，没人回头检查标签本身。
> **错误分析的第零层应该是「数据标得对不对」。**

## 阈值实验：在没有判别力的模型上调阈值

`model_b.py` 最后设了 `threshold = 0.42`。我把几个阈值都跑了一遍：

```text
好评概率: [0.483  0.4107  0.4767  0.4419  0.4192  0.4353  0.6293  0.5652]
真实标签: [1, 1, 0, 0, 1, 1, 0, 0]
```

| 阈值 | 预测结果 | Acc | 好评 P | 好评 R | 好评 F1 | 差评 R |
|---:|---|---:|---:|---:|---:|---:|
| 0.30 | 全判好评 | 0.500 | 0.500 | **1.000** | 0.667 | 0.000 |
| 0.42 | `1,0,1,1,0,1,1,1` | 0.250 | 0.333 | 0.500 | 0.400 | 0.000 |
| **0.50**（默认） | `0,0,0,0,0,0,1,1` | 0.250 | **0.000** | **0.000** | **0.000** | 0.500 |
| 0.60 | 只判 1 条好评 | 0.375 | 0.000 | 0.000 | 0.000 | 0.750 |
| 0.70 | 全判差评 | 0.500 | 0.000 | 0.000 | 0.000 | **1.000** |

**三条结论：**

**第一，`0.42` 看起来「改善」了指标，但那不是改善。** 默认阈值下好评 F1 = 0（一条好评都没找到），降到 0.42 之后随便判几条好评，F1 自然从 0 变成 0.4。**这是从「全错」变成「蒙对了一部分」，模型没有变好。** 当时的结论是「Precision、Recall 和 F1 都有所提高」——数字没错，但解释不成立。

**第二，两个极端阈值给出了最高的准确率 0.5。** 全判好评和全判差评都能拿 0.5——因为测试集是 4:4 平衡的。**一个 50% 的准确率在平衡二分类上等于抛硬币。** 中间那几个阈值（0.42、0.5）只有 0.25，**比抛硬币还差一半**。

**第三，这组概率印证了「调阈值不改变模型」。** 8 个概率全在 0.41~0.63 之间，跨度 0.22。阈值在这个窄带里移动，就是在一堆几乎没有区别的分数里硬切一刀。切在哪里，指标就跟着跳——**跳动来自噪声，不是来自判别力。**

> **在模型没有判别能力之前，调阈值毫无意义。** 正确的顺序是：
> 先让模型学到真实规律（覆盖词汇、修正标注、加数据），
> 再根据业务目标在**验证集**上选阈值。
>
> 当时课件里也提醒了这一点：
> 「小数据集上指标波动会比较明显，而且阈值不能根据最终测试集反复调优。」

## 实验设计本身的问题

课程设计的 A/B 实验是**控制变量**的：

| 实验 | 训练数据 | 测试数据 |
|---|---:|---:|
| A：基线 | 18 条 | **原来的 6 条** |
| B：扩充 | 30 条 | **同样的 6 条** |

实际做的是：数据集从 24 条扩到 32 条，然后**重新 `train_test_split`**。结果测试集从 6 条变成 8 条、内容也完全不同。

**这样 A 和 B 的分数不可比**——变了两样东西（训练数据 + 测试数据），分数变化无法归因。

| | 课程设计 | 实际做法 |
|---|---|---|
| 训练集 | 18 → 30（变） | 18 → 24（变） |
| 测试集 | 6 条，**不变** | 6 条 → 8 条，**也变了** |
| 能否归因 | 能 | **不能** |

> **做对比实验，一次只能改一个变量。** 这是实验设计的基本功，和代码能力无关。
> 课程还提醒了另一件事：那 6 条测试评论已经被用来做错误分析、并据此构造了新样本，
> **它们事实上已经变成验证集，不再是独立测试集了。**

<summary>参考答案</summary>

1. 做的是**分类**（名字是历史遗留）。它直接输出的是**概率**（0~1 之间的数），再经过阈值（默认 0.5）转成类别。
2. `predict()` 给类别（0 或 1），`predict_proba()` 给每个类别的概率。列顺序由 `model.classes_` 决定，不能想当然——稳妥写法是 `list(model.classes_).index(1)` 取出正类所在的列。
3. 95%。说明**准确率在类别不平衡时会失效**：一个什么都没学、差评一条也找不出的模型也能拿 95%，业务价值为零。
4. TP = 实际正、预测正（抓对）；FP = 实际负、预测正（误报）；TN = 实际负、预测负（放过对了）；FN = 实际正、预测负（漏报）。记法：**第一个字母看预测对不对，第二个字母看预测成了什么**。
5. **行是真实标签、列是预测标签，顺序按标签值升序**。所以：真实 0 预测 0 有 0 条、真实 0 预测 1 有 3 条（3 条差评全被误判）、真实 1 预测 0 有 2 条、真实 1 预测 1 有 1 条。对角线是对的。
6. Precision 的分母是「所有**被预测为**正类的」，Recall 的分母是「所有**真实的**正类」。一句话：**Precision 看报出来的准不准，Recall 看该找的漏没漏。**
7. 因为调和平均会被小的那一项拖住。Precision = 1.0、Recall = 0.01 时，算术平均是 0.505（看起来还行），F1 只有 0.0198（如实反映很差）。**F1 高必须两个都高。**
8. 垃圾邮件过滤看 **Precision**（误报代价高，别把正常邮件扔进垃圾箱）；疾病筛查看 **Recall**（漏报代价高，宁可多叫几个人来复查，不能漏掉病人）。
9. 默认 `pos_label=1`。当你真正关心的类别标签不是 1 时（比如差评是 0），必须写 `pos_label=0`，否则算的是另一个类别的指标，而且不会报错。
10. `support` = 该类别**真实**的样本数；`macro avg` = 各类别指标的简单平均（每类等权）；`weighted avg` = 按 `support` 加权平均（大类影响更大）。
11. 把概率数组按阈值转成标签数组。三个参数是：条件、条件为真时取的值、条件为假时取的值，**逐元素**判断，一行代替 `for` 循环。
12. Recall **上升**、Precision **下降**。阈值降低后更容易被判成正类，真正的正类抓得更全（Recall↑），但同时抓进更多假的（Precision↓）。
13. **不会。** 权重、概率都没变，改变的只是「把概率切成类别」的那条线的位置。所以它能做的是在既有判别能力上选一个业务上更合适的折中点，不能让模型变聪明。
14. 顺序是 **① 分词 → ② 特征与未登录词 → ③ 权重 → ④ 概率**。对应 `jieba.lcut(text)`、`set(vectorizer.get_feature_names_out())` 做差集、`zip(feature_names, model.coef_[0])`、`model.predict_proba()`。（还应该补一个**第零层：检查标注对不对**。）
15. 训练词汇表里没有的词。`transform()` 不会为它创建特征列，所以它**不贡献任何信息**，等于被静默丢弃。
16. **不是。** 实测 `n_iter_ = [5]`，模型第 5 次迭代就收敛，`max_iter` 设 10 / 100 / 1000 的输出完全相同，也没有 `ConvergenceWarning`。验证方法：**打印 `model.n_iter_`**，它等于 `max_iter` 才说明撞上了上限；另外 sklearn 未收敛会主动发警告，没警告就不是收敛问题。
17. **6 条评论的情感判别词全部不在训练词汇表里**（`慢`、`不错`、`棒`、`模糊`、`很差`、`屏幕显示`）。模型只能看到「手机」「效果」「电池」这类中性词，等于在瞎猜——印证是 6 个好评概率全挤在 0.42~0.60 之间。
18. **分词粒度不一致。** 加数据不一定能解决，因为问题出在 jieba 对不同句子的切分方式不同，同一个情感概念被拆成了互不相干的特征。解法是统一分词（自定义词典）、或者换成子词/词向量表示。
19. 因为两条最直白的好评「手机质量非常好」「屏幕显示效果很好」里的单字 **`好` 不在训练词汇表**——训练集的好评用的全是「好用」「不错」「优秀」，jieba 从没切出独立的「好」。4 条好评全部被判差评，所以 TP = 0，Precision、Recall、F1 全为 0。
20. 因为训练集里「电池非常耐用」是好评，模型给「电池」学了 **+0.427** 的权重（第二偏好评）。于是测试集两条含「电池」的差评被这一个词推过了 0.5。这说明**在样本数远小于特征数时，模型会把无关词学成判别特征**——「这个」被学成 -0.315 也是同一回事。这就是过拟合的具体长相。
21. 「这个手机屏幕非常清晰」被标成了 0（差评）。训练集里同时有「拍照效果非常清晰」标 1，**同一个词指向两个相反的类别**，结果「清晰」的权重被压到 **+0.0632**，几乎为零——一个本该是强好评信号的词变成了噪声。
22. **等于抛硬币。** 测试集是 4:4 平衡的，全判好评或全判差评都能拿 0.5。中间阈值只有 0.25，**比抛硬币还差一半**。这组数字整体说明模型没有判别能力。
23. 课程设计是**控制变量**的：只改训练数据，测试集保持那 6 条不变。实际做法把数据集整体扩到 32 条后**重新划分**，训练集和测试集同时变了（6 条 → 8 条、内容不同），所以分数变化无法归因到「加了数据」这一个原因上。
24. 因为那 6 条已经被用来做错误分析，并且**根据它们的错误构造了新的训练样本**。信息已经从测试集流回了模型开发过程，它现在的角色是**验证集**。最终测试集必须在整个开发过程中保持独立、只用一次。
