# Day 7：游戏结束时给一份统计

昨天你已经把每次猜测存进了列表。有了数据，就可以算点东西：一共猜了几次，最大猜过多少，最小猜过多少，平均是多少。

算这些只要四个内置函数。今天真正要花心思的是另一件事：**列表是空的时候怎么办。**

## 一、四个统计函数

```python
g = [30, 70, 50]
print(len(g), max(g), min(g), sum(g))
avg = sum(g) / len(g)
print(avg)
print(f"平均猜测值：{avg:.2f}")
```

```text
3 70 30 150
50.0
平均猜测值：50.00
```

`len`、`max`、`min`、`sum` 都是内置函数，不用导入。

平均值是总和除以个数。注意 `/` 的结果**一定是小数**，就算能除尽也一样，所以打出来是 `50.0`，`6 / 2` 也是 `3.0`。

题目要求保留两位小数，用 f-string 的格式说明：在变量后面加 `:.2f`。换一组除不尽的数看得更清楚：

```python
g2 = [30, 70, 51]
avg2 = sum(g2) / len(g2)
print(avg2)
print(f"{avg2:.2f}")
```

```text
50.333333333333336
50.33
```

`:.2f` 只影响显示，`avg2` 本身的值没有变。

## 二、空列表会让它们崩溃

用户刚进游戏，一次没猜就输入 `q`，列表是空的。这时候：

```python
e = []
print(len(e), sum(e))
```

```text
0 0
```

再分别算 `max(e)`、`min(e)`、`sum(e) / len(e)`，三个都报错：

```text
max(e) -> ValueError: max() iterable argument is empty
min(e) -> ValueError: min() iterable argument is empty
sum(e) / len(e) -> ZeroDivisionError: division by zero
```

`len` 和 `sum` 没事，空列表的长度是 0、总和是 0。`max` 和 `min` 会报错，因为空列表根本没有最大值。平均值是 0 除以 0，也报错。

这不是什么少见的情况，「一次都没猜就退出」在正常使用中一定会发生。所以要在计算之前先判断，而不是等它崩了再去接。

判断列表是不是空的，最常见的写法是 `if not 列表:`。空列表在 `if` 里当作假，有元素的列表当作真：

```python
print(bool([]), bool([0]))
```

```text
False True
```

## 三、守卫语句：先把特殊情况挡在门外

统计函数可以这样写：

```python
def show_statistics(guess_list: list[int]) -> None:
    print("猜测记录：", guess_list)
    print("有效猜测次数：", len(guess_list))

    if not guess_list:
        print("暂无统计数据")
        return

    avg = sum(guess_list) / len(guess_list)
    print("最大猜测值：", max(guess_list))
    print("最小猜测值：", min(guess_list))
    print(f"平均猜测值：{avg:.2f}")
```

中间那段 `if not guess_list: ... return` 叫**守卫语句**。Day 5 说过 `return` 会结束函数，这里它后面什么都不带，作用就是「到此为止」。

这样写的好处是：读到 `return` 下面的代码时，你可以确定列表一定不是空的，`max`、`min`、除法都安全。主要的计算也不用缩进在 `else` 里面。

`list[int]` 表示「装整数的列表」，比只写 `list` 说得更清楚。`-> None` 表示这个函数只负责打印，不交回结果。

## 四、范围检查：写「什么是对的」再取反

题目只接受 1 到 100。检查范围有两种写法：

```python
if i_num < 0 or i_num > 100:     # 列举不合法的情况
if not 1 <= i_num <= 100:        # 描述合法的范围，再取反
```

我用两个条件分别检查了几个数：

```text
-5 旧条件拦住 新条件拦住
0 旧条件放过 新条件拦住
1 旧条件放过 新条件放过
100 旧条件放过 新条件放过
101 旧条件拦住 新条件拦住
```

第一种放过了 0。0 既不小于 0，也不大于 100。列举不合法的情况，很容易漏掉一个边界；直接说清「1 到 100 是对的」，就不会漏。

## 六、小测

**1.** `max([])` 会怎样？

- A. 返回 0
- B. 返回 `None`
- C. 报 `ValueError`

**2.** 用户输入 `0`，`if i_num < 0 or i_num > 100:` 会拦住它吗？

- A. 会
- B. 不会

**3.** 守卫语句里那个单独的 `return` 起什么作用？

- A. 返回空列表
- B. 提前结束函数，后面的计算不再执行
- C. 结束整个程序

<details>
<summary>答案</summary>

1. C。空列表没有最大值。`len([])` 和 `sum([])` 倒是都能正常得到 0。
2. B。0 不小于 0，也不大于 100，两个条件都不成立。
3. B。`return` 结束的是当前函数，程序回到调用它的地方继续走。

</details>

最后有一行讲评里提到了、但 `Day6.py` 里没改的：

```python
def random_num():
    return random.randint(1,100)

random_num = random_num()
```

右边调用函数，左边把结果存进了**同一个名字**。这一行执行完，`random_num` 就不再是函数，而是一个整数。现在只调用一次，看不出问题；哪天想再抽一个数：

```text
TypeError: 'int' object is not callable
```

「整数不能被调用」，明明定义了函数，报错却这么说，第一次看到很难想到原因。办法是让名字各说各的：函数名用动词，变量名用名词，比如 `generate_random_number()` 和 `target_num`，自然不会撞上。

还有一个小地方：第二版猜对时直接打印「游戏结束！」，没有告诉玩家「猜对了」。统计函数是两条路径共用的，「猜对了」这句该放在调用它之前。
