## 为什么需要这一章

第 1.6 章的 `play` 是这样的：

```python
def play(target: int, max_attempts: int = 7, ask=input, say=print) -> str:
    attempts = 0
    while attempts < max_attempts:
        raw = ask(f"[{attempts + 1}/{max_attempts}] 你猜： ")
        ...
```

答案、次数上限、已经猜了几次，这几个变量**总是一起出现**。现在想加两个功能：

- 猜错几次以后给提示（答案在哪个范围）
- 记分板（每个玩家最好成绩）

如果继续用函数，每个新函数都要把这一组变量传进去：

```python
def give_hint(target, history, low, high, hint_after): ...
def remaining(history, max_attempts): ...
def is_over(target, history, max_attempts): ...
```

参数越传越多，而且没有任何东西保证调用方传的 `history` 和 `target` 属于同一局。

**类把一组总是一起出现的数据，和操作这些数据的函数，放在一起。** 一个 `GuessGame` 对象就是一局游戏：它自己知道答案、上限和历史，`game.remaining` 不用再传参数。

其实你已经写过类了。第 2.2 章的 `class GuessError(ValueError):` 就是一个类，用的是这一章第 8 节的继承。

# 一、概念与原理

## 1. 类和对象

```python
class GuessGame:
    def __init__(self, target: int, max_attempts: int = 7) -> None:
        self.target = target
        self.max_attempts = max_attempts
        self.history: list[int] = []

    def guess(self, n: int) -> str:
        self.history.append(n)
        if n < self.target:
            return "小了"
        if n > self.target:
            return "大了"
        return "正确"


game = GuessGame(42)          # 创建一个对象
game.guess(50)                # → '大了'
```

| 术语 | 是什么 | 例子 |
|---|---|---|
| **类**（class） | 模板，描述「这一类东西有什么数据、能做什么」 | `GuessGame` |
| **对象 / 实例**（object / instance） | 按模板造出来的一个具体的东西 | `game` |
| **属性**（attribute） | 对象身上的数据 | `game.target`、`game.history` |
| **方法**（method） | 定义在类里的函数 | `game.guess(50)` |

`GuessGame(42)` 这一句做了两件事：先造一个空对象，再调用 `__init__(那个对象, 42)` 给它填属性。**`__init__` 负责初始化，不负责创建**，所以它不写 `return`。

对象的属性就存在一个字典里（下面是配套代码里的完整版 `GuessGame`，猜过 50 和 30 之后）：

```text
   vars(game)  → {'target': 42, 'max_attempts': 7, 'low': 1, 'high': 100, 'history': [50, 30]}
```

## 2. `self` 就是第一个参数

```text
1. self 就是第一个参数
   game.guess(50)                           → '大了'
   GuessGame.guess(game, 30)                → '小了'
   game.history                             → [50, 30]
   type(game.guess).__name__                → 'method'
   type(GuessGame.guess).__name__           → 'function'
```

**`game.guess(50)` 就是 `GuessGame.guess(game, 50)` 的简写。** 两种写法都往同一个 `history` 里记了数。

- 通过类拿到的 `GuessGame.guess` 是一个普通**函数**，有两个参数 `self` 和 `n`
- 通过对象拿到的 `game.guess` 是一个**绑定方法**：Python 已经把 `game` 塞进了第一个参数，你只需要再给 `n`

所以 `self` 不是关键字，只是第一个参数的名字（约定叫 `self`，PEP 8 要求这么叫）。它指向「调用这个方法的那个对象」，方法通过它读写对象的属性。

### ⚠️ 漏写 `self`

```python
class Forgot:
    def guess(n):              # 漏了 self
        return n

Forgot().guess(5)
```

```text
TypeError: Forgot.guess() takes 1 positional argument but 2 were given
```

你明明只传了 1 个参数，报错说给了 2 个。按上面的规则展开就清楚了：`Forgot().guess(5)` 等于 `Forgot.guess(对象, 5)`，对象本身算第 1 个。

**看到「多给了一个参数」的报错，先检查方法有没有写 `self`。** 这个错误工具都能抓：ruff 的 `N805`（First argument of a method should be named `self`）和 mypy（`"self" parameter missing for a non-static method`）。

反过来，通过类调用时忘了传对象：

```text
   GuessGame.guess(50)                      → TypeError: GuessGame.guess() missing 1 required positional argument: 'n'
```

`50` 被当成了 `self`，`n` 没人给。

## 3. 第一个完整的类

配套代码里的 `GuessGame` 比上面多了几样东西：

```python
class GameOverError(Exception):
    """游戏已经结束，不能再猜。"""


class GuessGame:
    def __init__(self, target: int, max_attempts: int = 7, low: int = 1, high: int = 100) -> None:
        self.target = target
        self.max_attempts = max_attempts
        self.low = low
        self.high = high
        self.history: list[int] = []

    def guess(self, n: int) -> str:
        if self.is_over:
            raise GameOverError(f"这局已经结束了（{self!r}）")
        self.history.append(n)
        ...

    @property
    def remaining(self) -> int:
        return self.max_attempts - len(self.history)

    @property
    def won(self) -> bool:
        return bool(self.history) and self.history[-1] == self.target

    @property
    def is_over(self) -> bool:
        return self.won or self.remaining <= 0

    def __repr__(self) -> str:
        return (f"GuessGame(range={self.low}-{self.high}, "
                f"attempts={len(self.history)}/{self.max_attempts}, won={self.won})")
```

**只存必要的数据，能算出来的就算。** 已用次数是 `len(self.history)`，剩余次数是上限减已用。如果再单独存一个 `self.attempts`，每次 `append` 都要记得同步加一，忘了就不一致。

**结束以后再猜，抛异常。** `guess` 第一行检查状态，第 2.2 章的原则：调用方用错了，就明确告诉它。

## 4. ⚠️ 实例属性和类属性

属性可以写在两个地方：

```python
class Shared:
    history: list[int] = []         # 写在类里：类属性，属于类本身

    def add(self, n: int) -> None:
        self.history.append(n)
```

```python
class GuessGame:
    def __init__(self, ...) -> None:
        self.history: list[int] = []   # 写在 __init__ 里：实例属性，每个对象一份
```

读 `obj.history` 时，Python **先在对象自己身上找，找不到再去类上找**。`Shared` 的对象自己身上没有 `history`，读到的都是类上那一个列表：

```text
3. 写在类里的属性
   Shared：a.add(1) 之后 b.history             → [1]
```

`a` 加的数出现在了 `b` 身上。**所有 `Shared` 对象共用同一个列表。**

### 整数写在类里，为什么「看起来」没事

```python
class Counter:
    count = 0

    def bump(self) -> None:
        self.count += 1
```

```text
   Counter：(c1.count, c2.count, 类的)         → (1, 0, 0)
```

`c1` 加了一，`c2` 和类本身都还是 0，好像没共享。原因是 `self.count += 1` 展开后是 `self.count = self.count + 1`：

1. **读** `self.count`：对象身上没有，读到类上的 `0`
2. **写** `self.count = 1`：赋值永远写在对象自己身上，于是 `c1` 有了自己的 `count`

`list.append` 只读不写（它改的是那个列表对象，没有给 `self.history` 赋值），所以一直改的是类上那一个。**区别不在整数和列表，而在「赋值」和「原地修改」。** 把第 1.7 章的「赋值是引用」和「原地修改」放在一起，就是这里的规则。

### 类属性比对象活得久

写这门课的测试时，这个坑真的踩到了一次。示例里有个函数演示上面的 `Shared`：

```python
def shared_after_other_add() -> list[int]:
    a, b = Shared(), Shared()
    a.add(1)
    return b.history
```

练习 1 的标准答案是 `[1]`。但测试里这个函数被调用了三次，第三次返回的是 **`[1, 1, 1]`**。每次调用都创建新的 `a` 和 `b`，函数返回后它们就没了，**可它们 `append` 进去的数留在类属性上**。类属性和类活得一样久，也就是整个进程那么久。

配套代码最后的修法是在函数第一行加 `Shared.history = []`，测试 `test_ch03_02_class_attribute_outlives_objects` 专门验证了这个现象。

> 这和第 1.6 章的「可变默认值」是同一个根因：
> **一个可变对象只在定义时创建一次，之后所有使用者共享它。**
> 默认值是在 `def` 执行时创建的，类属性是在 `class` 执行时创建的。

**规则：可变的东西（列表、字典、集合）一律在 `__init__` 里创建。类属性只放不会被修改的常量。**

ruff 有一条规则 `RUF012`（Mutable default value for class attribute）专门查这个，实测能抓到 `Shared`。这门课的规则集没有启用 `RUF`，可以自己加上。

## 5. ⚠️ 属性名拼错

```python
class Typo:
    def __init__(self) -> None:
        self.attempts = 0

    def bump(self) -> None:
        self.atempts = self.attempts + 1     # 少了一个 t
```

```text
4. 拼错属性名
   Typo：bump 之后 attempts                    → 0
```

`bump` 之后 `attempts` 还是 0，没有任何报错。看一眼对象的属性字典就明白了：

```text
   vars(t)  → {'attempts': 0, 'atempts': 1}
```

**给一个不存在的属性赋值，不是错误，而是新建一个属性。** Python 的对象默认可以随时加属性。

**mypy 在这里也不报错。** 实测 mypy 把方法里的 `self.atempts = ...` 当成了「声明一个新属性」。它只在类外面赋值时才报：

```python
def outside(t: Typo) -> None:
    t.atempts = 1
```

```text
error: "Typo" has no attribute "atempts"; maybe "attempts"?  [attr-defined]
```

### 用 `slots` 让它报错

```python
@dataclass(slots=True)
class Slotted:
    attempts: int = 0

    def bump(self) -> None:
        self.atempts = self.attempts + 1
```

```text
   Slotted：bump 之后 attempts                 → AttributeError: 'Slotted' object has no attribute 'atempts' and no __dict__ for setting new attributes
```

`slots` 让对象只能有声明过的属性，拼错的名字在**运行时**立刻报错。mypy 也能在**写代码时**发现它：

```text
error: Trying to assign name "atempts" that is not in "__slots__" of type "Slotted"  [misc]
```

| | 普通类 | `slots=True` |
|---|---|---|
| 方法里拼错属性名，运行时 | **不报错**，新建一个属性 | `AttributeError` |
| 方法里拼错属性名，mypy | **不报错** | 报错 |
| 类外面拼错属性名，mypy | 报错 | 报错 |
| 运行中动态加属性 | 可以 | 不可以 |

> 报错的措辞与版本有关：3.13 是 `... has no attribute 'atempts' and no __dict__ for setting new attributes`，
> 3.11 只有前半句 `'Slotted' object has no attribute 'atempts'`。

`@dataclass(slots=True)` 需要 Python 3.10+，正好是这门课的最低版本。普通类也可以手写 `__slots__ = ("attempts",)`，效果一样。

## 6. `@property` 和 `@classmethod`

### `@property`：像属性一样读的方法

```python
    @property
    def remaining(self) -> int:
        return self.max_attempts - len(self.history)
```

```text
   game.remaining                           → 5
```

读的时候**不加括号**，看起来像属性，实际上每次读都重新算一遍，所以永远和 `history` 一致。

| 写法 | 结果 |
|---|---|
| `game.remaining` | `5` |
| `game.remaining()` | `TypeError: 'int' object is not callable`（`game.remaining` 已经是 `5` 了，再加括号就是 `5()`） |
| `game.remaining = 3` | `AttributeError: property 'remaining' of 'GuessGame' object has no setter` |

第三行是好事：剩余次数是算出来的，不该被直接改。**只读是 `property` 默认的行为。**

**什么时候用 property**：值可以由其他属性算出来、计算很便宜、读的人不需要关心它是存的还是算的。计算很慢（要读文件、发请求）的话，写成普通方法，让括号提醒调用方「这里有代价」。

### `@classmethod`：另一种构造方式

```python
    @classmethod
    def with_random_target(cls, seed: int | None = None, **options: int) -> GuessGame:
        low, high = options.get("low", 1), options.get("high", 100)
        return cls(random.Random(seed).randint(low, high), **options)
```

```python
game = GuessGame.with_random_target()          # 随机出题
game = GuessGame.with_random_target(seed=42)   # 测试时固定答案（第 1.4 章）
```

普通方法的第一个参数是对象（`self`），classmethod 的第一个参数是**类本身**（`cls`）。用 `cls(...)` 而不是写死 `GuessGame(...)`，子类调用时造出来的就是子类：实测 `HintGame.with_random_target(seed=1)` 返回的是 `HintGame` 对象（练习 3）。

还有一种 `@staticmethod`，既不要对象也不要类。它和模块级的普通函数没有区别，**这门课不用它**，写成普通函数就行。

## 7. `__repr__`、`==`、哈希与 `dataclass`

### 普通类的默认行为

```python
class Plain:
    def __init__(self, x: int, y: int) -> None:
        self.x = x
        self.y = y
```

```text
5. 相等、打印、哈希
   Plain(1, 2) == Plain(1, 2)               → False
   Plain(1, 2)                              → <__main__.Plain object at 0x00000184D9717C50>
   len({Plain(1, 2), Plain(1, 2)})          → 2
```

| | 默认行为 | 后果 |
|---|---|---|
| `==` | 等同于 `is`，比的是「是不是同一个对象」 | 两个内容一样的对象**不相等** |
| 打印 | 类名加内存地址 | 日志和报错里看不出内容 |
| 哈希 | 按对象身份 | 放进集合不会去重 |

`GuessGame` 自己写了 `__repr__`，所以打印出来是 `GuessGame(range=1-100, attempts=2/7, won=False)`。注意它**故意不显示答案**：对象会出现在日志和报错信息里（上面 `GameOverError` 的消息就用了 `{self!r}`），答案不该跟着泄露。

### `dataclass`：只装数据的类

很多类主要是用来装数据的。手写 `__init__`、`__repr__`、`__eq__` 很啰嗦，标准库的 `dataclass` 根据类型注解自动生成：

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int
```

```text
   Point(1, 2) == Point(1, 2)               → True
   Point(1, 2)                              → Point(x=1, y=2)
   Point('1', '2')                          → Point(x='1', y='2')
```

前两行是自动生成的 `__eq__`（按字段比较）和 `__repr__`。第三行说明**类型注解不做运行时检查**，和第 1.6 章讲函数注解时一样，要靠 mypy。

可变默认值，dataclass 直接拦住：

```python
@dataclass
class Settings:
    players: list[str] = []
```

```text
ValueError: mutable default <class 'list'> for field players is not allowed: use default_factory
```

正确写法是 `players: list[str] = field(default_factory=list)`，每个对象创建时调用一次 `list()`，得到各自的新列表。**普通类不会拦你（第 4 节的 `Shared`），dataclass 会。**

### ⚠️ `{Point(1, 2)}` 报错

```text
   {Point(1, 2)}                            → TypeError: unhashable type: 'Point'
   len({FrozenPoint(1, 2), FrozenPoint(1, 2)}) → 1
```

普通类能放进集合，dataclass 反而不能。原因是第 1.8 章的规则：**能放进集合的对象，哈希值在它的一生里不能变；相等的对象，哈希值必须相同。**

- dataclass 按字段比较相等，那哈希也只能按字段算
- 但普通 dataclass 的字段可以改。放进集合以后改了字段，哈希值就变了，集合就找不到它了
- 所以 dataclass 干脆把 `__hash__` 设成 `None`，不让你放

加上 `frozen=True`，字段不能再改，哈希就安全了：

```python
@dataclass(frozen=True)
class FrozenPoint:
    x: int
    y: int
```

改字段会报 `FrozenInstanceError: cannot assign to field 'x'`。两个内容相同的 `FrozenPoint` 放进集合只剩一个，这正是练习 4 去重要用的。

| | 普通类 | `@dataclass` | `@dataclass(frozen=True)` |
|---|---|---|---|
| `==` | 比身份 | **比字段** | 比字段 |
| `repr` | 内存地址 | **`Point(x=1, y=2)`** | 同左 |
| 能放进集合 | 能（按身份） | **不能** | **能（按字段）** |
| 字段能改 | 能 | 能 | **不能** |

## 8. 继承与 `super()`

```python
class HintGame(GuessGame):          # HintGame 继承 GuessGame
    ...
```

**子类自动拥有父类的全部属性和方法**，可以添加新的，也可以重写（同名方法覆盖父类的）。查找顺序记在 `__mro__` 里：

```text
   [c.__name__ for c in WithSuper.__mro__]  → ['WithSuper', 'Base', 'object']
```

和第 2.2 章异常的 `__mro__` 是同一个东西。所有类最终都继承自 `object`。

重写时如果还需要父类的逻辑，用 `super()` 调用它：

```python
class WithSuper(Base):
    def __init__(self, target: int, hint: bool) -> None:
        super().__init__(target)         # 先让父类把它的属性设好
        self.hint = hint                 # 再设自己的
```

### ⚠️ 忘了 `super().__init__()`

```python
class Base:
    def __init__(self, target: int) -> None:
        self.target = target
        self.history: list[int] = []

    def guess(self, n: int) -> str:
        self.history.append(n)
        return "记下了"


class NoSuper(Base):
    def __init__(self, target: int, hint: bool) -> None:
        self.hint = hint                 # 没调 super().__init__
```

```text
6. 继承
   NoSuper(42, True).hint                   → True
   NoSuper(42, True).guess(1)               → AttributeError: 'NoSuper' object has no attribute 'history'
   WithSuper(42, True).guess(1)             → '记下了'
```

**创建对象时不报错，调用方法时才报。** 子类重写了 `__init__`，父类的 `__init__` 就不会自动执行，`history` 从来没被创建。报错出现在 `guess` 里，离真正的原因（`__init__` 漏了一行）很远。

**mypy 也不报。** `history` 在 `Base` 里声明过，mypy 认为子类对象当然有它。配套测试 `test_ch03_02_mypy_misses_typo_but_not_slots` 验证了这一点：同一个文件里拼错属性名、漏调 `super().__init__()`、用了 slots 的拼错，mypy 只报了最后一个。

**规则：子类写了 `__init__`，第一行就写 `super().__init__(...)`。**

### `isinstance` 和 `type`

```text
   isinstance(WithSuper(42, True), Base)    → True
   type(WithSuper(42, True)) is Base        → False
```

`isinstance` 把子类也算进去，`type(...) is` 只认那一个类。**判断类型用 `isinstance`**，第 2.2 章 `except` 按继承关系匹配也是同样的规则。

### 什么时候用继承

子类和父类是「**是一种**」的关系时：`HintGame` 是一种 `GuessGame`，`GuessRangeError` 是一种 `GuessError`。只是想复用几个函数的话，不要为此继承。

## 9. 什么时候别用类

类不是越多越好。按这张表判断：

| 情况 | 用什么 | 课程里的例子 |
|---|---|---|
| 没有状态，输入决定输出 | **普通函数** | `parse_guess`、`check_num` |
| 只是把几个值装在一起 | **`dataclass`**（要放进集合就 `frozen=True`） | 练习 4 的 `GameRecord` |
| 有状态，而且**多个操作**围绕这份状态 | **类** | `GuessGame`、第 7.1 章的 `APIClient` |
| 要被 `except` 按类型捕获 | **异常类**（只能是类） | `GuessError`、`GameOverError` |

两个信号说明类写多了：

- **类里只有 `__init__` 和一个方法。** 那就是一个函数，`__init__` 的参数挪到函数参数里
- **方法里从来不用 `self`。** 那它不属于这个类，写成模块级函数

`parse_guess` 就是第二种：它不需要任何状态，所以示例里它是函数，不是 `GuessGame` 的方法。

## 10. 类版本的猜数字

规则全部进了 `GuessGame`，`play` 只剩下问和说：

```python
def play(game: GuessGame, ask=input, say=print) -> GuessGame:
    say(f"我想好了一个 {game.low}-{game.high} 之间的数，你有 {game.max_attempts} 次机会。")
    while not game.is_over:
        raw = ask(f"[{len(game.history) + 1}/{game.max_attempts}] 你猜（q 退出）： ")
        if raw.strip() == "q":
            say("不玩了。")
            break
        try:
            n = parse_guess(raw, game.low, game.high)
        except GuessError as e:
            say(f"   {e}，这次不算")
            continue
        say(f"   {n:>3} → {game.guess(n)}")
    if game.won:
        say(f"   用了 {len(game.history)} 次。")
    elif game.remaining == 0:
        say(f"   机会用完了，答案是 {game.target}。")
    return game
```


| | 1.6 的函数版 | 3.2 的类版 |

| 「结束了吗」 | 循环条件里手写 | `game.is_over` |

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | 方法漏写 `self` | `takes 1 positional argument but 2 were given` | ruff `N805`、mypy 都能抓 |
| **2** | **可变对象写成类属性** | 所有对象共享，**跨调用累积**，不报错 | 可变的东西在 `__init__` 里创建；ruff `RUF012` |
| **3** | **方法里拼错属性名** | 新建了一个属性，原属性没变；**Python 和 mypy 都不报错** | `@dataclass(slots=True)` 或 `__slots__` |
| **4** | **子类 `__init__` 没调 `super().__init__()`** | 创建时不报错，调用方法时 `AttributeError`；mypy 不报错 | 子类 `__init__` 第一行写 `super().__init__(...)` |
| **5** | property 加了括号 | `'int' object is not callable` | property 读的时候不加括号 |
| **6** | **以为两个内容相同的对象 `==`** | 普通类比的是身份，`False` | 需要按内容比较用 dataclass |
| **7** | **普通 dataclass 放进集合** | `TypeError: unhashable type` | `frozen=True` |
| **8** | dataclass 字段默认值写 `[]` | `ValueError: mutable default ... use default_factory` | `field(default_factory=list)` |
| **9** | 存了能算出来的值 | 忘了同步就不一致 | 用 property 现算 |
| **10** | `__repr__` 打印了敏感数据 | 答案、密码出现在日志里 | `__repr__` 只放排查需要的信息 |
| **11** | 什么都写成类 | 只有一个方法的类、不用 `self` 的方法 | 第 9 节的表 |

**第 2、3、4 条最危险**，都不报错。第 3、4 条连 mypy 都发现不了，第 2 条要加 ruff 的额外规则才能发现。

# 四、本章小结

```text
类 = 数据 + 操作数据的函数
   ├─ __init__ 初始化属性（可变的东西在这里创建）
   └─ obj.method(x) 就是 Class.method(obj, x)，self 是第一个参数
        ↓
⚠️ 属性查找：先对象，后类
   ├─ 列表写在类里 → 所有对象共享，而且比对象活得久
   └─ 整数 += 看起来没事 → 赋值写到了对象上
        ↓
⚠️ 拼错属性名 = 新建属性，Python 和 mypy 都不报 → slots
        ↓
@property 现算的只读属性；@classmethod 另一种构造方式（用 cls）
        ↓
dataclass：自动 __init__ / __repr__ / __eq__
   └─ ⚠️ 不能放进集合 → frozen=True
        ↓
继承：子类是一种父类；super() 调父类
   └─ ⚠️ 漏了 super().__init__() → 很久以后才 AttributeError
        ↓
没状态用函数，只装数据用 dataclass，有状态有多个操作才用类
```

一句话总结：**这一章的四个坑（类属性共享、拼错属性名、漏调 `super().__init__()`、dataclass 不能哈希）里，只有最后一个会立刻报错。**

<details>
<summary>参考答案</summary>

1. 类是模板，对象是按模板造出来的具体实例。`GuessGame(42)` 先创建一个空对象，再调用 `__init__(那个对象, 42)` 给它设置属性。
2. `__init__` 只负责**初始化**一个已经创建好的对象，不负责创建它。返回对象的是 `GuessGame(42)` 这个调用本身。
3. **前者是后者的简写**，完全等价。`type(game.guess)` 是 `method`（绑定方法，已经把 `game` 塞进了第一个参数），`type(GuessGame.guess)` 是 `function`（普通函数，两个参数都要自己给）。
4. 是**对象本身**。`obj.guess(5)` 等于 `Class.guess(obj, 5)`，对象算第 1 个参数，`5` 是第 2 个，而方法只声明了 1 个参数。
5. **先在对象自己身上找，找不到再去类上找**（再找不到就按 `__mro__` 去父类找）。
6. 两个对象共用同一个列表，`a.add(1)` 之后 `b.history` 也是 `[1]`。因为对象身上没有 `history`，读到的都是类上那一个，`append` 修改的就是它。
7. **没变。** `self.count += 1` 等于 `self.count = self.count + 1`，赋值永远写在对象自己身上，于是这个对象有了自己的 `count`，类上的和别的对象都不受影响。区别在于「赋值」和「原地修改」：`append` 只修改不赋值。
8. 类属性属于类本身，类存在多久它就存在多久（通常是整个进程）。测试里 `shared_after_other_add()` 被调用了三次，每次的 `a`、`b` 用完就没了，但它们 `append` 的数留在类属性上，第三次返回 `[1, 1, 1]`。
9. **是同一个根因**：一个可变对象只在定义时创建一次，之后所有使用者共享它。默认值在 `def` 执行时创建，类属性在 `class` 执行时创建。
10. **新建了一个叫 `atempts` 的属性**，`attempts` 不变，不报错。**mypy 也不报**，它把方法里的赋值当成了声明新属性（类外面赋值它才报）。用 `@dataclass(slots=True)` 或 `__slots__`，运行时会 `AttributeError`，mypy 也会报 `not in "__slots__"`。
11. `game.remaining` 得到剩余次数（整数）；`game.remaining()` 报 `TypeError: 'int' object is not callable`；`game.remaining = 3` 报 `AttributeError: property 'remaining' of 'GuessGame' object has no setter`。
12. 是**类本身**（约定叫 `cls`）。写 `cls(...)` 的话，子类调用这个方法时造出来的就是子类对象；写死 `GuessGame(...)` 的话，子类调用也只能得到父类对象。
13. **`False`。** 普通类没有定义 `__eq__`，默认的 `==` 等同于 `is`，比的是「是不是同一个对象」。
14. `__init__`、`__repr__`、`__eq__`（还有一些不常用的）。**不检查类型**，`Point('1', '2')` 照样能创建，类型要靠 mypy 检查。
15. dataclass 按字段判断相等，哈希也只能按字段算；但普通 dataclass 的字段可以修改，放进集合后改字段会让哈希值变化，所以 dataclass 把 `__hash__` 设成了 `None`。改成 `@dataclass(frozen=True)`，字段不可修改，就可以哈希了。
16. **创建对象时不报错**，等到调用某个用到父类属性的方法时才报 `AttributeError: '...' object has no attribute 'history'`。父类的 `__init__` 没执行，那些属性从来没被创建。mypy 也发现不了。
17. `isinstance` 把子类也算进去（`WithSuper` 的对象是 `Base` 的实例）；`type(x) is Base` 只认 `Base` 本身。判断类型一般用 `isinstance`。
18. 没有状态、输入决定输出时用普通函数；只是装数据时用 dataclass。两个信号：**类里只有 `__init__` 和一个方法**（那其实是一个函数）；**方法里从来不用 `self`**（它不属于这个类）。
