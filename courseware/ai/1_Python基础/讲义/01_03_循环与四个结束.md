这一章的核心实验只有三条命令，**务必亲手跑一遍**。

# 一、概念与原理

## 1. `while` 循环

```python
while 条件:
    # 条件为真时反复执行
```

先判断条件，为真就执行一次循环体，然后回到开头**再判断一次**，直到条件为假。

```python
count = 3
while count > 0:
    print(count)
    count -= 1        # 等价于 count = count - 1
print("发射")
```

```text
3
2
1
发射
```

**循环体里必须有东西让条件最终变假**，否则就是死循环。这里是 `count -= 1`。

## 2. `while True` + `break`

最常见的写法其实是这样：

```python
while True:
    raw = input("输入（q 退出）： ")
    if raw == "q":
        break
    print("你输入了", raw)
```

`while True` 是无限循环，靠循环体里的 `break` 退出。

**为什么不把退出条件写在 `while` 后面？** 因为**条件要等循环体执行一部分才能判断**——这里得先读到输入，才知道是不是 `q`。硬写在 `while` 后面，就得在循环前先读一次、循环末尾再读一次，同一行 `input()` 写两遍。

`while True` + `break` 把「什么时候退出」放在它真正能被判断的位置。

> 学习记录里写过 `while 1:`。它能工作（`1` 是真值），但应该写 `while True`——
> Python 有真正的布尔类型，用它表达「无限循环」的意图更清楚。

## 3. `for` 循环与 `range()`

**次数已知**的循环用 `for` 更直接：

```python
for attempt in range(5):
    print(f"第 {attempt + 1} 次")
```

`range()` 有三种写法：

```text
2. range() 的三种写法
   list(range(5))        → [0, 1, 2, 3, 4]
   list(range(1, 6))     → [1, 2, 3, 4, 5]      ← 不含结束值
   list(range(0, 10, 3)) → [0, 3, 6, 9]
   list(range(5, 0, -1)) → [5, 4, 3, 2, 1]
```

| 写法 | 含义 |
|---|---|
| `range(n)` | 0 到 n-1，共 n 个 |
| `range(a, b)` | a 到 b-1，**不含 b** |
| `range(a, b, step)` | 步长为 step，可以是负数 |

**「包含开头、不包含结尾」是 Python 的通用约定**，切片（第 1.7 章）也是这样。好处是 `range(a, b)` 的长度正好是 `b - a`，相邻的区间 `range(0, 5)` 和 `range(5, 10)` 首尾相接、不重不漏。

`for` 不只能遍历 `range`，任何「可以逐个取出元素」的东西都行：

```python
for ch in "abc":           # 字符串：逐个字符
    print(ch)
for raw in ["50", "42"]:   # 列表：逐个元素（第 1.7 章细讲）
    print(raw)
```

## 4. `while` 还是 `for`

```text
4. 什么时候用 while，什么时候用 for
   次数已知（猜 5 次）       → for attempt in range(5)
   次数未知（直到猜中为止）  → while True + break
   例：从 27 开始做 3n+1 变换，111 步后到达 1 —— 事先不知道要几步
```

| 场景 | 用 |
|---|---|
| 遍历一组已有的东西 | `for x in 容器` |
| 重复固定次数 | `for i in range(n)` |
| 重复到某个条件满足为止，次数事先不知道 | `while` |

能用 `for` 就用 `for`：它不需要手动维护计数器，**不可能因为忘了 `count += 1` 而死循环**。

## 5. 四个「结束」

这是本章的核心。四个关键字都会打断当前的执行流程，**作用范围层层扩大**：

| 关键字 | 结束什么 | 之后执行哪里 |
|---|---|---|
| `continue` | **本轮**循环 | 回到循环开头，继续下一轮 |
| `break` | **整个**循环 | 循环后面的代码 |
| `return` | **整个函数** | 调用这个函数的地方 |
| `sys.exit()` | **整个程序** | 什么都不执行了 |

### 核心实验：同一个循环，三种打断方式

配套示例里有这样一个循环：循环 3 次，第 2 次时打断；**循环结束后有一行「保存成绩」**。

```python
for attempt in range(1, 4):
    print(f"第 {attempt} 次尝试")
    if attempt == 2:
        # 这里分别换成 break / continue / sys.exit()
        ...
    print(f"   第 {attempt} 次的循环体后半段")

print("循环结束后：保存成绩、打印统计")
```

**请依次运行这三条命令，每条之后查看一次退出码：**

```powershell
python -m m01_basics.ch01_03_example ending break
echo "退出码: $LASTEXITCODE"            # PowerShell；macOS / Linux 用 echo "退出码: $?"

python -m m01_basics.ch01_03_example ending continue
echo "退出码: $LASTEXITCODE"

python -m m01_basics.ch01_03_example ending exit
echo "退出码: $LASTEXITCODE"
```

**退出码**是程序结束时交给操作系统的一个整数，下面第 6 节细讲。现在只需要知道 0 表示「成功」。

**`break`：**

```text
第 1 次尝试
   第 1 次的循环体后半段
第 2 次尝试
循环结束后：保存成绩、打印统计
退出码: 0
```

第 2 次的后半段没执行，第 3 次没开始，**循环后面的代码执行了**。

**`continue`：**

```text
第 1 次尝试
   第 1 次的循环体后半段
第 2 次尝试
第 3 次尝试
   第 3 次的循环体后半段
循环结束后：保存成绩、打印统计
退出码: 0
```

只跳过了第 2 次的后半段，第 3 次照常进行，**循环后面的代码执行了**。

**`sys.exit()`：**

```text
第 1 次尝试
   第 1 次的循环体后半段
第 2 次尝试
退出码: 0
```

**「保存成绩」那一行没有打印。** 而且注意最后一行：**退出码是 0**。

### ⚠️ 为什么 `sys.exit()` 危险：它不报错

退出码 0 在操作系统看来就是「成功」。所以：

- 在终端里跑，看不出任何异常
- 被脚本或 CI 调用，判定为成功
- 本该保存的成绩没保存、本该打印的统计没打印——**没有任何信号**

学习记录里的第一版循环就是这样写的：

```python
while 1:
    input_num = int(input("请输入数字"))
    if input_num > 10:
        print("输入的数字太大了")
    elif input_num < 10:
        print("输入的数字太小了")
    else:
        exit(0)        # ← 想结束循环，结束的却是整个程序
```

**在这一版里 `exit(0)` 和 `break` 表现完全一样**，因为猜中之后本来就没有后续代码了。所以这个问题当时没有暴露。

但一旦循环后面加了「再来一局吗」「保存本局成绩」——这正是后面几章要做的——这些代码会被静默跳过。而且很难调试：**程序看起来正常结束了。**

> **规律：想结束一个循环用 `break`，想结束一个函数用 `return`，
> 想结束一个程序才用 `sys.exit()`——而且只在程序入口处用。**

## 6. `sys.exit()` 的本质：一个异常

```text
1. exit() 的本质
   sys.exit() 抛出了 SystemExit，code=None
   SystemExit 的继承链：['SystemExit', 'BaseException', 'object']
   ↑ 它继承的是 BaseException，不是 Exception
     所以 except Exception 接不住它 —— 这是故意设计的
```

`sys.exit()` 并不是「立刻杀掉进程」，它做的是 **`raise SystemExit`**。这个异常一路往上冒，没人接住的话，解释器就退出。

两个推论：

**一、`except Exception` 接不住它。** `SystemExit` 继承的是 `BaseException`，而 `Exception` 只是 `BaseException` 的一个子类。

```python
try:
    play_buggy(["42"], 42)       # 里面调用了 sys.exit()
except Exception:
    print("出错了")              # 不会执行，程序照样退出
```

这是 Python 故意的设计：让「我要退出」不会被一个宽泛的 `except` 意外拦住。同样继承 `BaseException` 的还有 `KeyboardInterrupt`（按 Ctrl+C 时抛出）。

**二、`finally` 会执行。** 因为它是异常，`try / finally` 里的清理代码照样会跑。异常处理是第 1.5 章的内容，这里先记住结论。

**推论：一个函数里藏着 `sys.exit()`，调用方几乎没有办法优雅地处理它。** 这就是为什么库函数里永远不该出现它。

### 退出码

| 写法 | 退出码 | 说明 |
|---|---|---|
| `sys.exit()` | `0` | 不传参数 = 成功 |
| `sys.exit(0)` | `0` | 显式表示成功 |
| `sys.exit(3)` | `3` | 非零整数 = 失败，数字由你定义含义 |
| `sys.exit("出错了")` | `1` | 传字符串：打印到 stderr，退出码为 1 |

```text
$ python -c "import sys; sys.exit('出错了')"
出错了
退出码: 1
```

**约定：0 表示成功，非 0 表示失败。** 脚本、CI、其他程序都靠这个判断你的程序跑没跑成功。

### `exit()` 和 `sys.exit()` 不是一回事

你可能见过直接写 `exit()` 的代码。它们的区别：

| | `exit()` | `sys.exit()` |
|---|---|---|
| 来源 | `site` 模块在启动时塞进来的 | 标准库 `sys` 模块 |
| 类型 | `_sitebuiltins.Quitter` | 内置函数 |
| 设计用途 | **交互式解释器**里方便退出 | **程序**里退出 |
| 一定存在吗 | **不一定** | 一定 |

验证「不一定存在」：

```powershell
python -S -c "exit()"
```

```text
NameError: name 'exit' is not defined
```

`-S` 表示不加载 `site` 模块（某些嵌入式环境、打包工具会这样运行 Python），这时 `exit` 根本不存在。

> **程序里一律用 `sys.exit()`。** 本章后面所有代码都这样写。

## 7. 嵌套循环里的 `break`

```text
3. 嵌套循环里的 break 只跳出最内层
   outer=1 inner=1
   outer=2 inner=1
   outer=3 inner=1
   ↑ 外层循环跑满了 3 次，break 只结束了内层
```

```python
for outer in range(1, 4):
    for inner in range(1, 4):
        if inner == 2:
            break              # 只结束内层循环
        print(f"outer={outer} inner={inner}")
```

**`break` 只跳出它所在的那一层循环。** 想一次跳出多层，最干净的办法是把这段循环抽成函数，然后用 `return`——这也是 `return` 比 `break` 作用范围大的一个实际用处。

## 8. 循环的 `else` 分支

这是 Python 一个少见但有用的语法：

```python
while attempts < MAX_ATTEMPTS:
    ...
    if result == "正确":
        break
else:
    print("次数用完了")       # 循环「正常结束」时执行；被 break 打断时不执行
```

| 循环怎么结束的 | `else` 执行吗 |
|---|---|
| 条件变假（`while`）/ 遍历完（`for`） | **执行** |
| 被 `break` 打断 | **不执行** |

它正好表达了「找遍了也没找到」这种语义。上面的例子里：猜中了是 `break` 出来的，不会打印「次数用完」；次数用完是条件变假，才会打印。

> 这个语法很多人不认识，读代码时容易误以为 `else` 属于循环里的某个 `if`。
> **团队里没人用过的话，宁可多写一个标志变量**，可读性比少两行代码重要。

## 9. 计数器要放在循环外面

```python
# ✗ 每一轮都重置成 0
for raw in inputs:
    attempts = 0
    attempts += 1          # 永远是 1

# ✓ 循环前初始化一次
attempts = 0
for raw in inputs:
    attempts += 1
```

**需要跨轮累积的东西（计数器、总和、历史记录）都放在循环外面初始化。** 这是循环里最常见的错误之一，而且不报错——只是数字永远不对。

## 10. 第三版猜数字

把三章的东西拼起来：

```python
MAX_ATTEMPTS = 5

attempts = 0
while attempts < MAX_ATTEMPTS:
    raw = input(f"第 {attempts + 1}/{MAX_ATTEMPTS} 次，猜 1-100（q 退出）： ")

    if raw.strip().lower() in ("q", "quit"):      # 1.1 练习 3
        print("你选择了退出")
        break

    if not looks_like_int(raw):                    # 1.2 练习 3
        print(f"   '{raw}' 不是整数，这次不算")
        continue

    attempts += 1
    result = check_num(int(raw), TARGET)           # 1.1 练习 2
    print(f"   {result}")
    if result == "正确":
        print(f"   用了 {attempts} 次")
        break
else:
    print(f"次数用完了，答案是 {TARGET}")

print("本局结束")
```


**四种「结束」各司其职**：

| 情况 | 用的是 | 「本局结束」会打印吗 |
|---|---|---|
| 输入不是整数 | `continue`（跳过本轮，不计次） | —— |

| 猜中 | `break` | ✓ |
| 次数用完 | 条件变假 → `else` | ✓ |

**没有一处用 `sys.exit()`，所以「本局结束」在任何情况下都会执行。** 下一章开始往这里加「保存成绩」时，不用担心它被跳过。

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **用 `exit()` 结束循环** | 循环后的代码被跳过，**退出码 0**，看起来正常 | 结束循环用 `break` |
| **2** | **函数里调用 `sys.exit()`** | 调用方 `except Exception` 接不住，程序直接退出 | 函数里用 `return`，`sys.exit()` 只在入口用 |
| **3** | **程序里写 `exit()` 而不是 `sys.exit()`** | `python -S` 等环境下 `NameError` | 一律 `import sys` 然后 `sys.exit()` |
| **4** | **计数器在循环里初始化** | 每轮被重置，计数永远是 1 | 跨轮累积的变量放循环外 |
| **5** | **「次数用完」判断在「猜中」之前** | 最后一次机会猜中被判成次数用完 | 先判断成功，再判断失败 |
| **6** | **以为 `break` 能跳出多层循环** | 外层循环继续跑 | 抽成函数用 `return` |
| **7** | **`while` 循环体里没有改变条件的语句** | 死循环 | 能用 `for` 就用 `for` |

**第 1、5 条是最值得警惕的**：第 1 条不报错且退出码正常；第 5 条只在「正好最后一次猜中」时出现，随手测几次几乎碰不到——要靠专门的边界用例（第 2.1 章）。

# 四、本章小结

```text
while 条件：先判断再执行；while True + break 把退出条件放在能判断的位置
        ↓
for + range()：次数已知时用；range(a, b) 不含 b
        ↓
四个「结束」，范围层层扩大：
   continue  →  本轮
   break     →  整个循环
   return    →  整个函数
   sys.exit  →  整个程序
        ↓
⚠️ sys.exit() 的本质是 raise SystemExit
   ├─ 退出码 0，「少做了事」没有任何信号
   ├─ 继承 BaseException，except Exception 接不住
   └─ 只该出现在程序入口
        ↓
第三版猜数字：没有一处 sys.exit()，所以「本局结束」总能执行
```

一句话总结：**选「结束」方式的原则是：用作用范围最小、刚好够用的那个。** 范围越大，被它跳过的东西越多，而且往往没有任何提示。

<details>
<summary>参考答案</summary>

1. 因为**退出条件要等循环体执行一部分才能判断**（比如得先读到输入才知道是不是 `q`）。写在 `while` 后面就得在循环前读一次、循环末尾再读一次，同一行代码写两遍。
2. **1、2、3、4、5**（不含 6）。`range(a, b)` 有 **`b - a`** 个元素。
3. 长度正好是 `b - a`，好算；相邻区间 `range(0, 5)` 和 `range(5, 10)` 首尾相接、不重不漏。切片也遵守同样的约定。
4. 遍历已有的东西、重复固定次数用 `for`；重复到某个条件满足为止、次数事先不知道用 `while`。「能用 `for` 就用 `for`」是因为它不需要手动维护计数器，**不可能因为忘了更新计数而死循环**。
5. `continue` 结束**本轮**循环；`break` 结束**整个循环**；`return` 结束**整个函数**；`sys.exit()` 结束**整个程序**。
6. 「**循环结束后：保存成绩、打印统计**」那一行没有打印。退出码是 **0**。
7. 因为 0 在操作系统看来就是「成功」。终端里看不出异常，脚本和 CI 会判定成功，本该执行的代码被跳过了却**没有任何信号**。
8. 本质是 **`raise SystemExit`**。继承链是 `SystemExit → BaseException → object`。
9. **接不住。** `SystemExit` 继承的是 `BaseException` 而不是 `Exception`。这样设计是为了让「我要退出」不会被一个宽泛的 `except` 意外拦住。`KeyboardInterrupt`（Ctrl+C）也是同样的设计。
10. 分别是 **0、3、1**。传字符串时会把字符串打印到 stderr，退出码为 1。
11. `exit()` 是 `site` 模块在启动时塞进内置命名空间的、给**交互式解释器**用的便利工具（类型是 `_sitebuiltins.Quitter`）；`sys.exit()` 是标准库函数。**程序里该用 `sys.exit()`。** `python -S` 不加载 `site`，所以 `exit()` 会报 `NameError: name 'exit' is not defined`。
12. **只跳出最内层。** 想跳出多层，最干净的办法是把循环抽成函数，用 `return`。
13. 循环**正常结束**（`while` 条件变假、`for` 遍历完）时执行；被 **`break` 打断时不执行**。
14. 因为它要**跨轮累积**。写在循环里每一轮都会被重置成 0，计数永远是 1，而且不报错。
15. 因为最后一次机会可能恰好猜中。顺序写反的话，第 N 次（最后一次）猜中时，次数已经到了上限，会先被判成「次数用完」。暴露它的输入是 **`play(["1", "42"], 42, 2)`**——两次机会，第二次猜中。
16. **`return`。** `break` 只结束循环，函数还会继续往下执行；`sys.exit()` 结束整个程序，调用方没有任何机会处理；`return` 结束函数并把结果交给调用方，由调用方决定下一步。

</details>
