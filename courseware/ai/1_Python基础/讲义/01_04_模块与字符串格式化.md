# 一、概念与原理

## 1. 模块：Python 的能力从哪来

一个 `.py` 文件就是一个**模块**。

| 来源 | 说明 | 例子 | 要装吗 |
|---|---|---|---|
| **内置函数** | 不用导入，直接用 | `print()`、`len()`、`int()` | 不用 |
| **标准库** | 随 Python 安装，`import` 即可 | `random`、`json`、`sys`、`logging` | 不用 |
| **第三方库** | 别人写的，发布在 PyPI 上 | `requests`、`pytest` | **要 `pip install`** |
| **自己的模块** | 自己写的 `.py` 文件 | `m01_basics.ch01_04_example` | 不用 |

**标准库不用装，第三方库要装。** `import random` 在任何 Python 环境里都能用，`import requests` 在新的虚拟环境里会报：

```text
ModuleNotFoundError: No module named 'requests'
```

> 第 0.2 章说过，遇到 `ModuleNotFoundError` 先检查虚拟环境有没有激活。
> 这里补充一条：**再确认它是不是第三方库**。标准库的模块不可能报这个错（除非是下面第 3 节那种情况）。

## 2. `import` 的四种形式

```python
# ① 导入整个模块，用的时候带模块名
import random
random.randint(1, 100)

# ② 只导入模块里的某个成员，用的时候不带模块名
from random import randint
randint(1, 100)

# ③ 导入并起别名
import numpy as np
np.array([1, 2, 3])

# ④ 导入所有成员（不推荐）
from random import *
```

| 写法 | 之后怎么用 | 什么时候用 |
|---|---|---|
| `import X` | `X.成员` | **默认用这个**——读代码时一眼看出函数来自哪 |
| `from X import Y` | `Y` | 只用少数几个成员，名字不会冲突 |
| `import X as Y` | `Y.成员` | 模块名太长，或社区有约定别名（`np`、`pd`） |
| `from X import *` | 直接用 | **不要用**——不知道引入了哪些名字，可能覆盖你已有的变量 |

### ⚠️ `from random import random`

学习记录里出现过这样的代码：

```python
from random import random
random_num = random.randint(1, 100)
```

```text
1. from random import random 之后，random 是什么
   type(random) = builtin_function_or_method
   random.randint(1, 100)         → AttributeError: 'builtin_function_or_method' object has no attribute 'randint'
```

`random` 这个名字**既是模块名，又是这个模块里一个函数的名字**（`random.random()` 返回 0~1 的浮点数）。`from random import random` 导入的是那个**函数**，它当然没有 `randint`。

> **判断方法**：`from A import B` 之后，`B` 就是你导入的那个东西本身。
> 不能再用 `B.xxx` 去访问它在模块里的「兄弟」。

## 3. ⚠️ 自己的文件名遮蔽了标准库

这是新手最常见、也最莫名其妙的一个错误。

你在练习 `random` 的用法，顺手把文件命名为 `random.py`：

```python
# random.py
import random
print(random.randint(1, 100))
```

运行它：

**Python 3.13：**

```text
AttributeError: module 'random' has no attribute 'randint' (consider renaming
'C:\...\random.py' since it has the same name as the standard library module
named 'random' and prevents importing that standard library module)
```

**Python 3.11：**

```text
AttributeError: partially initialized module 'random' has no attribute 'randint'
(most likely due to a circular import)
```

**同一个错误，两个版本的提示完全不同。** 3.13 直接告诉你「把文件改个名」；3.11 说的是「可能是循环导入」，很容易把人带到错误的方向上去。

### 发生了什么

Python 找模块时，**先找当前脚本所在的目录，再找标准库**。

```text
import random
   ↓
1. 当前目录有 random.py 吗？  ← 有！就用它
2. 标准库里的 random          ← 根本没走到这一步
```

所以 `import random` 导入的是**你自己的 `random.py`**，而你的文件里没有 `randint`。

更隐蔽的情况是：**你的文件叫 `game.py`，但同一个目录里还躺着一个之前练习用的 `random.py`**。实测这种情况报的是完全一样的错误。你盯着 `game.py` 看半天也找不出问题，因为问题根本不在这个文件里。

| 避开这些名字 | 原因 |
|---|---|
| `random.py`、`json.py`、`logging.py`、`string.py`、`time.py`、`test.py` | 和标准库同名 |
| `requests.py`、`pytest.py`、`numpy.py` | 和你装的第三方库同名 |

> **第 3.1 章会讲完整的模块搜索规则**（`sys.path`）。现在只需要记住：
> 看到「标准库的模块没有某个属性」这种错误，第一件事是检查当前目录有没有同名文件。

## 4. `random` 模块

```python
import random

random.randint(1, 100)            # 1~100 的随机整数，两端都包含
random.random()                   # 0.0 ~ 1.0 的随机浮点数（不含 1.0）
random.choice(["石头", "剪刀", "布"])   # 从序列里随机选一个
random.shuffle(cards)             # 原地打乱列表，返回 None
random.sample(range(100), 5)      # 不重复地随机取 5 个
```

### `randint` 是闭区间——和 `range` 相反

```text
2. randint 两端都包含，range 不含结尾
   10000 次 randint(1, 3) 的分布：{1: 3346, 2: 3353, 3: 3301}
   list(range(1, 3))           ：[1, 2]
```

| | 包含开头 | 包含结尾 |
|---|---|---|
| `range(1, 3)` | ✓ | ✗ |
| `random.randint(1, 3)` | ✓ | **✓** |

Python 几乎所有地方都是「左闭右开」（`range`、切片），**`randint` 是例外**。它的兄弟 `random.randrange(1, 3)` 倒是左闭右开的，和 `range` 一致。

### 种子：让随机变得可重现

计算机产生的随机数其实是**伪随机**：从一个起始值（**种子**）出发，按固定算法一步步算出来。种子一样，算出来的序列就一样。

```text
3. 种子相同，随机序列就相同
   seed(42) 后连续 5 次：[82, 15, 4, 95, 36]
   seed(42) 后连续 5 次：[82, 15, 4, 95, 36]
   两个独立的 Random(42) 实例：82 和 82
```

**你在自己电脑上用 `seed(42)` 跑出来的也一定是 `[82, 15, 4, 95, 36]`**（同一个 Python 版本下）。

这有什么用？**测试。** 随机生成答案的游戏没法写断言——你不知道答案是什么。固定种子之后，答案就是确定的。

### `random.seed()` 和 `random.Random(seed)` 的区别

| 写法 | 影响范围 |
|---|---|
| `random.seed(42)` | **全局**：之后程序里所有地方的 `random.randint`、`random.choice` 都受影响 |
| `rng = random.Random(42)` | **只影响 `rng` 这一个对象**，别处的 `random` 照常 |

```python
def make_target(seed: int | None = None) -> int:
    return random.Random(seed).randint(1, 100)
```

**优先用独立实例。** 你在一个函数里调了 `random.seed()`，程序另一个角落的随机行为就悄悄变了——这叫「远距离作用」，排查起来极其困难。

`random.Random(None)` 用系统的随机源初始化，每次不同；`random.Random(42)` 每次相同。所以这个函数平时不传参数就是真随机，测试时传个种子就是确定的。

## 5. 字符串格式化：三代写法

```python
name, age = "Tom", 25

"我叫 %s，今年 %d 岁" % (name, age)            # ① % 格式化（最老）
"我叫 {}，今年 {} 岁".format(name, age)         # ② str.format()
f"我叫 {name}，今年 {age} 岁"                   # ③ f-string（Python 3.6+）
```

**现在一律用 f-string**：最短，变量就写在它该出现的位置。另外两种在老代码里会看到，能认出来就行。

### ⚠️ 两种不报错的错误

```text
4. 两种不报错的格式化错误
   漏掉 f      → 随机数：{num}
   交给 print  → 随机数：{} 56
   正确写法    → 随机数：56
```

**一、漏掉开头的 `f`**：花括号和变量名被原样输出。

**二、把 `{}` 交给 `print`**：

```python
print("随机数：{}", num)
```

这是 `print` 的两个参数：字符串 `"随机数：{}"` 和 `num`。`print` 把它们用空格连起来输出，`{}` 不会被替换——**`{}` 占位符是 `str.format()` 的功能，不是 `print` 的**。

学习记录里两种都出现过。**它们都要靠看输出才能发现。**

## 6. f-string 的格式规格

花括号里冒号后面那一段，控制值怎么显示：

```text
5. 格式规格：冒号后面那一段
   f"{3.14159:.2f}"               → '3.14'
   f"{1234567:,}"                 → '1,234,567'
   f"{0.85:.1%}"                  → '85.0%'
   f"{42:>8}|"                    → '      42|'
   f"{42:<8}|"                    → '42      |'
   f"{42:^8}|"                    → '   42   |'
   f"{7:03}"                      → '007'
   f"{name!r}"                    → "'Tom'"
   f"{x=}"                        → 'x=10'
   f"{x / y = :.2f}"              → 'x / y = 3.33'
   f"{{x}}"                       → '{x}'
```

| 写法 | 含义 |
|---|---|
| `:.2f` | 浮点数，保留 2 位小数 |
| `:,` | 千位分隔符 |
| `:.1%` | **先乘以 100**，加百分号，保留 1 位小数 |
| `:>8` `:<8` `:^8` | 右对齐 / 左对齐 / 居中，总宽度 8 |
| `:03` | 用 0 补齐到宽度 3 |
| `!r` | 用 `repr()` 显示（字符串会带引号） |
| `=` | **同时显示表达式和结果**（Python 3.8+） |
| `{{` `}}` | 字面的花括号 |

**`:%` 会自己乘以 100。** 写成 `f"{rate * 100:.0%}"` 会得到 `2857%` 这种结果。

**`!r` 在调试时很有用。** `f"{raw}"` 显示 `42`，看不出它是数字还是字符串；`f"{raw!r}"` 显示 `'42'`，引号说明它是字符串。第 1.3 章的游戏里 `print(f"   {raw!r} 不是整数")` 就是这个用途——用户输入了一个空格时，`!r` 会显示 `' '`，而不是一片空白。

**`=` 是调试神器。** 以前要写 `print(f"x={x}")`，现在写 `print(f"{x=}")`。它还能和格式规格组合：`f"{x / y = :.2f}"`。

## 7. ⚠️ 四舍五入的两个意外

```text
6. 四舍五入的两个意外
   round(2.5)                     → 2
   round(3.5)                     → 4
   round(0.5)                     → 0
   round(2.675, 2)                → 2.67
   format(2.675, '.20f')          → '2.67499999999999982236'
```

**意外一：`round(2.5)` 是 2，不是 3。**

Python 的 `round` 用的是「**四舍六入五成双**」（也叫银行家舍入）：正好是 .5 时，取**最近的偶数**。所以 `round(2.5) = 2`、`round(3.5) = 4`、`round(0.5) = 0`。

这样做的原因是统计上更公平：如果 .5 一律进位，大量数据求和时会系统性地偏大。

**意外二：`round(2.675, 2)` 是 2.67，不是 2.68。**

这次不是舍入规则的问题。`2.675` 这个小数**在二进制里存不准**，实际存的是 `2.67499999999999982236...`，比 2.675 小一点点，所以舍掉了。f-string 的 `:.2f` 也一样。

| 场景 | 怎么办 |
|---|---|
| 显示给人看 | 一般不用管，差别在最后一位 |
| **涉及钱** | 用标准库的 `decimal` 模块，或者以「分」为单位存整数 |

> 浮点数存不准这件事，B 线（NLP 课程）第 06 节讲 `np.isclose` 时有更完整的解释：
> `0.1 + 0.2 == 0.3` 的结果是 `False`。

## 8. ⚠️ f-string 对齐中文会歪

```text
7. f-string 对齐按字符数算，中文会歪
   |Tom     |   len=3  显示宽度=3
   |张三      |   len=2  显示宽度=4
   |欧阳修文    |   len=4  显示宽度=8
```

三行都是 `f"{name:<8}"`，但右边的竖线没对齐。

**f-string 按字符数补齐，而一个中文字符在终端里占两列。** `"张三"` 是 2 个字符，f-string 补了 6 个空格凑够 8 个字符——但它实际显示宽度是 4 + 6 = 10 列。

第 0.2 章的环境自检脚本已经遇到过这个问题，用 `unicodedata.east_asian_width()` 算显示宽度解决了。练习 4 就是把这个方法用到排行榜上。

> 为什么 Python 不直接按显示宽度对齐？因为「一个字符占几列」**取决于终端和字体**，
> 不是字符本身的属性。有一类字符（`①` `±` `§`）在中文终端里占两列、在西文终端里占一列。
> Python 不知道你用的是哪种终端。

## 9. `print()` 的参数

```python
print("a", "b", "c")                  # a b c        默认用空格分隔
print("a", "b", sep="-")              # a-b          改分隔符
print("不换行", end="")               # 默认 end="\n"，改成空字符串就不换行
print("错误信息", file=sys.stderr)      # 输出到标准错误（第 4.4 章讲日志时用）
```

`print("随机数：", num)` 的输出是 `随机数： 56`——中间有一个空格，因为那是 `sep` 的默认值。想精确控制，就用 f-string 拼好再交给 `print`。

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **`from random import random` 后调 `random.randint`** | `AttributeError: 'builtin_function_or_method' object has no attribute 'randint'` | 默认用 `import random` |
| **2** | **文件名和标准库同名** | 「模块没有某属性」；3.11 还会误导你去查循环导入 | 不用 `random.py`、`json.py`、`test.py` 这类名字 |
| **3** | **随机数生成在循环里** | 每轮答案都变，永远猜不中 | 跨轮不变的东西在循环外初始化 |
| **4** | **漏掉 f-string 的 `f`** | 花括号原样输出 | 看输出 |
| **5** | **`print("{}", x)`** | 输出 `{} 56` | 用 f-string |
| **6** | **`:%` 前面又手动乘 100** | 显示 `2857%` | `:%` 会自己乘 |
| **7** | **以为 `round` 是四舍五入** | `round(2.5)` 得 2 | 涉及钱用 `decimal` |
| **8** | **用 `random.seed()` 做测试** | 别处的随机行为被悄悄改变 | 用 `random.Random(seed)` 独立实例 |

**第 2 条最耗时间。** 错误信息指向的文件里根本没有问题，问题在同目录的另一个文件里。而 3.11 及更早版本的提示还会把你引向「循环导入」这个错误方向。

# 四、本章小结

```text
模块来源：内置 / 标准库 / 第三方（要装）/ 自己的
        ↓
import X  vs  from X import Y
   └─ ⚠️ from random import random 导入的是函数
        ↓
⚠️ 自己的 random.py 会遮蔽标准库 —— 当前目录优先
        ↓
random：randint 闭区间（例外！）、种子让结果可重现
   └─ 用 random.Random(seed)，别用全局的 random.seed()
        ↓
f-string 格式规格：.2f  ,  .1%  >8  03  !r  =
   ├─ ⚠️ 漏掉 f / 把 {} 交给 print —— 不报错
   ├─ ⚠️ round(2.5) == 2，round(2.675, 2) == 2.67
   └─ ⚠️ 按字符数对齐，中文会歪
```

一句话总结：**这一章的八个常见错误里，只有两个会报错。** 剩下六个都要靠看输出才能发现——这也是第 2 章要用测试代替「看输出」的理由。

<details>
<summary>参考答案</summary>

1. 内置函数直接用；标准库随 Python 安装，`import` 即可；第三方库是别人发布在 PyPI 上的，**需要 `pip install`**。
2. `random.randint(1, 100)` 和 `randint(1, 100)`。前者带模块名，后者不带。
3. 抛 `AttributeError: 'builtin_function_or_method' object has no attribute 'randint'`。因为 `random` 这个名字既是模块名又是模块里一个函数的名字，`from random import random` 导入的是那个**函数**，函数没有 `randint` 属性。
4. 不知道引入了哪些名字，**可能覆盖你已有的变量或函数**，而且读代码时看不出某个函数来自哪里。
5. 报 `AttributeError`，说 `random` 模块没有 `randint`。因为 Python **先在当前脚本所在目录找模块，再找标准库**，所以导入的是你自己的 `random.py`。问题不在 `game.py` 里，所以盯着它看是找不出来的。
6. 3.13 直接提示「consider renaming ... since it has the same name as the standard library module」；3.11 说的是「partially initialized module ... (most likely due to a circular import)」。**3.11 更容易误导**，会让人去查循环导入。
7. **`randint(1, 3)` 能取到 3**（闭区间）；`range(1, 3)` 不能（只有 1 和 2）。`randint` 是 Python 里少有的「两端都包含」的例外。
8. 伪随机数从一个起始值（种子）出发按固定算法算出来，种子相同序列就相同。对测试有用是因为**随机行为变得确定了**，可以写断言。
9. `random.seed(42)` 改的是**全局**生成器，程序里所有用 `random.xxx` 的地方都受影响；`random.Random(42)` 创建一个**独立**的生成器，只影响它自己。推荐后者是为了避免「在一个地方 seed，别处的随机行为悄悄变了」这种远距离作用。
10. 输出 `随机数：{} 56`。因为这是 `print` 的两个参数，`print` 只是把它们用空格连起来；**`{}` 占位符是 `str.format()` 的功能，不是 `print` 的**。
11. `'85.0%'`。写成 `0.85 * 100` 会得到 `'8500.0%'`，因为 **`:%` 会自己乘以 100**。
12. `!r` 用 `repr()` 显示，字符串会带引号。用于**需要分清值的类型或看清空白字符时**，比如 `'42'` 能看出是字符串，`' '` 能看出是一个空格。
13. `'x=10'`（假设 `x` 是 10）。同时显示表达式和结果，Python 3.8+ 支持。
14. 分别是 **2 和 4**。这叫「**四舍六入五成双**」（银行家舍入）：正好是 .5 时取最近的偶数。这样设计是为了统计上更公平——.5 一律进位的话，大量数据求和会系统性偏大。
15. **不是同一个原因。** `2.675` 在二进制里存不准，实际存的是 `2.67499999999999982236...`，比 2.675 小，所以舍掉了。这是浮点数精度问题，不是舍入规则问题。
16. **10 列。** f-string 按字符数补齐：「张三」2 个字符，补 6 个空格凑够 8 个字符。但每个中文字符在终端里占 2 列，所以实际是 4 + 6 = 10 列。
17. 写在循环里的话，每猜一次答案就重新生成一次，上一次的「大了/小了」提示全部作废，永远猜不中。**需要跨轮保持不变的东西，必须在循环外初始化。**
