
| 容器 | 解决什么问题 |

| **集合** | 去重；快速判断「有没有」 |

# 一、概念与原理

## 1. 字典：键到值的映射

```python
best = {"张三": 3, "李四": 5}
```

| 部分 | 含义 |
|---|---|
| `"张三"` | **键**（key），用来查找 |
| `3` | **值**（value），查到的东西 |

```text
1. 字典基础（d = {"张三": 3, "李四": 5}）
   d["张三"]                            → 3
   d["王五"]                            → KeyError: '王五'
   d.get("王五")                        → None
   d.get("王五", 0)                     → 0
   "张三" in d                          → True
   3 in d                             → False
   3 in d.values()                    → True
   list(d.items())                    → [('张三', 3), ('李四', 5)]
   ↑ in 查的是键，不是值
```

### `d[k]` 和 `d.get(k)`

| 写法 | 键存在 | 键不存在 |
|---|---|---|
| `d[k]` | 返回值 | **抛 `KeyError`** |
| `d.get(k)` | 返回值 | 返回 `None` |
| `d.get(k, 默认值)` | 返回值 | 返回默认值 |

**什么时候用哪个**：键**一定存在**（不存在就是 bug）时用 `d[k]`，让它报错；键**可能不存在**是正常情况时用 `get`。

这和第 1.5 章「只捕获你预期的异常」是同一个思路：不该发生的事就让它报错，别用 `get` 把 bug 掩盖成 `None`。

### `in` 查的是键

**`3 in d` 是 `False`**，因为 `3` 是值不是键。要查值得写 `3 in d.values()`——但那是逐个比较，和列表一样慢。

### 增、改、删

```python
best["王五"] = 4         # 键不存在：新增
best["张三"] = 2         # 键已存在：覆盖
del best["李四"]         # 删除，键不存在抛 KeyError
best.pop("王五")         # 删除并返回值，键不存在抛 KeyError
best.pop("赵六", None)   # 删除并返回值，键不存在返回 None
```

**同一个键只能有一个值。** `{'a': 1, 'a': 2}` 得到 `{'a': 2}`，后面的覆盖前面的。

## 2. 遍历字典

```python
for name in best:                       # 遍历键（默认）
    ...
for attempts in best.values():          # 遍历值
    ...
for name, attempts in best.items():     # 同时要键和值 —— 最常用
    print(f"{name}: {attempts} 次")
```

`items()` 返回的每一项是一个 `(键, 值)` 元组，`for name, attempts in ...` 是在解包它（第 6 节）。

### 顺序：按插入顺序

**从 Python 3.7 起，字典保证按插入顺序遍历。**

```python
d = {}
d["z"] = 1
d["a"] = 2
d["m"] = 3
list(d)           # ['z', 'a', 'm']    不是按字母排序，是按插入顺序
d["z"] = 99
list(d)           # ['z', 'a', 'm']    修改已有的键不改变顺序
```

> 你可能在老资料里读到「字典是无序的」。那是 3.6 之前的情况。现在可以依赖插入顺序——
> 练习 4 就会用到它。

## 3. 计数：最常见的字典用法

统计每种结果出现了几次：

```text
4. 计数的三种写法
   直接 counts[r] += 1  → KeyError: '大了'
   counts.get(r, 0) + 1 → {'大了': 2, '小了': 1, '正确': 1}
   Counter(results)     → {'大了': 2, '小了': 1, '正确': 1}
```

**第一种为什么报错**：`counts[r] += 1` 等价于 `counts[r] = counts[r] + 1`，要先**读出**旧值。第一次遇到 `"大了"` 时这个键还不存在。

**第二种是标准写法**：`get(r, 0)` 表示「没有就当它是 0」。

```python
counts: dict[str, int] = {}
for r in results:
    counts[r] = counts.get(r, 0) + 1
```

**第三种是标准库的现成工具**：

```python
from collections import Counter

counts = Counter(results)
counts.most_common(1)       # [('大了', 2)]   出现最多的
```

`Counter` 是 `dict` 的子类，用法基本一样，还多了 `most_common()` 这类方法。**能用 `Counter` 就用 `Counter`。** 练习 2 要求手写，是为了看清它在做什么。

## 4. ⚠️ 键必须可哈希

```text
2. 键必须可哈希；值相等的键会合并
   {[1, 2]: 'x'}                      → TypeError: unhashable type: 'list'
   {(1, 2): 'x'}                      → {(1, 2): 'x'}
   {1: 'a', True: 'b'}                → {1: 'b'}
   {1: 'a', 1.0: 'b'}                 → {1: 'b'}
   hash(1) == hash(True) == hash(1.0) → True
```

### 什么是哈希

字典之所以能按键快速查找，是因为它会对键调用 `hash()`，算出一个整数，直接用这个整数定位存放的位置——**不需要逐个比较**。

这要求键满足一个条件：**它的哈希值在存进字典之后不能变。** 否则存的时候算出位置 A，查的时候算出位置 B，就找不到了。

所以：

| 类型 | 能做键吗 | 原因 |
|---|---|---|
| `int`、`float`、`str`、`bool`、`None` | ✓ | 不可变 |
| `tuple`（元素也都不可变） | ✓ | 不可变 |
| `list`、`dict`、`set` | **✗** | 可变，内容一变哈希就变 |

**可哈希 ≈ 不可变。** 第 1.7 章讲的可变/不可变之分，在这里有了一个具体的后果。

### ⚠️ 值相等的键会合并

```python
{1: 'a', True: 'b'}       # → {1: 'b'}，只有一个键
```

**`True == 1` 是成立的**（第 1.2 章：`bool` 是 `int` 的子类），而且它们的哈希值也相同。对字典来说，它们就是**同一个键**。结果是：保留第一次出现的键 `1`，值被后面的 `'b'` 覆盖。

`1.0` 也一样，`{True, 1, 1.0}` 这个集合只有一个元素。

**什么时候会遇到**：从 JSON 读进来的数据里，`true` 和 `1` 混在一起做键；或者用一个「有时是布尔、有时是整数」的字段做分组。不报错，数据就悄悄合并了。

好消息是 `ruff` 能发现字面量里的这种重复：

```text
F601 Dictionary key literal `True` repeated (`True` hashes to the same value as `1`)
```

配套测试里有一行故意这样写，必须加 `# noqa: F601` 才能通过检查。

## 5. 遍历时改变字典的大小

```text
3. 遍历字典时改变它的大小
   边遍历边删 → RuntimeError: dictionary changed size during iteration
   for k in list(d) 先拍快照再删 → {'b': 2, 'c': 3}
```

**第 1.7 章说过，列表遍历时删除会悄悄漏删。字典会直接报错。** 报错反而是好事——你立刻知道写错了。

修法是**先拍一张快照**：`list(d)` 把所有键复制成一个新列表，遍历这个列表，删的是原字典。

```python
for k in list(d):
    if d[k] < 2:
        del d[k]
```

或者用推导式建一个新字典：

```python
d = {k: v for k, v in d.items() if v >= 2}
```

## 6. 元组：不可变的序列

```python
point = (3, 4)
steps = [(50, "大了"), (30, "小了"), (42, "正确")]
```

元组和列表很像：有序、能索引、能切片、能遍历。**区别只有一个：创建之后不能修改。**

### ⚠️ 逗号才是元组的标志

```text
5. 元组
   (1)                                → 1
   (1,)                               → (1,)
   1, 2                               → (1, 2)
   tuple([1, 2])                      → (1, 2)
```

**`(1)` 不是元组，是整数 1。** 括号在这里只是分组（和 `(1 + 2) * 3` 里的括号一样）。只有一个元素的元组必须写成 `(1,)`。

反过来，**没有括号也可以是元组**：`1, 2` 就是 `(1, 2)`。第 1.6 章的 `return a // b, a % b` 返回元组，就是这个原因。

### 解包

```python
guess, result = (50, "大了")         # 左边变量个数 = 元组长度

x, y = 1, 2
x, y = y, x                          # 交换两个变量，不需要临时变量
```

```text
   x, y = y, x → x=2, y=1
   first, *rest = [50, 30, 42] → first=50, rest=[30, 42]
```

`*rest` 表示「剩下的全部收进一个列表」。

### ⚠️ 元组不可变，但里面的东西可能可变

```text
   t = ([1, 2], 3); t[0] += [3] → TypeError: 'tuple' object does not support item assignment
   但是 t 已经变成了 ([1, 2, 3], 3)   ← 报错了，修改却生效了
```

**这是 Python 里最反直觉的现象之一。** 报错了，但修改生效了。

拆开看，`t[0] += [3]` 做了两件事：

```python
tmp = t[0]           # 取出那个列表
tmp += [3]           # 第一步：列表的 += 是原地 extend —— 成功，列表变成了 [1, 2, 3]
t[0] = tmp           # 第二步：把结果赋回元组的第 0 位 —— 失败，元组不能赋值
```

第一步已经原地修改了那个列表，第二步才报错。**列表已经变了，报错撤销不了它。**

这个现象说明了「元组不可变」的准确含义：**元组里每个位置指向哪个对象，这件事不能变**。但如果那个对象本身是可变的，它的内容可以变。这也是为什么含有列表的元组不能做字典的键：

```text
   hash((1, [2]))                     → TypeError: unhashable type: 'list'
```

> 我检查过，`mypy` 不会报 `t[0] += [3]` 这一行。这种问题只能靠理解，或者干脆别往元组里放可变对象。

### 什么时候用元组，什么时候用列表

| 用元组 | 用列表 |
|---|---|
| 固定几个值组成一个整体：`(猜的数, 结果)`、`(x, y)` | 一串同类的东西，个数会变 |
| 需要做字典的键或集合的元素 | 需要增删改 |
| 函数返回多个值 | 需要排序 |

一个记法：**元组像一条记录（每个位置含义不同），列表像一张表（每个位置含义相同）**。`(50, "大了")` 里第 0 位是数、第 1 位是结果；`[50, 30, 42]` 里每一位都是一次猜测。

## 7. 集合：去重与快速查找

```text
6. 集合
   type({})                           → <class 'dict'>
   type(set())                        → <class 'set'>
   {1, 2, 2, 3}                       → {1, 2, 3}
   {1, 2} | {2, 3}                    → {1, 2, 3}
   {1, 2} & {2, 3}                    → {2}
   {1, 2} - {2, 3}                    → {1}
   {1, 2} ^ {2, 3}                    → {1, 3}
   {True, 1, 1.0}                     → {True}
```

### ⚠️ `{}` 是空字典，不是空集合

**空集合要写 `set()`。** `{}` 留给了字典，因为字典比集合常用得多。

### 运算

| 运算 | 写法 | 含义 |
|---|---|---|
| 并集 | `a \| b` | 在 a 或 b 里 |
| 交集 | `a & b` | 同时在 a 和 b 里 |
| 差集 | `a - b` | 在 a 里但不在 b 里 |
| 对称差 | `a ^ b` | 只在其中一个里 |

```python
allowed = {"development", "testing", "production"}
if env not in allowed:              # 第 6.2 章读配置时会用到
    raise ValueError(f"未知环境：{env}")
```

### ⚠️ 集合不保证顺序

```text
   list(set([3, 1, 3, 2]))            → [1, 2, 3]
   list(dict.fromkeys([3, 1, 3, 2]))  → [3, 1, 2]
```

第一行看起来像「去重并排好序了」。**这是巧合，不是语言保证的行为。** 换一组整数：

```text
list({30, 5, 100, 42, 7})    → [100, 5, 7, 42, 30]
```

既不是插入顺序，也不是大小顺序。

对字符串更明显。我在四个进程里用不同的哈希种子跑同一行代码：

```text
PYTHONHASHSEED=1  →  ['cherry', 'date', 'apple', 'banana']
PYTHONHASHSEED=2  →  ['banana', 'date', 'cherry', 'apple']
PYTHONHASHSEED=3  →  ['banana', 'date', 'apple', 'cherry']
PYTHONHASHSEED=4  →  ['date', 'cherry', 'apple', 'banana']
```

不设种子连跑三次，三次结果也不一样。**Python 每次启动都会给字符串的哈希加一个随机种子**（这是一项安全措施，防止有人构造大量哈希冲突的输入拖慢程序），所以字符串集合的遍历顺序每次运行都可能不同。

**后果**：一段代码依赖了集合的顺序，在你电脑上测十次都对，部署到服务器上偶尔出错，而且没法稳定复现。

**需要「去重 + 保留顺序」时用 `dict.fromkeys`**：字典保证插入顺序，重复的键不会再插入一次，所以保留的是第一次出现的位置。练习 4 就是这个场景，测试会抓住 `list(set(...))`。

### 为什么字典和集合快

两者用的是同一套哈希机制（集合可以理解为「只有键、没有值的字典」）：

| 操作 | 列表 | 字典 / 集合 |
|---|---|---|
| `x in 容器` | 从头逐个比较，越长越慢 | 算哈希、直接定位，**和长度基本无关** |
| 按位置取 `[i]` | 直接定位 | 不支持（集合）/ 按键取（字典） |
| 保留顺序 | ✓ | 字典 ✓（3.7+），集合 **✗** |
| 元素要求 | 任意 | **必须可哈希** |

**代价是元素必须可哈希**——这就是第 4 节那些规则的由来。

## 8. 怎么选容器

| 场景 | 选 | 理由 |
|---|---|---|
| 一局的猜测轨迹，按顺序 | `list[int]` | 有序、个数会变 |
| 「这个数猜过没有」 | `set[int]` | `in` 快，不关心顺序 |
| 每个玩家的最好成绩 | `dict[str, int]` | 按名字查 |
| 一步：猜的数 + 结果 | `tuple[int, str]` | 固定两个值，含义不同 |
| 统计每种结果出现几次 | `Counter` / `dict[str, int]` | 计数 |
| 合法的环境名 | `set[str]` | 只判断「在不在」 |

**判断顺序**：先问「要不要按名字查」→ 字典；再问「要不要保留顺序、允许重复」→ 列表；只判断有没有 → 集合；固定几个值打包 → 元组。

## 9. 第八版猜数字：三种容器各管一件事

```python
def play(target, max_attempts=7, ask=input, say=print) -> list[tuple[int, str]]:
    steps: list[tuple[int, str]] = []    # 轨迹：要顺序
    seen: set[int] = set()               # 猜过的数：要快
    ...
        if guess in seen:
            say(f"   {guess} 已经猜过了，这次不算")
            continue
        seen.add(guess)
        steps.append((guess, result))
```

上一章用 `guess in history` 判断重复，`history` 是列表。这一章拆成两个容器：**`steps` 负责记录顺序，`seen` 负责快速判断**。

> 这看起来和第 1.7 章「同一个事实只存一份」矛盾？其实不矛盾。
> `seen` 可以从 `steps` 算出来，但它是为了速度而存在的**缓存**，并且两者只在同一处一起更新。
> 「只存一份」的真正要求是：**不要让两份数据有机会不一致**。两者相邻更新，就没有这个机会。

排行榜用字典：

```python
def record_round(board: dict[str, int], name: str, steps: list[tuple[int, str]]) -> bool:
    if not steps or steps[-1][1] != "正确":
        return False
    attempts = len(steps)
    best = board.get(name)
    if best is None or attempts < best:
        board[name] = attempts
        return True
    return False
```

`steps[-1][1]`：最后一步（`steps[-1]`）这个元组的第 1 位（结果）。注意先判断 `not steps`——空列表上取 `[-1]` 会报 `IndexError`。

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **用 `d[k]` 取可能不存在的键** | `KeyError` | 可能不存在时用 `get` |
| **2** | **用 `get` 掩盖一定存在的键** | bug 变成了一个 `None`，在远处才出错 | 一定存在时用 `d[k]`，让它报错 |
| **3** | **`counts[k] += 1` 计数** | 第一次遇到某个键时 `KeyError` | `counts.get(k, 0) + 1` 或 `Counter` |
| **4** | **`in d` 以为查的是值** | 结果不对 | `in d` 查键，`in d.values()` 查值 |
| **5** | **`True` 和 `1` 混用做键** | 数据悄悄合并 | 键的类型保持一致；`ruff` 的 F601 |
| **6** | **列表做键** | `unhashable type: 'list'` | 换成元组 |
| **7** | **遍历字典时增删键** | `RuntimeError` | `for k in list(d)` 或推导式建新字典 |
| **8** | **`(1)` 当成元组** | 得到整数 | `(1,)` |
| **9** | **`{}` 当成空集合** | 得到空字典 | `set()` |
| **10** | **依赖集合的顺序** | 偶发、无法稳定复现的 bug | 去重保序用 `dict.fromkeys` |

**第 5 条和第 10 条最难查。** 第 5 条不报错，数据悄悄少了；第 10 条在你的电脑上可能每次都对，换个环境才出问题。

---

# 四、本章小结

```text
字典：键 → 值
   ├─ d[k] 不存在报错 / d.get(k) 返回 None
   ├─ in 查的是键
   ├─ 3.7 起按插入顺序遍历
   ├─ 计数：get(k, 0) + 1 或 Counter
   └─ 遍历时增删 → RuntimeError（比列表的悄悄漏删好）
        ↓
⚠️ 键必须可哈希 ≈ 不可变
   └─ True == 1 == 1.0，哈希也相同 → 同一个键
        ↓
元组：不可变；逗号才是元组的标志
   ├─ 解包、交换、*rest
   └─ ⚠️ t[0] += [3]：报错了，修改却生效了
        ↓
集合：去重、交并差、in 很快
   ├─ ⚠️ {} 是空字典
   └─ ⚠️ 不保证顺序，字符串集合每次运行都可能不同 → 保序去重用 dict.fromkeys
```

一句话总结：**选容器时先问三个问题：要不要按名字查？要不要保留顺序？元素会不会变？** 三个答案基本就决定了用哪一种。

<summary>参考答案</summary>

1. `d[k]` 抛 `KeyError`，`d.get(k)` 返回 `None`（或指定的默认值）。键**一定存在**、不存在就是 bug 时用 `d[k]`，让它报错；键**可能不存在**是正常情况时用 `get`。
2. **`False`**。`in` 对字典查的是**键**，`3` 是值。查值要写 `3 in d.values()`。
3. **Python 3.7**。修改已有的键**不改变**顺序，只有新插入的键排在最后。
4. 因为 `+=` 要先**读出**旧值，第一次遇到某个键时它还不存在。标准写法是 `counts[r] = counts.get(r, 0) + 1`，或者直接用 `collections.Counter`。
5. 对象能用 `hash()` 算出一个整数，并且这个值**存进字典之后不会变**。列表是可变的，内容一变哈希就变——存的时候算出的位置和查的时候不一样，就找不到了。
6. 结果是 **`{1: 'b'}`**，只有一个键。因为 `True == 1`（`bool` 是 `int` 的子类），而且两者哈希值相同，字典把它们当成同一个键：保留第一次出现的键 `1`，值被后面的 `'b'` 覆盖。**`ruff` 的 F601 规则**能发现字面量里的这种重复。
7. 报 `RuntimeError: dictionary changed size during iteration`。**字典更好**——它直接报错，你立刻知道写错了；列表会悄悄漏删。正确做法是 `for k in list(d):` 先拍快照，或者用推导式建一个新字典。
8. `(1)` 是**整数 1**（括号只是分组）；`(1,)` 是**只有一个元素的元组**。逗号才是元组的标志。
9. `x, y = y, x`。右边先打包成元组 `(y, x)`，再解包给左边。
10. 报 `TypeError: 'tuple' object does not support item assignment`，但**元组里的列表已经变成了 `[1, 2, 3]`**。因为 `t[0] += [3]` 分两步：先对那个列表原地 extend（成功），再把结果赋回 `t[0]`（失败）。第一步的修改已经发生，报错撤销不了它。
11. 准确含义是：**元组每个位置指向哪个对象不能变**，但如果那个对象本身可变，它的内容可以变。`(1, [2])` **不能**做字典的键，因为里面有列表，`hash()` 会报 `unhashable type: 'list'`。
12. 元组用于**固定几个值组成一个整体**（每个位置含义不同，像一条记录）、需要做键或集合元素、函数返回多个值；列表用于**一串同类的东西**（每个位置含义相同，像一张表），个数会变、需要增删改或排序。
13. **`set()`**。`{}` 是**空字典**。
14. `{1, 2} - {2, 3}` 是 **`{1}`**（差集：在前者不在后者）；`{1, 2} ^ {2, 3}` 是 **`{1, 3}`**（对称差：只在其中一个里）。
15. **不能说明**，那是小整数在 CPython 实现上的巧合，换一组整数（`{30, 5, 100, 42, 7}` → `[100, 5, 7, 42, 30]`）顺序就乱了。字符串集合的顺序每次运行都可能不同，是因为 **Python 每次启动都会给字符串哈希加一个随机种子**，这是一项防止哈希冲突攻击的安全措施。
16. 用 **`list(dict.fromkeys(x))`**。字典从 3.7 起保证插入顺序，重复的键不会再插入一次，所以保留的是每个元素**第一次出现**的位置。
17. **不违反。** `seen` 是为了速度存在的**缓存**，而且两者在同一处相邻更新（`seen.add` 后紧跟 `steps.append`），没有机会不一致。「只存一份」的真正要求是**不要让两份数据有机会不一致**。
