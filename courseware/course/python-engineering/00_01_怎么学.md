# 0.1 这门课怎么学

> **前置** 无
> **时长** 约 20 分钟（只读，不写代码）
> **配套代码** 无

这一章不教任何技术内容。花 20 分钟读完它，后面 32 章会省下很多时间。

## 一、这门课在教什么

一个能跑的脚本，和一份能交付的代码，差的不是语法。

```python
# 能跑的脚本
num = int(input("猜数字："))
if num == 42:
    print("对了")
```

这段代码有什么问题？输入 `abc` 会崩，没法自动验证对不对，判断逻辑和显示文字绑在一起没法复用，出问题了不知道发生过什么。

**工程化就是把这些问题一个个解决掉的过程。** 这门课的 33 章就是这个过程的 33 个步骤。

## 二、一个项目贯穿全程

**不换例子。** 第 1 章写的猜数字游戏，会一直改到第 33 章：

```text
M1  猜数字游戏（单文件，60 行）
      ↓ 加测试
M2  check_num() 有了断言，改错代码测试会报警
      ↓ 拆文件
M3  main.py / game_logic.py / test_game.py 三个文件
      ↓ 加持久化
M4  history.py 记录每局成绩，带日志和数据校验
      ↓ 换数据源
M5  成绩从 HTTP API 读写，处理超时和格式错误
      ↓ 移出密钥
M6  API 地址和 Key 进 .env，支持开发/测试/生产三套
      ↓ 升级成类
M7  APIClient 类，三层架构，带资源清理
      ↓ 补测试
M8  用 Mock 隔离网络，不联网也能跑全部测试
```

这样安排有个好处：**每一章的新知识都有一个「为什么现在需要它」的理由。** 比如第 6.1 章讲环境变量，是因为第 5 章刚把 API Key 写进了代码，而那是不能提交到仓库的。

反过来也成立——如果你某一章觉得「学这个干嘛」，大概是跳过了前面某章。

## 三、每一章由什么组成

| 部分 | 怎么用 |
|---|---|
| **学习目标** | 开头有一份「学完能做什么」的清单。**学完回来对一遍**，做不到的回去重看 |
| **为什么需要这一章** | 上一章的代码在哪里不够用了。这部分别跳 |
| **概念与原理** | 主体。带可运行的示例，和真实的报错输出 |
| **动手练习** | 2~4 道题，分基础和进阶 |
| **常见错误** | 这一章对应的真实踩坑，每条都有复现步骤 |
| **本章小结** | 一张流程图 + 一句话总结 |
| **自测** | 10~20 个问题，答案折叠在下面 |

## 四、练习怎么做

配套代码在 [`code/`](code/)，每章三个文件：

```text
ch02_01_example.py     讲解里的示例 —— 先跑它
ch02_01_exercise.py    练习骨架 —— 你写的地方
ch02_01_solution.py    参考答案 —— 最后才看
```

**顺序是：跑示例 → 读讲解 → 做练习 → 跑测试 → 看答案。**

```powershell
# 1. 先跑示例，看到实际输出再回去读讲解
python -m m02_testing.ch02_01_example

# 2. 做完练习，用测试检查
pytest tests/test_m02.py -k ch02_01 -v
```

测试输出里的 `skipped` 表示那道题还没做：

```text
SKIPPED [1] tests\test_m02.py:36: test_is_leap_year 还没完成
```

全部做完就没有 skip 了。

### 关于参考答案

**卡住了先自己试 20 分钟。**

直接看答案能学到的东西比自己卡出来的少很多——因为「卡住」的那个点，正是你理解有缺口的地方，看答案会把它盖过去，而不是填上。

参考答案里每道题都写了「为什么这样做」。**那部分比答案本身重要**，做对了也值得读一遍。

## 五、遇到报错怎么办

报错是这门课的主要素材，不是意外。学会读它比避免它重要。

### 从下往上读

```text
Traceback (most recent call last):
  File "main.py", line 12, in <module>
    play_game()
  File "game_logic.py", line 25, in play_game
    num = int(user_input)
ValueError: invalid literal for int() with base 10: 'abc'
```

| 看哪里 | 得到什么 |
|---|---|
| **最后一行** | 错误类型（`ValueError`）和原因（`'abc'` 转不成整数） |
| **倒数第二组** | 出错的具体位置（`game_logic.py` 第 25 行） |
| 上面几组 | 调用链，从哪一路调过来的 |

**先读最后一行。** 它通常已经说清了问题。

### 三类报错的处理方式

| 类型 | 例子 | 怎么办 |
|---|---|---|
| **语法错误** | `SyntaxError`、`IndentationError` | 看报错指的那一行和**它上面一行**（漏括号、漏冒号常常指到下一行） |
| **运行时错误** | `ValueError`、`KeyError`、`TypeError` | 读最后一行，然后去报错位置看那个变量实际是什么 |
| **导入错误** | `ModuleNotFoundError` | 先确认虚拟环境激活了，再确认用的是 `python -m` 而不是 `python 路径/文件.py` |

### 调试的第一步永远是「打印出来」

```python
print(f"{user_input=}, {type(user_input)=}")
```

f-string 的 `=` 写法会同时打印变量名和值（第 1.4 章讲）。**猜变量的值是最浪费时间的调试方式**，打印一下只要 5 秒。

> 到第 4.4 章会用 `logging` 替代 `print`，但在调试当下，`print` 永远是最快的工具。

## 六、节奏建议

**每天 1 章，不要赶。** 33 章约 45 小时。

一次学 3 章和分 3 天学 3 章，效果差别很大——工程化的内容需要在自己写的代码上反复撞几次才会留下来。

| | 建议 |
|---|---|
| 一次学几章 | **1 章**，最多 2 章 |
| 练习做多久 | 卡 20 分钟再看答案 |
| 跟不上了怎么办 | 回到上一章的自测，对一遍学习目标 |
| 某章觉得太简单 | 直接做练习，做对了就过 |

## 七、三件不要做的事

**一、不要跳过 M1。**

M1 看起来是「基础语法」，但有几节是后面模块的地基：

| 章 | 后面在哪里用到 |
|---|---|
| 1.7 列表（**赋值是引用**） | M4 数据校验、M8 fixture 作用域 |
| 1.8 字典（**哈希要求**） | M4 JSON、M5 请求参数 |
| 1.9 **空容器的边界** | 贯穿全程，是 bug 最高发的地方 |

已经会的可以快速翻过，**但要做练习**。

**二、不要只读不做。**

这门课有一半内容是「某个写法在什么情况下会出问题」。读的时候都觉得懂了，自己写的时候照样会踩。

比如第 2.1 章那条「`assert` 在 `python -O` 下会被删除」——读过的人很多，但真正跑一次 `python -O` 看到校验失效的人很少。**跑过的人不会忘。**

**三、不要在报错时立刻改代码。**

先搞清楚它为什么错。随手改到不报错，问题通常只是换了个地方出现。

这门课后面有个真实案例（附录 A）：某处 `except` 顺序写错了，代码不报错、测试也通过，但日志把「数据格式错误」记成了「网络请求失败」。**排查方向被带偏了三章**，直到第 17 天才被发现。
