# 一、概念与原理

## 1. 定义与调用

```python
def add(a: int, b: int) -> int:     # 定义
    return a + b

result = add(3, 5)                   # 调用，result 得到 8
```

| 部分 | 说明 |
|---|---|
| `def` | 定义函数的关键字 |
| `add` | 函数名，命名规则和变量一样 |
| `(a, b)` | **形参**（parameter），函数内部用的名字 |
| `: int` / `-> int` | 类型注解（第 7 节） |
| 缩进的部分 | 函数体 |
| `return` | 把结果交给调用方 |

调用时传进去的 `3, 5` 叫**实参**（argument）。

## 2. `def` 是一条要执行的语句

```text
1. def 是一条要执行的语句：调用在 def 之前会报错
   NameError: name 'f' is not defined
```

```python
f()               # ← 这里报错

def f():
    print("hi")
```

**`def` 不是「声明」，是一条会被执行的语句。** 执行它的效果是「创建一个函数对象，把名字 `f` 绑定到它」。Python 从上往下执行，跑到 `f()` 时下面那个 `def` 还没执行，`f` 这个名字还不存在。

**但两个函数互相调用没有问题：**

```python
def a():
    b()           # 写的时候 b 还没定义，没关系

def b():
    print("hi")

a()               # 正常
```

因为 `a()` 里的 `b()` 是在**运行 `a` 的时候**才去查找 `b` 的。那时两个 `def` 都已经执行完了。

> **规律：名字必须在「被使用的那一刻」已经存在，而不是「写在前面」。**
> 学习记录里遇到过这个错误：主循环写在文件上方，`def check_guess` 写在下方。

## 3. `return` 的语义

```text
2. 没有 return 的函数返回 None
   show 打印了 5
   返回值 r = None   ← 屏幕上看到了 5，程序拿到的是 None
```

三个要点：

**一、没有 `return` 的函数返回 `None`。** 屏幕上看到了值，不等于程序拿到了值。

**二、`return` 会立即结束函数。** 后面的代码不再执行。所以它可以用来提前退出——第 1.3 章的 `play` 就是这样用的，第 1.9 章还会正式讲「守卫语句」。

**三、可以「返回多个值」**，实际上是返回一个元组（第 8 节）。

### `return` 与 `print` 的根本区别

| | `return` | `print` |
|---|---|---|
| 交给谁 | **调用方的代码** | **屏幕前的人** |
| 结果能继续用吗 | 能：参与运算、比较、传给别的函数 | 不能，程序拿不到 |
| 能直接测试吗 | 能：`assert f(x) == y` | 要捕获标准输出，很麻烦 |

**一句话：`print` 是给人看的，`return` 是给程序用的。**

这就是为什么从第 1.1 章开始，`check_num` 一直是 `return "小了"` 而不是 `print("小了")`。第 2.1 章写测试时会看到这个选择的回报。

## 4. ⚠️ 可变对象做默认值

```python
def add_item(item, items=[]):      # ← 危险
    items.append(item)
    return items
```

```text
3. 可变默认值：所有调用共享同一个列表
   add_item('a') = ['a']
   add_item('b') = ['a', 'b']   ← 第二次调用，没传 items
   add_item.__defaults__ = (['a', 'b'],)
```

**第二次调用明明没传 `items`，却拿到了第一次留下的 `'a'`。**

原因要回到第 2 节：**`def` 是一条语句，默认值是在这条语句执行时算出来的**——只算一次，然后存在函数对象的 `__defaults__` 里。之后每次不传 `items` 的调用，拿到的都是**同一个列表对象**。

修法是用 `None` 做默认值，在函数体里再创建新列表：

```python
def add_item(item: str, items: list[str] | None = None) -> list[str]:
    if items is None:
        items = []           # 函数体每次调用都重新执行，所以每次都是新列表
    items.append(item)
    return items
```

注意判断用的是 **`is None`**，不是 `if not items`。调用方明确传了一个空列表 `[]`，意思是「往这个列表里加」；`if not items` 会把它当成「没传」，另起一个新列表，调用方手里那个就没变。**这和第 1.2 章 `x or 默认值` 吞掉 0 是同一个坑。**

> 哪些默认值是安全的：`None`、数字、字符串、元组——**不可变的**都安全。
> 列表、字典、集合这些可变的都不安全。第 1.7 章会讲可变和不可变的区别。

## 5. 参数的几种传法

### 位置参数与关键字参数

```python
def check(guess, target):
    return guess - target

check(50, 42)                    # 位置参数：按顺序对应
check(guess=50, target=42)       # 关键字参数：按名字对应，顺序无关
check(target=42, guess=50)       # 同样正确
```

### 传错时的报错

```text
4. 参数传错时的报错原文
   check(1)             → TypeError: check() missing 1 required positional argument: 'target'
   check(1, 2, 3)       → TypeError: check() takes 2 positional arguments but 3 were given
   check(1, 2, goal=3)  → TypeError: check() got an unexpected keyword argument 'goal'
   check(1, guess=2)    → TypeError: check() got multiple values for argument 'guess'
```

这四条报错都很直白，值得认一遍。**最后一条容易困惑**：`1` 按位置给了 `guess`，然后又用关键字给了一次 `guess`，`target` 反而没人给。

### ⚠️ 参数传反不报错

```text
   参数传反不报错：check(50, 42) = 8，check(42, 50) = -8
```

**两个参数都是 `int`，传反了 Python 无从知道。** 结果直接反过来，没有任何提示。学习记录里第 12 天就因为这个出过一次错。

### 用 `*` 强制关键字参数

```python
def check_kw(*, guess: int, target: int) -> int:
    return guess - target
```

```text
   check_kw(50, 42)     → TypeError: check_kw() takes 0 positional arguments but 2 were given
   强制关键字参数：check_kw(guess=50, target=42) = 8
```

**单独的 `*` 表示「它后面的参数只能用关键字传」。** 调用方被迫写出 `guess=`、`target=`，传反就不可能了。

| 什么时候值得这样做 |
|---|
| 几个参数类型相同，传反了不报错 |
| 参数的含义从位置看不出来，比如 `f(True, False, True)` |

### 默认值

```python
def greet(name: str, greeting: str = "你好") -> str:
    return f"{greeting}，{name}"

greet("Tom")              # '你好，Tom'
greet("Tom", "早上好")     # '早上好，Tom'
```

**带默认值的参数必须放在没有默认值的参数后面**，否则是语法错误。

## 6. 作用域

```python
x = 10                 # 全局变量（模块级）

def f():
    y = 20             # 局部变量，只在函数里存在
    print(x)           # 能读到全局变量
```

**函数里定义的变量，外面访问不到。** 这保证了函数内部的名字不会和外面冲突。

### 四个常见的作用域错误

```text
5. 作用域与遮蔽
   函数里给全局变量赋值：
   UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
   在函数外访问局部变量：
   NameError: name 'y' is not defined
   变量名遮蔽了内置函数 sum：
   TypeError: 'int' object is not callable
   结果覆盖了函数名：
   TypeError: 'int' object is not callable
```

**第一个：`UnboundLocalError`**

```python
count = 0

def inc():
    count = count + 1      # ← 报错
```

**只要函数里对某个名字有赋值，Python 就把它当成局部变量**——整个函数里都是，包括赋值之前的那一半。所以 `count + 1` 里的 `count` 指的是「还没赋值的局部变量 `count`」，而不是外面那个全局的。

可以用 `global count` 声明它是全局的，**但不推荐**。更好的做法是传参数、返回结果：

```python
def inc(count: int) -> int:
    return count + 1

count = inc(count)
```

用 `global` 的函数，行为取决于外部状态——你没法只看函数本身判断它会做什么，也没法单独测试它。

**第三个：遮蔽内置函数**

```python
sum = 0                  # 把内置的 sum 函数盖掉了
sum([1, 2, 3])           # TypeError: 'int' object is not callable
```

Python 查找名字的顺序是 **LEGB**：

| 层 | 含义 |
|---|---|
| **L**ocal | 当前函数内部 |
| **E**nclosing | 外层函数（嵌套函数时） |
| **G**lobal | 模块级 |
| **B**uiltin | 内置名字：`print`、`len`、`sum`、`list`…… |

`sum = 0` 在 Global 层定义了一个 `sum`，它比 Builtin 层的 `sum` 先被找到。**不要用 `list`、`sum`、`max`、`min`、`input`、`id`、`type` 这些名字做变量名。**

**第四个：结果覆盖了函数名**

```python
def random_num():
    return random.randint(1, 9)

random_num = random_num()     # 现在 random_num 是一个整数
random_num()                  # TypeError: 'int' object is not callable
```

学习记录里第 6 天遇到过这个错误。看到 `'xxx' object is not callable`，**先找有没有哪里把这个名字赋成了别的值**。

## 7. 类型注解

```python
def check_num(guess: int, target: int) -> str:
    ...
```

| 写法 | 含义 |
|---|---|
| `guess: int` | 这个参数预期是整数 |
| `-> str` | 返回值预期是字符串 |
| `-> None` | 没有有意义的返回值 |
| `list[int]` | 元素是整数的列表 |
| `int \| None` | 整数或 None（Python 3.10+） |

### 注解不做运行时检查

```text
7. 类型注解不做运行时检查
   add(1, 2) = 'hello'   ← 注解写的是 -> int，实际返回了字符串
```

**运行时 Python 完全无视注解。** 那它有什么用？

### `mypy` 会在运行之前发现问题

```python
def add(a: int, b: int) -> int:
    return "hello"

check_num("50", 42)
result: int = check_num(50, 42)
```

```text
error: Incompatible return value type (got "str", expected "int")  [return-value]
error: Argument 1 to "check_num" has incompatible type "str"; expected "int"  [arg-type]
error: Incompatible types in assignment (expression has type "str", variable has type "int")  [assignment]
```

三个错误，**一行代码都没运行就全部发现了**。第二个尤其有价值：`check_num("50", 42)` 是第 1.1 章那个「`input()` 忘了转换」的错误，`mypy` 直接替你拦住了。

第 0.2 章的 `pyproject.toml` 里配置了 `disallow_untyped_defs = true`，所以课程代码里每个函数都必须写注解。练习文件被排除了，你写练习时可以先不写，但建议养成习惯。

> 配套代码里有几处 `# type: ignore[...]`，那是**故意的错误示范**，加上它 `mypy` 才能通过。
> 自己的代码里不要用它来掩盖真实的类型错误。

## 8. 返回多个值

```text
8. 返回多个值，其实是返回一个元组
   divide(17, 5) = (3, 2)   type = tuple
   q, r = divide(17, 5) → q=3, r=2
   ValueError: not enough values to unpack (expected 3, got 2)
```

```python
def divide(a: int, b: int) -> tuple[int, int]:
    return a // b, a % b       # 等价于 return (a // b, a % b)

q, r = divide(17, 5)            # 解包
```

**`return a, b` 返回的是一个元组**，括号可以省略。调用方用**解包**接收：左边变量的个数必须和元组长度一致，否则报 `ValueError`。

元组是第 1.8 章的内容，这里先会用就行。

## 9. 函数本身也是一个值

```text
6. 函数本身也是一个值
   greet   → greet 这个函数对象（不加括号 = 函数本身）
   greet() → 'hi'（加括号 = 调用它，得到返回值）
   f = greet; f() → 'hi'
```

| 写法 | 是什么 |
|---|---|
| `greet` | **函数本身**，一个可以被传来传去的对象 |
| `greet()` | **调用**它，得到返回值 |

**函数可以赋给变量，也可以作为参数传给另一个函数。** 这叫「函数是一等公民」。

### 它解决了一个实际问题：测试需要键盘输入的函数

第 1.3 章的 `play` 里直接调用了 `input()`，想测试它只有两个办法：用一个列表模拟输入（改变了函数的结构），或者在测试里偷偷把 `input` 换掉（`monkeypatch`）。

现在有第三个办法：**把「读一行输入」这件事本身当成参数传进来。**

```python
from collections.abc import Callable

def play(
    target: int,
    max_attempts: int = 7,
    ask: Callable[[str], str] = input,      # 默认就是内置的 input
    say: Callable[[str], None] = print,     # 默认就是内置的 print
) -> str:
    ...
    raw = ask(f"[{attempts + 1}/{max_attempts}] 你猜： ")
    ...
    say(f"   {guess:>3} → {result}")
```

`Callable[[str], str]` 的意思是：「一个接收 str、返回 str 的可调用对象」。内置的 `input` 正好符合，所以它可以做默认值。

**平时调用 `play(42)`，就是真实的键盘输入和屏幕输出。** 测试时：

```python
lines = []
result = play(42, ask=scripted(["abc", "50", "42"]), say=lines.append)

assert result == "猜中了，用了 2 次"
assert "    50 → 大了" in lines
```

`scripted` 返回一个按顺序吐出预设输入的假函数，`lines.append` 把每一行输出收集进列表。**整局游戏在没有键盘、没有屏幕的情况下跑完了，而且每一行输出都能断言。**

这叫**依赖注入**：函数需要的外部依赖（键盘、屏幕、网络、文件），由调用方传进来，而不是自己去拿。

> 第 8.1 章的 Mock 是另一种思路：不改函数签名，在运行时把 `input` 替换掉。
> 两种都常用。**能改签名的时候，依赖注入通常更清楚**——看签名就知道这个函数依赖什么。

## 10. 第六版猜数字

拆成一组各管一件事的函数：

| 函数 | 职责 | 纯函数吗 |
|---|---|---|
| `make_target(seed)` | 生成答案 | 传 seed 时是 |
| `parse_int(raw)` | 字符串转整数 | ✓ |
| `is_quit(raw)` | 判断是否退出 | ✓ |
| `check_num(guess, target)` | 比较大小 | ✓ |
| `play(target, max_attempts, ask, say)` | 跑一局，返回结局 | 依赖注入后可测 |

```python
def main() -> None:
    print(f"我想好了一个 {LOW}-{HIGH} 之间的数，你有 {MAX_ATTEMPTS} 次机会。")
    print(play(make_target()))
    print("本局结束")
```

```powershell
python -m m01_basics.ch01_06_example play
```

注意 `play` 返回结局字符串，**由 `main` 决定怎么显示**。`play` 也没有调用 `sys.exit()`——第 1.3 章说过，要不要结束程序是调用方的事。

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **调用写在 `def` 前面** | `NameError: name 'f' is not defined` | 主程序放在所有 `def` 之后，或放进 `main()` |
| **2** | **用 `print` 代替 `return`** | 调用方拿到 `None` | 函数计算结果用 `return`，显示交给调用方 |
| **3** | **可变对象做默认值** | 多次调用之间数据累积，不报错 | 默认值用 `None`，函数体里再创建 |
| **4** | **同类型参数传反** | 结果相反，不报错 | 用 `*` 强制关键字参数 |
| **5** | **函数里给全局变量赋值** | `UnboundLocalError` | 传参数、返回结果，不用 `global` |
| **6** | **用内置函数名做变量名** | `'int' object is not callable` | 避开 `list`、`sum`、`max`、`input`、`id`、`type` |
| **7** | **用结果覆盖函数名** | 同上 | 结果用另一个名字，比如 `target = make_target()` |
| **8** | **以为注解会在运行时检查** | 传错类型照样运行 | 用 `mypy` 在运行前检查 |

**第 3、4 条不报错**，而且只在特定调用方式下才出现。第 3 条要连续调用两次才能看到，第 4 条要恰好传反才能看到——这两类都是靠测试的特定用例才能发现。

---

# 四、本章小结

```text
def 是一条要执行的语句
   ├─ 名字在使用的那一刻必须已存在  →  调用不能写在 def 前面
   └─ 默认值在 def 执行时算一次      →  ⚠️ 可变默认值被所有调用共享
        ↓
return 给程序，print 给人；没有 return 就返回 None
        ↓
参数：位置 / 关键字 / 默认值
   └─ ⚠️ 同类型参数传反不报错  →  * 强制关键字
        ↓
作用域 LEGB
   ├─ 函数里赋值 = 局部变量  →  UnboundLocalError
   └─ 遮蔽内置名字          →  'int' object is not callable
        ↓
注解：运行时不检查，mypy 在运行前检查
        ↓
函数是一个值  →  可以当参数传  →  依赖注入，不用 monkeypatch 也能测
```

一句话总结：**一个好函数的标准是：只看它的签名，就知道它需要什么、给出什么、依赖什么。** 类型注解说明了「需要什么、给出什么」，依赖注入说明了「依赖什么」。

<details>
<summary>参考答案</summary>

1. 因为 **`def` 是一条执行语句**，执行后函数名才存在。模块顶层的代码从上往下执行，调用时下方的 `def` 还没执行到。函数互相调用没问题，是因为函数体里的调用发生在**运行时**，那时所有 `def` 都已执行完。
2. **`None`**。函数没有 `return`，默认返回 `None`；屏幕上打印出了 1，但这个值没有交给调用方。
3. `print` 把结果交给**屏幕前的人**，`return` 交给**调用方的代码**。`return` 更好测，因为可以直接 `assert f(x) == y`；`print` 的结果只能通过捕获标准输出来检查。
4. 第一次得到 `['a']`，第二次得到 `['a', 'b']`。因为**默认值在 `def` 执行时只算一次**，存在函数对象的 `__defaults__` 里，之后每次不传参数的调用都共享同一个列表对象。
5. 因为调用方可能明确传了一个**空列表**，意思是「往这个列表里加」。`if not items` 会把空列表当成「没传」，另起一个新列表，调用方手里的那个就没被修改。这和 `x or 默认值` 吞掉 0 是同一个坑。
6. **不可变的类型**：`None`、数字、字符串、元组。列表、字典、集合这些可变类型都不安全。
7. `TypeError: check() got multiple values for argument 'guess'`。`1` 按位置给了 `guess`，然后关键字又给了一次 `guess`，同一个参数被赋了两次值（而 `target` 没人给）。
8. **不会报错**，结果直接反过来。防止方法是用 `*` **强制关键字参数**，让调用方必须写出参数名。
9. 表示 **`*` 后面的参数只能用关键字传**，不能按位置传。
10. 因为**函数里对 `count` 有赋值**，Python 就把 `count` 当成整个函数的局部变量，包括赋值之前的 `count + 1`。而这个局部变量还没有值。
11. 用 `global` 的函数行为取决于外部状态，**没法只看函数本身判断它会做什么，也没法单独测试**。更好的写法是传参数、返回结果：`def inc(count): return count + 1`，然后 `count = inc(count)`。
12. **L**ocal → **E**nclosing → **G**lobal → **B**uiltin，Python 按这个顺序查找名字。`sum = 0` 在 Global 层定义了一个整数 `sum`，它比 Builtin 层的 `sum` 函数先被找到，所以 `sum([1, 2])` 是在调用一个整数。
13. **检查有没有哪里把这个名字赋成了别的值**——要么用内置函数名做了变量名，要么用函数的结果覆盖了函数名。
14. **不会。** 运行时 Python 完全无视注解。它的作用是给人看（不读实现就知道函数吃什么、吐什么）、给编辑器看（补全和提示）、**给 `mypy` 这类工具看（在运行前发现类型错误）**。
15. **能**，报 `Argument 1 to "check_num" has incompatible type "str"; expected "int"`。这对应第 1.1 章的「**`input()` 返回字符串，忘了转换**」。
16. 返回的是**元组**。`q, r, x = divide(17, 5)` 会报 `ValueError: not enough values to unpack (expected 3, got 2)`——左边 3 个变量，右边只有 2 个值。
17. `greet` 是**函数本身**，一个可以被赋值、被传递的对象；`greet()` 是**调用它**，得到返回值。
18. **依赖注入**：函数需要的外部依赖（键盘、屏幕、网络、文件）由调用方传进来，而不是自己去拿。`play` 不直接调用全局的 `input` 和 `print`，而是调用「别人交给它的那两个函数」。测试时交给它假的（一个按顺序返回预设输入的函数、一个收集输出的 `list.append`），它就用假的，所以不需要在运行时替换全局的 `input`。

</details>
