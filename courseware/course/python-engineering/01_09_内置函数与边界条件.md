# 一、概念与原理

## 1. 四个统计函数

```python
history = [30, 70, 50]

len(history)     # 3
sum(history)     # 150
max(history)     # 70
min(history)     # 30
```

都是**内置函数**，不需要导入。写法是 `len(history)` 而不是 `history.len()`——这些函数对列表、字符串、字典、集合都适用。

### ⚠️ 空容器上的行为

```text
1. 空容器：哪些会报错，哪些不会
   len([])                    → 0
   sum([])                    → 0
   max([])                    → ValueError: max() iterable argument is empty
   min([])                    → ValueError: min() iterable argument is empty
   max([], default=0)         → 0
   [][-1]                     → IndexError: list index out of range
   sum([]) / len([])          → ZeroDivisionError: division by zero
   sorted([])                 → []
```

| 调用 | 空容器时 | 为什么 |
|---|---|---|
| `len([])` | `0` | 没有元素，长度是 0 |
| `sum([])` | `0` | 数学约定：空和是 0 |
| `max([])` / `min([])` | **`ValueError`** | 空集合**没有**最大值 |
| `[][-1]` | **`IndexError`** | 没有最后一个元素 |
| `sum / len` | **`ZeroDivisionError`** | 除以 0 |

**`max([])` 报错不是 bug**，空集合确实没有最大值。处理方法有两种：

```python
max(history, default=0)      # 空时返回一个默认值
```

或者在调用之前就把空列表挡住（第 6 节的守卫语句）。

> **哪种好？** 看「默认值」有没有意义。猜数字的最大值在空列表时显示成 0 会误导人——
> 0 不在 1-100 范围里，用户会以为猜过 0。这时候守卫语句更合适：直接说「暂无统计」。

### 报错措辞在 3.13 变了

同一行 `max([])`，在两个版本上：

```text
Python 3.11:  ValueError: max() arg is an empty sequence
Python 3.13:  ValueError: max() iterable argument is empty
```

**异常类型没变，消息变了。** 这件事的实际意义是：**不要让代码依赖异常消息的原文。** 测试里写 `pytest.raises(ValueError, match="arg is an empty sequence")`，升级 Python 就挂了。要判断就判断异常类型。

> 网上很多教程和 AI 回答里引用的是旧版措辞，原学习记录里也是。你看到的可能和它们不一样。

## 2. `key` 参数与 `lambda`

`max`、`min`、`sorted` 都接收一个 `key` 参数：**一个函数，用它的返回值来比较，但返回的是原元素**。

```text
6. max / min / sorted 的 key 参数
   history = [50, 30, 45, 40]，target = 42
   min(history, key=lambda g: abs(g - 42)) → 40   离 42 最近的
   min([44, 40], key=lambda g: abs(g - 42)) → 44   并列时取先出现的
   sorted(history, reverse=True) → [50, 45, 40, 30]
```

`min(history, key=lambda g: abs(g - 42))` 的意思是：对每个 `g` 算出 `abs(g - 42)`，找出算出来最小的那个 `g`。

### `lambda`：一行写完的小函数

```python
lambda g: abs(g - 42)
```

等价于：

```python
def distance(g):
    return abs(g - 42)
```

| 部分 | 含义 |
|---|---|
| `lambda` | 关键字 |
| `g` | 参数 |
| `:` 之后 | **返回值**（只能是一个表达式，不能写语句） |

**`lambda` 只适合这种「当场用一次的简单函数」。** 逻辑超过一个表达式，就老老实实写 `def`。

第 1.8 章的排行榜也用了它：

```python
sorted(board.items(), key=lambda item: item[1])     # 按元组的第 1 位（次数）排序
```

### 并列时返回先出现的

`min([44, 40], key=...)` 里两个数离 42 都是 2，返回的是 **44**——先出现的那个。这是 `min` 文档保证的行为，可以依赖。

`max(1, '2')` 会报 `TypeError: '>' not supported between instances of 'str' and 'int'`——比较大小时，元素之间必须能比。

## 3. 除法的三个运算符

```text
4. 除法的三个运算符
   7 / 2                      → 3.5
   6 / 2                      → 3.0
   7 // 2                     → 3
   -7 // 2                    → -4
   7 % 2                      → 1
   -7 % 2                     → 1
   divmod(17, 5)              → (3, 2)
   int(-3.5)                  → -3
   math.floor(-3.5)           → -4
   1 % 0                      → ZeroDivisionError: integer modulo by zero
```

| 运算符 | 名称 | 结果类型 |
|---|---|---|
| `/` | 真除法 | **永远是 `float`**，即使能整除：`6 / 2` 是 `3.0` |
| `//` | 整除 | 两边都是 int 时是 int |
| `%` | 取余 | 同上 |
| `divmod(a, b)` | 同时取商和余数 | 元组 `(a // b, a % b)` |

### ⚠️ `//` 向下取整，`int()` 向零截断

```text
-7 // 2      → -4      向下取整：-3.5 往负无穷方向是 -4
int(-3.5)    → -3      向零截断：直接丢掉小数部分
```

**正数时两者一样，负数时不同。** 第 1.1 章讲过 `int(-3.99)` 是 `-3`，现在知道它和 `//` 不是一回事了。

### `%` 的符号跟除数走

```text
-7 % 2   → 1
7 % -2   → -1
```

Python 保证 `a == (a // b) * b + (a % b)` 永远成立。`-7 // 2` 是 `-4`，所以 `-7 % 2` 必须是 `-7 - (-4 × 2) = 1`。

> 这和 C、Java、JavaScript 不一样，它们的 `-7 % 2` 是 `-1`。
> 从其他语言转过来时，用 `%` 判断奇偶（`n % 2 == 1`）在负数上会得到不同结果。
> Python 里 `-7 % 2 == 1`，所以这个判断对负数也成立。

## 4. 浮点数求和：一处版本差异

```text
5. 浮点数求和
   0.1 + 0.2                  → 0.30000000000000004
   sum([0.1] * 10)            → 1.0
   math.fsum([0.1] * 10)      → 1.0
   当前 Python 3.13.2；3.11 及更早的 sum([0.1] * 10) 是 0.9999999999999999
```

第 1.4 章讲过浮点数存不准。`0.1 + 0.2` 在任何版本上都不等于 `0.3`。

**但 `sum([0.1] * 10)` 在 3.12 起变成了 `1.0`。** 我在同一台机器上用 3.11 和 3.13 分别跑了一遍：

```text
3.11.4 | sum([0.1]*10) = 0.9999999999999999
3.13.2 | sum([0.1]*10) = 1.0
```

[官方文档](https://docs.python.org/3/library/functions.html#sum) 的说明是：3.12 起，`sum()` 对浮点数换用了精度更高的求和算法。

| 写法 | 3.11 | 3.12+ |
|---|---|---|
| `0.1 + 0.2` | `0.30000000000000004` | 同左 |
| `sum([0.1] * 10)` | `0.9999999999999999` | **`1.0`** |
| `math.fsum([0.1] * 10)` | `1.0` | `1.0` |

**结论没变：不要用 `==` 比较浮点数。** 3.12 只是让 `sum` 更准了，没有让浮点数变得精确。需要高精度求和、又要跨版本一致时，用 `math.fsum`；比较两个浮点数时，用 `math.isclose(a, b)`。

## 5. ⚠️ 空容器边界清单

任何处理容器的代码都该问一句：**它是空的时候会怎样？**

### `split()` 的两种行为

```text
3. split() 的空字符串边界
   ''.split(',')              → ['']
   ''.split()                 → []
   ' a  b '.split()           → ['a', 'b']
   ' a  b '.split(' ')        → ['', 'a', '', 'b', '']
   'a,,b'.split(',')          → ['a', '', 'b']
   '50,'.split(',')           → ['50', '']
```

**`''.split(',')` 得到的是 `['']`——一个包含空字符串的列表，不是空列表。**

| 写法 | 行为 |
|---|---|
| `s.split()`（不带参数） | 按**任意空白**切分，**丢掉空段** |
| `s.split(',')`（带参数） | 严格按这个分隔符切，**保留空段** |

所以：

```python
[int(p) for p in "".split(",")]       # ValueError: invalid literal for int() with base 10: ''
```

一个「什么都没有」的输入，被当成了格式错误。末尾多一个逗号（`"50,"`）也会触发同样的错误。练习 4 就是修这个。

### `all` / `any` 的空真

```text
2. all / any 对空容器
   all([])                    → True
   any([])                    → False
```

**`all([])` 是 `True`。** 「所有元素都满足条件」在没有元素时**成立**——没有任何一个元素违反它。这在逻辑上叫**空真**（vacuous truth）。

```python
if all(score >= 60 for score in scores):
    print("全部及格")              # scores 为空时也会打印这一句
```

一个班一个学生都没有，也会显示「全部及格」。如果这不是你想要的，先判断非空。

### 完整清单

| 操作 | 空容器时 | 处理 |
|---|---|---|
| `max(x)` / `min(x)` | `ValueError` | `default=` 或守卫语句 |
| `sum(x) / len(x)` | `ZeroDivisionError` | 守卫语句 |
| `x[0]` / `x[-1]` | `IndexError` | 守卫语句 |
| `''.split(',')` | `['']`，**不是 `[]`** | 过滤空段 |
| `all(x)` | **`True`** | 需要时先判断非空 |
| `any(x)` | `False` | 通常符合预期 |
| `for item in x` | 一次都不执行 | 通常符合预期，但**循环后面的代码要能处理「什么都没发生」** |

### 判断空容器：真值测试

```python
if not history:          # 推荐
if len(history) == 0:    # 可以，但啰嗦
if history == []:        # 不推荐：对其他容器类型不适用
```

第 1.2 章讲过，空列表、空字符串、空字典、空集合都是假值。

## 6. 守卫语句

两种写法：

```python
# A：if / else 嵌套
def statistics(history):
    if len(history) == 0:
        return ["暂无统计"]
    else:
        avg = sum(history) / len(history)
        lines = [f"最大 {max(history)}，最小 {min(history)}，平均 {avg:.2f}"]
        ...
        return lines

# B：守卫语句
def statistics(history):
    if not history:
        return ["暂无统计"]

    avg = sum(history) / len(history)
    lines = [f"最大 {max(history)}，最小 {min(history)}，平均 {avg:.2f}"]
    ...
    return lines
```

**B 更好：**

| | |
|---|---|
| **缩进浅** | 主流程不嵌在 `else` 里。有三个边界条件时，A 要嵌三层，B 一层都不用 |
| **先排除，后处理** | 读到后面的代码时可以确信：不正常的情况已经被挡在外面了 |
| **边界集中在开头** | 一眼能看出这个函数对输入有什么要求 |

这叫**守卫语句**（guard clause）：用 `return` 提前结束函数，把不正常的情况挡在门口。第 1.6 章讲过「`return` 会立即结束函数」，这是它最常见的用法。

> 这两个异常（`max([])` 的 `ValueError`、平均值的 `ZeroDivisionError`）**属于正常使用中必然会遇到的情况**，
> 不该用 `try` 兜，应该用守卫语句提前避免。第 1.5 章说过：异常处理是为了处理**意外**，
> 而「用户一次都没猜」不是意外。

## 7. ⚠️ 范围判断：描述合法区间，不要枚举非法情况

```text
7. 范围判断：枚举非法 vs 描述合法
   x= -1  x<0 or x>100 判为合法: False  1<=x<=100: False
   x=  0  x<0 or x>100 判为合法: True   1<=x<=100: False
   x=  1  x<0 or x>100 判为合法: True   1<=x<=100: True
   x=100  x<0 or x>100 判为合法: True   1<=x<=100: True
   x=101  x<0 or x>100 判为合法: False  1<=x<=100: False
   ↑ 0 被第一种写法放过了
```

学习记录第 6 天的代码是这样写的：

```python
if i_num < 0 or i_num > 100:        # 想拦住非法输入
    print("请输入1~100的数字")
    continue
```

题目要求 1-100，**但 `0` 能通过**——0 既不小于 0，也不大于 100。

| 写法 | 思路 | 要想清楚什么 |
|---|---|---|
| `x < 0 or x > 100` | 枚举所有非法情况 | 所有边界在哪、每个边界是 `<` 还是 `<=` |
| `not 1 <= x <= 100` | 描述合法区间，再取反 | 只要说清上下界 |

**枚举非法情况要想全所有边界，描述合法区间只要写对两个数。** 后者的心智负担小得多。

> 规律：**范围判断先写「什么是对的」，再用 `not` 取反。**
> 第 1.2 章的 `classify` 和第 1.5 章的第五版游戏已经在这样写了。

## 8. 写完 `if` 分支，要写清「然后去哪」

同一份学习记录里还有另一个 bug：

```python
if i_num == 'q':
    show_statistics(guess_his)      # 打印完统计……然后呢？
i_num = int(i_num)                  # ← 继续执行到这里，int('q') 抛 ValueError
```

**少了一个 `break`。** 打印统计之后流程继续往下走，`int('q')` 抛 `ValueError`，被外层的 `except` 接住，打印「格式错误」，然后进入下一轮。

**现象是：输入 `q` 会打印一遍统计、再打印一句格式错误，游戏继续。** 用户怎么按 `q` 都退不出去。

而且它**没有崩溃**——异常被 `except` 吃掉了，看起来只是「提示有点怪」。这正是第 1.5 章说的「`try` 包得太大会把 bug 伪装成别的东西」。

> 规律：**一个分支做完事之后，明确它接下来去哪**——`return`、`break`、`continue`，还是确实该往下走。
> 只写处理、不写流程控制，代码就会顺着往下流到不该去的地方。

## 9. M1 最终版猜数字

```python
def statistics(history: list[int], target: int) -> list[str]:
    lines = [f"有效猜测 {len(history)} 次"]
    if not history:
        lines.append("一次都没猜，暂无统计")
        return lines

    avg = sum(history) / len(history)
    lines.append(f"最大 {max(history)}，最小 {min(history)}，平均 {avg:.2f}")
    if history[-1] == target:
        lines.append(f"猜中了，答案是 {target}")
    else:
        closest = min(history, key=lambda g: abs(g - target))
        lines.append(f"没猜中，答案是 {target}，离它最近的一次是 {closest}")
    return lines
```

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **对可能为空的列表调用 `max` / `min`** | `ValueError` | `default=` 或守卫语句 |
| **2** | **求平均值前没检查空列表** | `ZeroDivisionError` | 守卫语句 |
| **3** | **用 `[-1]` 前没检查空列表** | `IndexError` | 守卫语句 |
| **4** | **以为 `''.split(',')` 是 `[]`** | 空输入被当成格式错误 | 过滤空段，或先判断 `text.strip()` |
| **5** | **以为 `all([])` 是 `False`** | 空集合「全部满足」 | 需要时先判断非空 |
| **6** | **以为 `//` 和 `int()` 一样** | 负数时差 1 | 负数整除时想清楚要哪种 |
| **7** | **用 `x < 0 or x > 100` 判范围** | 0 被放过 | `not 1 <= x <= 100` |
| **8** | **`if` 分支做完事忘了 `break` / `return`** | 流程继续往下走，被 `except` 掩盖 | 每个分支写清「然后去哪」 |
| **9** | **测试依赖异常消息原文** | 升级 Python 后测试失败 | 判断异常类型，不判断措辞 |
| **10** | **用 `==` 比较浮点数** | 不同版本、不同写法结果不同 | `math.isclose` |

**第 4、5、7、8 条都不报错**，或者报的错和真正的问题无关。它们只能靠专门针对边界的测试用例发现——这正是下一个模块的主题。

# 四、本章小结

```text
len / sum 空时返回 0；max / min 空时报错
   └─ default= 或守卫语句；默认值有没有意义决定选哪个
        ↓
key 参数 + lambda：按算出来的值比较，返回原元素；并列取先出现的
        ↓
/ 永远是 float；// 向下取整，int() 向零截断；% 符号跟除数走
        ↓
⚠️ 空容器清单
   ├─ ''.split(',') 是 ['']，不是 []
   └─ all([]) 是 True（空真）
        ↓
守卫语句：先排除，后处理，主流程不缩进
        ↓
范围判断：描述合法区间再取反，不要枚举非法情况
        ↓
⚠️ 版本差异：max([]) 的措辞（3.13）、sum 浮点精度（3.12）
```

一句话总结：**写完一个处理容器的函数，先拿空容器调它一次。** 本章十个常见错误里，有六个会在这一次调用中暴露出来。

# 五、自测

1. `len([])`、`sum([])`、`max([])` 分别是什么结果？为什么 `max([])` 要报错？
2. `max(history, default=0)` 和守卫语句，各在什么时候更合适？
3. `max([])` 的报错消息在 3.11 和 3.13 有什么不同？这说明测试里应该怎么判断异常？
4. `min(history, key=lambda g: abs(g - 42))` 是什么意思？并列时返回哪个？
5. `lambda g: abs(g - 42)` 等价于什么样的 `def`？`lambda` 什么时候不该用？
6. `6 / 2` 的结果是什么类型？
7. `-7 // 2` 和 `int(-3.5)` 分别是多少？为什么不一样？
8. `-7 % 2` 是多少？Python 保证的等式是什么？这和 C、Java 有什么不同？
9. `sum([0.1] * 10)` 在 3.11 和 3.13 上分别是什么？`0.1 + 0.2 == 0.3` 在 3.13 上成立吗？
10. `''.split(',')` 和 `''.split()` 分别是什么？为什么 `[int(p) for p in "".split(",")]` 会报错？
11. `all([])` 和 `any([])` 分别是什么？为什么？
12. 判断列表为空，推荐怎么写？
13. 守卫语句比 `if / else` 嵌套好在哪三个方面？
14. 为什么「用户一次都没猜」不该用 `try` 处理？
15. `x < 0 or x > 100` 在题目要求 1-100 时有什么问题？怎么改？
16. 输入 `q` 后打印了统计但没写 `break`，会出现什么现象？为什么程序没有崩溃？

<details>
<summary>参考答案</summary>

1. 分别是 **`0`、`0`、`ValueError`**。`max([])` 报错是因为空集合**确实没有**最大值；而空和是 0、空长度是 0，这两个是有明确定义的。
2. `default=` 适合「默认值有实际意义」的场景；守卫语句适合「默认值会误导人」的场景——比如猜数字的最大值显示成 0，用户会以为猜过 0（0 不在合法范围里），这时直接说「暂无统计」更好。
3. 3.11 是 `max() arg is an empty sequence`，3.13 是 `max() iterable argument is empty`。**异常类型没变，消息变了**。说明测试里应该**判断异常类型**，不要依赖消息原文。
4. 对 `history` 里每个 `g` 算出 `abs(g - 42)`，返回算出来**最小的那个 `g`**——也就是离 42 最近的数。并列时返回**先出现的那个**，这是 `min` 文档保证的行为。
5. 等价于 `def f(g): return abs(g - 42)`。`lambda` 冒号后面只能是一个表达式，**逻辑超过一个表达式时就该用 `def`**。
6. **`float`**（`3.0`）。`/` 的结果永远是浮点数，即使能整除。
7. `-7 // 2` 是 **`-4`**，`int(-3.5)` 是 **`-3`**。`//` 是**向下取整**（朝负无穷），`int()` 是**向零截断**（丢掉小数部分）。正数时一样，负数时差 1。
8. **`1`**。Python 保证 `a == (a // b) * b + (a % b)`，因为 `-7 // 2` 是 `-4`，所以 `-7 % 2 = -7 - (-8) = 1`。**`%` 的符号跟除数走**。C、Java、JavaScript 的 `-7 % 2` 是 `-1`。
9. 3.11 是 **`0.9999999999999999`**，3.13 是 **`1.0`**——3.12 起 `sum()` 对浮点数换用了更精确的算法。`0.1 + 0.2 == 0.3` 在 3.13 上**仍然不成立**，因为两个数直接相加不经过 `sum`。
10. `''.split(',')` 是 **`['']`**（一个空字符串），`''.split()` 是 **`[]`**。带参数的 `split` 严格切分并保留空段，不带参数的按任意空白切分并丢掉空段。所以 `"".split(",")` 得到 `['']`，`int('')` 抛 `ValueError`。
11. `all([])` 是 **`True`**，`any([])` 是 **`False`**。「所有元素都满足」在没有元素时成立（没有任何元素违反它，这叫空真）；「至少有一个满足」在没有元素时不成立。
12. **`if not history:`**。空列表是假值，这是 Python 的惯用写法。
13. **缩进浅**（主流程不嵌在 `else` 里，多个边界条件时差距更明显）；**先排除后处理**（读后面的代码时可以确信不正常的情况已经被挡住了）；**边界集中在开头**（一眼看出函数对输入的要求）。
14. 因为它是**正常使用中必然会出现**的情况，不是意外。异常处理是为了处理意外，可预见的边界应该用守卫语句提前避免。
15. **`0` 能通过**——0 既不小于 0 也不大于 100。改成 **`not 1 <= x <= 100`**：描述合法区间再取反，只要写对上下界，不用想全所有非法情况。
16. 打印统计后流程继续往下走，`int('q')` 抛 `ValueError`，被外层的 `except` 接住、打印「格式错误」、进入下一轮——**现象是「输入 q 退不出去」**。没崩溃是因为异常被 `except` 吃掉了，这让 bug 更难发现。

</details>
