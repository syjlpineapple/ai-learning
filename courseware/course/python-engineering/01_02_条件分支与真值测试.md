# 一、概念与原理

## 1. `if / elif / else`

```python
if 条件1:
    # 条件1 成立时执行
elif 条件2:
    # 条件1 不成立、条件2 成立时执行
else:
    # 以上都不成立时执行
```

四个要点：

**一、冒号不能省。** `if`、`elif`、`else` 这一行末尾必须有 `:`。

**二、缩进决定代码块。** Python 不用大括号，靠缩进表示「哪些代码属于这个分支」。惯例是 **4 个空格**。同一个代码块里混用空格和 Tab 会抛 `TabError`。

**三、`elif` 和 `else` 都是可选的。** 只有一个 `if` 也合法。

**四、分支是互斥的。** 这一点单独展开。

## 2. `elif` 和连续 `if` 不是一回事

```python
x = 20

# 写法 A：if / elif
if x > 0:
    print("正")
elif x > 10:
    print("大于 10")

# 写法 B：两个独立的 if
if x > 0:
    print("正")
if x > 10:
    print("大于 10")
```

| 写法 | `x = 20` 时的输出 |
|---|---|
| A：`if / elif` | 只打印 `正` |
| B：两个 `if` | 打印 `正` 和 `大于 10` |

**`elif` 只在前面所有条件都不成立时才判断。** 一旦某个分支命中，后面的 `elif`、`else` 全部跳过。

由此得出一条实用规则：**用 `elif` 时，条件要从窄到宽排列。** 写法 A 里 `x > 10` 永远不会被执行到——任何大于 10 的数都先被 `x > 0` 截走了。这种「写了但永远进不去」的分支叫**死代码**。

> 死代码这个概念会在第 2.2 章和第 5.4 章变得非常重要。`except` 的顺序写错，
> 后面的分支就会变成死代码，而 Python 不报错也不警告。

## 3. 比较运算符

| 运算符 | 含义 |
|---|---|
| `==` | 相等 |
| `!=` | 不相等 |
| `>` `<` | 大于、小于 |
| `>=` `<=` | 大于等于、小于等于 |

**`=` 是赋值，`==` 才是比较。** 在 `if` 里写 `=` 会直接报 `SyntaxError`：

```python
if x = 1:     # SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

这是 Python 的好设计。C 语言里 `if (x = 1)` 能编译通过，是经典 bug 来源。

## 4. 真值测试：哪些值算「假」

`if` 后面不一定要写比较表达式，**任何值都能放在 `if` 后面**，Python 会自动判断真假。

假值只有这几种：

```text
1. 真值测试：哪些值在 if 里算「假」
   bool(False)                    → False
   bool(None)                     → False
   bool(0)                        → False
   bool(0.0)                      → False
   bool("")                       → False
   bool([])                       → False
   bool({})                       → False
   bool(())                       → False
   bool(set())                    → False
```

可以归成三类：**`False` 和 `None`、数字零、空容器**。除此之外全是真值。

所以可以这样写：

```python
if items:          # 等价于 if len(items) > 0
    ...
if not name:       # 名字是空字符串时成立
    ...
```

这种写法叫**真值测试**，比显式比较简洁，是 Python 的惯用法。

### 容易误判的真值

```text
   --- 下面这些都是「真」，最后两行最容易误判 ---
   bool(" ")                      → True
   bool([0])                      → True
   bool(-1)                       → True
   bool("0")                      → True
   bool("False")                  → True
```

| 值 | 为什么是真 |
|---|---|
| `" "` | 空格也是字符，不是空字符串 |
| `[0]` | 列表里有一个元素，列表就不是空的（哪怕元素是 0） |
| `-1` | 只有 0 是假，负数不是 |
| `"0"`、`"False"` | **非空字符串都是真值，不管内容是什么** |

**最后一条在读配置文件时会咬人**：配置文件里写的 `DEBUG=False`，读进来是字符串 `"False"`，`if debug:` 判为真。第 6.2 章会正面遇到这个问题。

## 5. 逻辑运算符与短路

| 运算符 | 含义 |
|---|---|
| `and` | 两边都真才真 |
| `or` | 任一边真就真 |
| `not` | 取反 |

Python 用这三个**英文单词**，不是 `&&` `||` `!`。

> `&` 和 `|` 在 Python 里也存在，但是**按位运算**，含义完全不同，而且优先级比比较运算符高。
> 误用它们代替 `and` / `or` 不会报错，只会得出错误的结果。第 4.5 章有一个真实案例。

### `and` / `or` 返回的不是 `True` / `False`

这一点很多人用了几年 Python 都不知道：

```text
2. and / or 返回的是操作数本身，不一定是 True / False
   "" or "匿名"                     → '匿名'
   "张三" or "匿名"                   → '张三'
   0 or "无限制"                     → '无限制'
   1 and "后面的值"                   → '后面的值'
   0 and 1/0                      → 0
   not ""                         → True
```

规则是：

| 运算 | 左边为真 | 左边为假 |
|---|---|---|
| `A or B` | 返回 **A** | 返回 **B** |
| `A and B` | 返回 **B** | 返回 **A** |

只有 `not` 一定返回布尔值。

### 短路求值

注意 `0 and 1/0` 那一行**没有报错**。`1/0` 会抛 `ZeroDivisionError`，但它根本没被执行：

> `and` 左边已经是假，结果一定是假，右边不用算了。

这叫**短路求值**。`or` 同理：左边为真时，右边不执行。

它的实际用途是**保护后面的表达式**：

```python
if user is not None and user.is_active:    # user 是 None 时，右边不会执行，不会报错
    ...
```

### `x or 默认值` 的陷阱

`or` 返回操作数这个特性，带来了一个常见写法：

```python
name = user_input or "匿名"        # 用户没输入时用默认值
```

**这个写法在值可能为 0 的时候会出错：**

```python
remaining = config_remaining or "不限次数"
```

`config_remaining` 是 `0` 时（一次都不剩了），`0` 是假值，被替换成了 `"不限次数"`。**含义正好反过来，而且不报错。**

| `remaining` 的值 | 业务含义 | `remaining or "不限次数"` 的结果 |
|---|---|---|
| `None` | 不限次数 | `"不限次数"` ✓ |
| `3` | 还剩 3 次 | `3` ✓ |
| **`0`** | **一次都不剩** | **`"不限次数"`** ✗ |

修法是**明确地判断 `None`**：

```python
if remaining is None:
    ...
```

> **规律**：当 `0`、`""`、`[]` 在业务上是合法值时，不能用真值测试代替 `is None`。
> 练习 4 就是这个场景。

## 6. `is` 与 `==`：身份与相等

```text
3. is 比较身份，== 比较值
   a == b → True    a is b → False    a is c → True
```

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a
```

| 运算符 | 比较什么 | `a` 和 `b` | `a` 和 `c` |
|---|---|---|---|
| `==` | **值**是否相等 | `True`（内容一样） | `True` |
| `is` | 是否为**同一个对象** | `False`（两个独立的列表） | `True`（`c` 就是 `a`） |

**`is` 只该用在三个地方：**

```python
x is None          # 判断是否为 None（标准写法）
x is True          # 判断是否就是 True 本身（少见）
type(x) is int     # 精确判断类型（见下一节）
```

其他情况一律用 `==`。Python 3.8 起，对字面量用 `is` 会直接给出警告：

```text
<string>:1: SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
```

**看到这个警告就改成 `==`。**

## 7. 判断类型：`isinstance` 与 `type`

```text
   isinstance(42, int)            → True
   isinstance('42', int)          → False
   isinstance(True, int)          → True
   type(True) is int              → False
   ↑ bool 是 int 的子类。isinstance 认子类，type(...) is 不认
```

| 写法 | 含义 | 对 `True` 判断是不是 `int` |
|---|---|---|
| `isinstance(x, int)` | x 是 int **或 int 的子类** | `True` |
| `type(x) is int` | x 的类型**恰好**是 int | `False` |

**`bool` 是 `int` 的子类**——`True` 在数值上等于 1，`False` 等于 0。所以 `isinstance(True, int)` 为真。

大多数时候用 `isinstance`。但如果你要检查的是「用户给的是不是一个真正的整数」，`True` 混进来就是个 bug。第 4.3 章校验 JSON 数据时会遇到这个问题。

### 一个真实的错误写法

学习记录里出现过这样的代码：

```python
from pydantic.v1.validators import Number

raw = input("请输入数字")
if raw is Number:              # ← 永远是 False
    raw = int(raw)
```

两处错误：

| 错误 | 为什么 |
|---|---|
| `raw is Number` | 在问「`raw` 这个对象是不是 `Number` 这个类本身」，当然不是。判断类型应该用 `isinstance` |
| **但 `isinstance` 在这里也没用** | `input()` 返回的**永远是 `str`**。根本不存在「输入的是数字类型」这回事，只存在「这个字符串**长得像**数字」 |

还有第三处：**为一个标准库就能做的事引入了第三方依赖**。`pydantic` 是个很重的数据校验库，而这里需要的只是字符串自带的一个方法。

> **习惯：先问标准库有没有现成的。** 多一个依赖就多一份安装、版本和安全负担。

## 8. 字符串的判断方法

字符串自带一组 `isXxx()` 方法：

| 方法 | 判断 |
|---|---|
| `s.isdigit()` | 每个字符都是「数字字符」 |
| `s.isdecimal()` | 每个字符都是「十进制数字」 |
| `s.isalpha()` | 每个字符都是字母（中文也算） |
| `s.isspace()` | 每个字符都是空白 |
| `s.startswith(x)` | 以 x 开头 |

**空字符串调用这些方法都返回 `False`**（`"".isdigit()` 是 `False`）。

看起来 `isdigit()` 正好能用来「先检查再转换」：

```python
raw = input("猜一个数字： ")
if raw.isdigit():
    guess = int(raw)
    ...
else:
    print("不是整数")
```

**但它和 `int()` 的判断标准不一样。**

## 9. ⚠️ `isdigit()` 和 `int()` 在两个方向上都不一致

```text
4. isdigit() 和 int() 的判断并不一致
   输入      isdigit   isdecimal   int()
   '123'   True      True        123
   '-5'    False     False       -5
   ' 42'   False     False       42
   '3.14'  False     False       ValueError
   ''      False     False       ValueError
   '４２'    True      True        42
   '²'     True      False       ValueError
```

把不一致的行挑出来：

| 输入 | `isdigit()` 说 | `int()` 实际 | 后果 |
|---|---|---|---|
| `'-5'` | 不是整数 | **能转**，得 -5 | **误杀**：合法输入被拒绝 |
| `' 42'` | 不是整数 | **能转**，得 42 | **误杀** |
| `'²'`（上标 2） | **是整数** | **会崩**，`ValueError` | **漏放**：校验通过了，程序照样崩 |

**第二类更严重。** 用 `isdigit()` 做校验的程序，输入 `²` 会通过检查，然后在 `int()` 那一行崩溃——**正是你加这段检查想要避免的事情**。

配套测试里有一条专门验证这件事：

```python
def test_ch01_02_example_play_v2_crashes_on_superscript(fake_input):
    """讲解的结论：用 isdigit 做校验，输入 ² 会崩。"""
    fake_input(["²"])
    with pytest.raises(ValueError):
        ch01_02_example.play_v2()
```

### 为什么会这样

`isdigit()` 判断的是「这个字符**在 Unicode 里被归类为数字字符**」。上标 `²`、`³` 被归类为数字字符，但它们不是十进制数字——你不能用 `²` 来写一个数。

`isdecimal()` 更严格，只认「能用来写十进制数」的字符，所以 `'²'.isdecimal()` 是 `False`，和 `int()` 一致。

| 方法 | 认 `²` 吗 | 和 `int()` 一致吗 |
|---|---|---|
| `isdigit()` | 认 | ✗ 会漏放 |
| **`isdecimal()`** | **不认** | **✓ 这一点一致** |

但 `isdecimal()` 也不认负号和空格，所以「误杀」的问题还在。**练习 3 就是要你把这两个问题都修掉。**

> 修完之后你会发现，还有一个情况对不上：`int("1_000")` 能转（Python 允许数字里写下划线），
> 你的函数大概会拒绝它。每补一条规则，就离 `int()` 的真实实现更近一步，也更容易漏。
>
> 这暴露了「先检查再转换」这种思路的根本问题：**检查逻辑必须和真正执行的逻辑完全一致，而这往往做不到。**
> 第 1.5 章会给出另一种思路——直接调用 `int()`，失败了再处理。那样判断标准就是 `int()` 本身，不可能不一致。

## 10. 链式比较

```text
5. 链式比较与优先级
   1 <= 5 <= 100                  → True
   1 <= 150 <= 100                → False
```

`1 <= x <= 100` 等价于 `1 <= x and x <= 100`，但只写一次 `x`，读起来和数学写法一样。

```python
if not 1 <= guess <= 100:
    return "超出范围"
```

**这是 Python 的特色写法**，很多语言不支持。在 C 或 JavaScript 里，`1 <= x <= 100` 会被解析成 `(1 <= x) <= 100`，先得到 `true` / `false`，再拿它和 100 比，结果永远为真。

## 11. 运算符优先级：`== ` 比 `or` 先算

```text
   False == False or True         → True
   True == False or True          → True
   ↑ 后两行：== 比 or 优先级高，所以 X == False or True 永远是 True
```

```python
x == False or True
```

你可能想表达「x 等于 False 或 True 之一」，但 Python 的解析方式是：

```python
(x == False) or True     # 不管 x 是什么，结果都是 True
```

**比较运算符的优先级高于 `and` / `or` / `not`。**

| 优先级（从高到低） | 运算符 |
|---|---|
| 高 | 算术：`*` `/` `+` `-` |
| ↓ | 比较：`==` `!=` `<` `>` `<=` `>=` `is` `in` |
| ↓ | `not` |
| ↓ | `and` |
| 低 | `or` |

想表达「x 是这几个值之一」，用 `in`：

```python
x in (False, True)
```

> 第 2.1 章的练习 2 里有一条断言就是 `assert is_leap_year(2023) == False or True`——它**永远通过**，
> 测试写了等于没写。现在你应该能一眼看出原因了。

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **`elif` 条件从宽到窄排** | 后面的分支永远进不去（死代码） | 从窄到宽排，或者每个分支都写完整条件 |
| **2** | **`x or 默认值` 吞掉合法的 0** | `0` 被替换成默认值，含义反转，不报错 | 0 / 空串合法时用 `is None` |
| **3** | **非空字符串 `"False"`、`"0"` 当成假** | 配置里的 `False` 被判为真 | 读进来的字符串要显式比较：`value == "true"` |
| **4** | **用 `is` 比较值** | 有时对有时错（小整数缓存），Python 3.8+ 给 `SyntaxWarning` | 只对 `None` 用 `is` |
| **5** | **用 `isdigit()` 校验后直接 `int()`** | 输入 `²` 时校验通过、程序崩溃 | 用 `isdecimal()`；或第 1.5 章的 EAFP |
| **6** | **`x == A or B` 想表达「是 A 或 B 之一」** | 永远为真 | 用 `x in (A, B)` |

**第 2、5、6 条都不报错**，或者只在特定输入下才出问题。这一类错误要靠测试的边界用例才能发现（第 2.1 章）。

# 四、本章小结

```text
if / elif / else：分支互斥，elif 从窄到宽排
        ↓
真值测试：False/None、数字零、空容器是假，其余全是真
   └─ ⚠️ "0"、"False" 是真
        ↓
and / or 返回操作数本身 + 短路求值
   └─ ⚠️ count or 默认值 会吞掉合法的 0  →  用 is None
        ↓
is 比身份，== 比值；isinstance 认子类（bool 是 int 的子类）
        ↓
⚠️ isdigit() 和 int() 两个方向都不一致
   ├─ 误杀：-5、" 42"
   └─ 漏放：²  ← 校验通过但程序崩溃
        ↓
「先检查再转换」的根本问题：检查逻辑必须和执行逻辑完全一致  →  1.5 换思路
```

一句话总结：**一个判断条件写出来容易，写得和你想的完全一致很难。** 本章五个「⚠️」里，有四个是不报错的。

# 五、自测

1. `if / elif` 和连续两个 `if` 有什么区别？`x = 20` 时 `if x > 0 ... elif x > 10 ...` 会进几个分支？
2. 什么是死代码？`elif` 的条件应该按什么顺序排？
3. `if x = 1:` 会发生什么？
4. Python 里哪些值是假值？可以归成哪三类？
5. `bool(" ")`、`bool("0")`、`bool([0])` 分别是什么？
6. `"" or "匿名"` 和 `"张三" or "匿名"` 分别返回什么？`A and B` 的返回规则是什么？
7. `0 and 1/0` 为什么不报错？这个机制叫什么？有什么实际用途？
8. `remaining or "不限次数"` 在什么情况下会出错？怎么改？
9. `is` 和 `==` 的区别是什么？`is` 只该用在哪些地方？
10. `isinstance(True, int)` 和 `type(True) is int` 分别是什么结果？为什么？
11. `if raw is Number:` 这个写法有哪几处问题？
12. `isdigit()` 和 `int()` 在哪两个方向上不一致？各举一个例子。哪个方向更危险？
13. `isdigit()` 和 `isdecimal()` 对 `²` 的判断有什么不同？为什么？
14. `1 <= x <= 100` 在 Python 和 C 语言里分别是什么含义？
15. `True == False or True` 为什么是 `True`？想表达「x 是 A 或 B 之一」应该怎么写？

<details>
<summary>参考答案</summary>

1. `elif` 只在前面所有条件都不成立时才判断，分支互斥；连续 `if` 是各自独立判断。`x = 20` 时 `if / elif` **只进第一个分支**（`x > 0` 命中后 `elif` 被跳过）。
2. 写了但永远不会执行到的代码。`elif` 的条件应该**从窄到宽**排列，否则宽的条件会把窄的截走。
3. 直接报 `SyntaxError`，提示 `Maybe you meant '==' or ':=' instead of '='?`。Python 不允许在 `if` 里写赋值，避免了 C 语言的经典 bug。
4. `False`、`None`、`0`、`0.0`、`""`、`[]`、`{}`、`()`、`set()`。三类：**`False` 和 `None`、数字零、空容器**。
5. 都是 **`True`**。空格是字符所以 `" "` 非空；`"0"` 是非空字符串；`[0]` 有一个元素所以列表非空。
6. `'匿名'` 和 `'张三'`。`or` 左边为真返回左边，为假返回右边。`A and B`：A 为真返回 **B**，A 为假返回 **A**。
7. 因为 `and` 左边已经是假，结果必然为假，**右边根本不执行**。这叫**短路求值**。用途是保护后面的表达式，比如 `user is not None and user.is_active`，`user` 为 `None` 时不会去访问它的属性。
8. 当 `remaining` 是 **`0`**（合法值，表示一次都不剩）时，`0` 是假值，会被替换成 `"不限次数"`，含义正好反过来。改法：`if remaining is None:` 明确判断 None。
9. `==` 比较**值**是否相等，`is` 比较是否为**同一个对象**。`is` 只该用于 `x is None`、`x is True`、`type(x) is int` 这三种场景。
10. 分别是 `True` 和 `False`。因为 **`bool` 是 `int` 的子类**：`isinstance` 认子类，`type(...) is` 只认精确类型。
11. 三处：① `is` 比较身份不是类型，永远为 `False`；② 即使改成 `isinstance` 也没用，因为 `input()` **永远返回 `str`**，只存在「字符串长得像数字」；③ 为一个标准库能做的事引入了 `pydantic` 这个重依赖。
12. **误杀**：`"-5"`、`" 42"`，`isdigit()` 说不是、`int()` 能转。**漏放**：`"²"`，`isdigit()` 说是、`int()` 会崩。**漏放更危险**——校验通过之后程序照样崩溃，正是加检查想避免的事。
13. `isdigit()` 认 `²`，`isdecimal()` 不认。`isdigit()` 判断的是「Unicode 里被归类为数字字符」，上标数字属于这一类；`isdecimal()` 只认「能用来写十进制数」的字符，和 `int()` 的规则一致。
14. Python 里是**链式比较**，等价于 `1 <= x and x <= 100`。C 里会被解析成 `(1 <= x) <= 100`，先得到 0 或 1，再和 100 比，**结果永远为真**。
15. 因为 `==` 的优先级高于 `or`，表达式被解析成 `(True == False) or True`，即 `False or True`，结果为 `True`——**不管左边是什么，都是 `True`**。想表达「是 A 或 B 之一」用 `x in (A, B)`。

</details>
