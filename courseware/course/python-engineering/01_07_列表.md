# 一、概念与原理

## 1. 列表：有序、可变的容器

```python
guesses = [50, 30, 42]
```

| 性质 | 含义 |
|---|---|
| **有序** | 元素有固定位置，不会自己变 |
| **可变** | 可以增加、删除、修改元素 |
| **元素类型不限** | `[1, "a", True, [2, 3]]` 合法，但实践中通常保持同一类型 |

创建列表的几种方式：

```python
items = []                  # 空列表
items = [1, 2, 3]
items = list("abc")         # ['a', 'b', 'c']   字符串被逐个拆开
items = list(range(5))      # [0, 1, 2, 3, 4]
items = [0] * 5             # [0, 0, 0, 0, 0]
```

## 2. 索引与切片

```text
1. 索引与切片（items = [10, 20, 30, 40, 50]）
   items[0]                   → 10
   items[-1]                  → 50
   items[5]                   → IndexError: list index out of range
   items[1:3]                 → [20, 30]
   items[:3]                  → [10, 20, 30]
   items[3:]                  → [40, 50]
   items[::2]                 → [10, 30, 50]
   items[::-1]                → [50, 40, 30, 20, 10]
   items[10:20]               → []
   ↑ 索引越界会报错，切片越界不会 —— 它只返回能取到的部分
```

### 索引

**从 0 开始。** 长度为 n 的列表，合法索引是 0 到 n-1。`items[len(items)]` 一定越界——这是最常见的 **off-by-one 错误**（差一错误）。

**负索引从末尾倒数。** `items[-1]` 是最后一个，`items[-2]` 是倒数第二个。取最后一个元素就写 `items[-1]`，不要写 `items[len(items) - 1]`。

### 切片

`items[开始:结束:步长]`，**左闭右开**——包含开始，不包含结束。和 `range()` 一致（第 1.3 章），和 `random.randint()` 相反（第 1.4 章）。

| 写法 | 含义 |
|---|---|
| `items[1:3]` | 索引 1、2 |
| `items[:3]` | 从头到索引 2 |
| `items[3:]` | 从索引 3 到末尾 |
| `items[:]` | 全部（**这是一个拷贝**，第 5 节） |
| `items[::-1]` | 反转 |

**切片的两个特性：**

- **越界不报错**：`items[10:20]` 返回 `[]`。这有时方便（不用先判断长度），有时会掩盖 bug（你以为取到了东西，其实是空的）
- **返回新列表**：改切片的结果不影响原列表

## 3. 常用方法

```python
items = [1, 2, 3]

items.append(4)          # 末尾加一个元素
items.extend([5, 6])     # 末尾逐个加多个元素
items.insert(0, 0)       # 在索引 0 的位置插入
items.remove(3)          # 删除第一个值为 3 的元素，找不到抛 ValueError
items.pop()              # 删除并返回最后一个
items.pop(0)             # 删除并返回索引 0 的元素
items.index(5)           # 第一个值为 5 的元素的索引，找不到抛 ValueError
items.count(2)           # 值为 2 的元素有几个
```

### `append` 和 `extend`

```text
   append([3, 4]) → [1, 2, [3, 4]]
   extend([3, 4]) → [1, 2, 3, 4]
   extend('ab')   → [1, 2, 'a', 'b']   ← 字符串被拆成了单个字符
```

`append` 把参数**整个**当作一个元素加进去；`extend` 把参数里的元素**逐个**加进去。

**最后一行是个容易踩的坑**：想加一个字符串 `"ab"`，误用了 `extend`，结果加进去的是 `'a'` 和 `'b'` 两个元素。因为字符串也能逐个遍历。

## 4. ⚠️ 原地修改的方法返回 `None`

```text
2. 原地修改的方法返回 None
   r = items.sort()      → r=None，items 被原地排好了：[1, 2, 3]
   items = items.sort()  → items=None   ← 列表没了
   sorted([3, 1, 2])     → [1, 2, 3]   ← 返回新列表，原列表不变
```

**`sort()`、`append()`、`extend()`、`reverse()`、`insert()`、`remove()` 都是「原地修改 + 返回 `None`」。**

`items = items.sort()` 把排好序的列表丢掉了，换成了 `None`。下一行用 `items` 的地方会报 `'NoneType' object is not ...`，而错误的根源在上一行。

| 原地修改，返回 `None` | 返回新对象，原对象不变 |
|---|---|
| `items.sort()` | `sorted(items)` |
| `items.reverse()` | `items[::-1]` 或 `list(reversed(items))` |

> **为什么要这样设计？** 返回 `None` 是一个明确的信号：「我改的是你手里那一份，不是给了你一份新的」。
> 如果 `sort()` 返回排好的列表，你就分不清原列表到底变没变。练习 4 会用到这个约定。

## 5. 可变与不可变

Python 的类型分两大阵营：

| 可变（mutable） | 不可变（immutable） |
|---|---|
| `list`、`dict`、`set` | `int`、`float`、`str`、`bool`、`tuple`、`None` |
| 可以**原地**修改内容 | 任何「修改」都是创建一个**新对象** |

```python
s = "hello"
s[0] = "H"         # TypeError: 'str' object does not support item assignment
s = s.upper()      # 不是修改，是创建了一个新字符串 "HELLO"，再让 s 指向它
```

所以字符串的所有方法——`upper()`、`strip()`、`replace()`——都**返回新字符串**，原字符串不变。第 1.1 章的 `raw.strip().lower()` 能链式调用，就是因为每一步都返回一个新字符串。

**这个区分是本章接下来所有坑的根源。**

## 6. ⚠️ 赋值是引用，不是拷贝

```text
3. 赋值是引用，不是拷贝
   b = a; b.append(4)       → a = [1, 2, 3, 4]    a is b: True
   c = a.copy(); c.append(5) → a = [1, 2, 3, 4]    a is c: False
```

```python
a = [1, 2, 3]
b = a              # 不是复制！b 和 a 指向同一个列表
b.append(4)
print(a)           # [1, 2, 3, 4]  ← a 也变了
```

**变量不是装东西的盒子，而是贴在对象上的标签。** `b = a` 是在同一个列表上又贴了一张标签 `b`。通过任何一张标签修改，看到的都是同一个列表。

`a is b` 为 `True` 证明了这一点——第 1.2 章讲过，`is` 判断的就是「是不是同一个对象」。

### 为什么不可变类型没有这个问题

```python
x = 10
y = x
y = y + 1      # 不是修改 10，是让 y 指向一个新的 11
print(x)       # 10
```

`int` 没法原地修改。`y + 1` 创建了一个新的 `11`，`y` 这张标签被撕下来贴到了 `11` 上，`x` 还贴在 `10` 上。

**共享一个不可变对象是完全安全的**，因为谁都改不了它。这就是为什么上一章说「`None`、数字、字符串做默认值是安全的」。

### 想要独立的副本

```python
c = a.copy()      # 方法
c = a[:]          # 切片
c = list(a)       # 构造新列表
```

三种写法效果一样。

### ⚠️ 浅拷贝只复制一层

```text
   浅拷贝后改内层            → 原列表 = [[1, 2, 99], [3, 4]]
                                nested[0] is shallow[0]: True
   深拷贝后改内层            → 原列表 = [[1, 2], [3, 4]]
```

```python
nested = [[1, 2], [3, 4]]
shallow = nested.copy()
shallow[0].append(99)
print(nested)              # [[1, 2, 99], [3, 4]]  ← 原列表的内层也变了
```

**`copy()` 只复制了外层列表**。外层是新的，但里面装的还是**同一批内层列表的引用**。`nested[0] is shallow[0]` 为 `True`。

要完全独立，用深拷贝：

```python
import copy
deep = copy.deepcopy(nested)
```

| | 外层 | 内层 |
|---|---|---|
| `b = a` | 共享 | 共享 |
| `a.copy()` / `a[:]` | **新的** | 共享 |
| `copy.deepcopy(a)` | **新的** | **新的** |

## 7. ⚠️ `[[0] * 3] * 3` 陷阱

```text
4. [[0] * 3] * 3 陷阱
   g = [[0] * 3] * 3; g[0][0] = 1 → [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
   g[0] is g[1] is g[2]: True
   推导式版本                     → [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```

想建一个 3×3 的表格，改了左上角一个格子，**三行的第一个格子全变成了 1**。

拆开看：

```python
row = [0] * 3          # 执行一次，得到一个列表 [0, 0, 0]
g = [row] * 3          # 把「对 row 的引用」复制 3 份
```

`* 3` 复制的是**引用**，不是列表本身。三行是同一个列表，`g[0] is g[1] is g[2]` 为 `True`。

**为什么 `[0] * 3` 本身没问题？** 它也是三个位置指向同一个 `0`。但 `0` 是不可变的——`row[0] = 1` 是让第 0 个位置指向一个新的 `1`，不影响其他位置。**只有可变对象被共享时才会出问题。**

正确写法是用推导式，让每一行都**重新执行一次** `[0] * 3`：

```python
g = [[0] * 3 for _ in range(3)]
```

`_` 是一个约定俗成的变量名，表示「这个循环变量我用不上」。

## 8. ⚠️ 函数会改到调用方的列表

```text
5. 把列表传给函数
   add_bonus(mine) 之后 mine = [60, 70, 100]   ← 函数改到了调用方的列表
   rebind(mine2) 之后 mine2 = [60, 70]        ← 重新绑定不影响调用方
```

```python
def add_bonus(scores: list[int]) -> None:
    scores.append(100)          # 修改：通过标签改了那个列表

def rebind(scores: list[int]) -> None:
    scores = [0]                # 重新绑定：把函数里的标签撕下来贴到新列表上
```

**传参和赋值是同一回事**：调用 `add_bonus(mine)` 时，相当于执行了 `scores = mine`——函数里的 `scores` 和外面的 `mine` 贴在同一个列表上。

| 函数里做了什么 | 调用方看得到吗 |
|---|---|
| **修改**：`scores.append(...)`、`scores[0] = ...`、`scores.sort()` | **看得到** |
| **重新绑定**：`scores = [...]` | **看不到**，只影响函数里的局部变量 |

**第一行是 bug 的常见来源**：调用一个函数，你以为它只是「读一下」你的列表，结果它悄悄改了。

> 这就是上一章可变默认值 bug 的完整解释：默认值 `[]` 是一个列表对象，
> 每次调用都把参数 `history` 贴到它上面，`history.append()` 是**修改**，所以累积了下来。

## 9. ⚠️ 遍历时删除元素会漏删

```text
6. 遍历时删除元素
   从 [-1, -2, 3, -4, 5] 删负数 → [-2, 3, 5]   ← -2 没删掉
```

```python
items = [-1, -2, 3, -4, 5]
for x in items:
    if x < 0:
        items.remove(x)
```

**`-2` 被跳过了。** 过程是这样的：

| 步 | 循环位置 | 看到的 x | 操作 | 删完后的列表 |
|---|---:|---:|---|---|
| 1 | 0 | -1 | 删 | `[-2, 3, -4, 5]` |
| 2 | **1** | **3** | 不删 | 同上 |
| 3 | 2 | -4 | 删 | `[-2, 3, 5]` |
| 4 | 3 | —— | 越界，结束 | |

`for` 循环内部记着一个「走到第几个」的位置。第 1 步删掉 `-1` 后，`-2` 前移到了位置 0，而循环的位置继续前进到 1——**`-2` 就这样被跳过了**。

**不报错，只是结果错了。** 而且换一组数据可能碰巧正确（比如负数都不相邻时），所以随手测几下可能发现不了。

### 两种正确做法

```text
   推导式建新列表             → [3, 5]
   items[:] = ...  → items = [3, 5]  alias = [3, 5]   （原地替换）
   items = ...     → items = [3, 5]  alias = [-1, -2, 3, -4, 5]   （重新绑定）
```

**做法一：建一个新列表**（推荐默认用这个）

```python
items = [x for x in items if x >= 0]
```

**做法二：原地替换全部内容**

```python
items[:] = [x for x in items if x >= 0]
```

两者的区别在最后两行：`alias` 是另一个指向原列表的变量。

| 写法 | `items` | 原列表（`alias`） |
|---|---|---|
| `items = [...]` | 新列表 | **不变** |
| `items[:] = [...]` | 原列表 | **被替换了内容** |

**什么时候用哪个**：默认用做法一，调用方不会被意外影响。只有在「调用方明确希望自己的列表被改」时用做法二——这时函数应该返回 `None`，和 `list.sort()` 一样，用返回 `None` 表明「我改的是你那份」。练习 4 就是这个场景。

## 10. 遍历与 `enumerate`

```python
for guess in history:                         # 只要元素
    print(guess)

for i, guess in enumerate(history, start=1):  # 要元素也要序号
    print(f"第 {i} 次：{guess}")
```

**需要序号时用 `enumerate`**，不要写 `for i in range(len(history))`——后者能用，但更长，而且多一次下标访问就多一次写错的机会。

`start=1` 让序号从 1 开始，给人看的编号通常这样写。

## 11. `in` 与速度

```python
50 in history          # 判断是否猜过
```

**对列表来说，`in` 是从头到尾逐个比较。** 列表越长越慢：

```text
7. in 的速度：list 逐个比较，set 直接定位
   10 万个元素，查最后一个，各 1000 次：
   list:   950.11 ms
   set :    0.105 ms   （约快 9,083 倍，具体数字因机器而异）
```

**几千到上万倍的差距**（我在同一台机器上跑了两次，一次 9 千倍、一次 1.8 万倍，数量级是稳定的）。

猜数字的历史最多 7 个元素，用列表完全没问题。但如果是「判断一个用户名是否在 10 万个已注册用户里」，就必须用 `set`。第 1.8 章讲集合。

## 12. 列表推导式

```python
squares = [x ** 2 for x in range(5)]               # [0, 1, 4, 9, 16]
evens = [x for x in range(10) if x % 2 == 0]       # [0, 2, 4, 6, 8]
```

结构是 `[表达式 for 变量 in 可遍历对象 if 条件]`，等价于：

```python
squares = []
for x in range(5):
    squares.append(x ** 2)
```

**适合「一个简单表达式 + 一个简单条件」。** 逻辑一多——比如要先转换、再判断两次——就写回普通循环。推导式套推导式、再加两个条件，三个月后自己都读不懂。

## 13. 第七版猜数字：只保留一个数据源

```python
def play(target, max_attempts=7, ask=input, say=print) -> list[int]:
    history: list[int] = []
    while len(history) < max_attempts:
        ...
        if guess in history:
            say(f"   {guess} 已经猜过了，这次不算")
            continue
        history.append(guess)
        ...
    return history


def summarize(history: list[int], target: int) -> str:
    if not history:
        return "一次都没猜"
    won = history[-1] == target
    ...
```

**注意没有 `attempts` 计数器了。** 次数就是 `len(history)`。

学习记录第 5 天的版本同时维护了两个变量：

```python
count += 1
guess_history.append(i_num)
```

`count` 永远等于 `len(guess_history)`。**两个变量表达同一件事，迟早会有一个分支只改了其中一个**——比如这一版新加的「重复猜测不算」，如果只在 `history.append` 前面 `continue`、忘了 `count` 也要跟着跳过，次数就对不上了。而且不报错。

> **规律：同一个事实只存一份。** 需要的时候从那一份算出来。

另外两处值得注意：

- `play` 返回 `history`，由 `summarize` 决定怎么显示——**计算和显示分开**，和第 1.6 章一致
- `summarize` 第一行先处理空列表。`history[-1]` 在空列表上会报 `IndexError`，**用到 `[-1]` 之前必须确认非空**。第 1.9 章会专门讲空容器的边界

# 三、常见错误

| # | 错误 | 表现 | 怎么避免 |
|---|---|---|---|
| **1** | **`items[len(items)]`** | `IndexError` | 最后一个用 `items[-1]` |
| **2** | **`items = items.sort()`** | 列表变成 `None` | `items.sort()` 或 `items = sorted(items)` |
| **3** | **`extend` 一个字符串** | 字符串被拆成单个字符 | 加一个元素用 `append` |
| **4** | **以为 `b = a` 是复制** | 改 `b` 时 `a` 也变 | `b = a.copy()` |
| **5** | **浅拷贝嵌套列表** | 改内层时原列表也变 | `copy.deepcopy()` |
| **6** | **`[[0] * n] * m`** | 改一格，整列都变 | `[[0] * n for _ in range(m)]` |
| **7** | **函数悄悄修改了参数** | 调用方的数据被改了 | 默认返回新列表；原地修改时返回 `None` 并写进文档 |
| **8** | **遍历时删除元素** | 漏删，不报错 | 推导式建新列表，或 `items[:] = ...` |
| **9** | **用 `[-1]` 前没检查空列表** | `IndexError` | 先 `if not items:` |
| **10** | **同一个事实存两份** | 两份对不上，不报错 | 只存一份，需要时算出来 |

**第 4 到第 8 条的根源都是同一件事：可变对象被多个名字共享。** 认清「这一步是修改还是重新绑定」「这里是共享还是拷贝」，就能避开它们。

---

# 四、本章小结

```text
列表：有序、可变
   ├─ 索引越界报错，切片越界不报错
   └─ ⚠️ sort / append / reverse 原地修改，返回 None
        ↓
可变 vs 不可变：这是本章所有坑的根源
        ↓
⚠️ 变量是标签，不是盒子
   ├─ b = a       →  同一个列表
   ├─ a.copy()    →  外层新，内层共享
   ├─ deepcopy    →  全部新
   └─ [[0]*3]*3   →  三行是同一个列表
        ↓
⚠️ 传参 = 赋值：函数里「修改」调用方看得到，「重新绑定」看不到
        ↓
⚠️ 遍历时删除会漏删  →  推导式建新列表 / items[:] = ...
        ↓
同一个事实只存一份：次数 = len(history)
```

一句话总结：**每次对列表做操作时，问自己两个问题：这是修改还是新建？这个列表还有谁在用？** 本章十个常见错误里，有七个不报错。

<details>
<summary>参考答案</summary>

1. `[10, 20, 30][3]` 报 `IndexError`（合法索引是 0-2）；`[10, 20, 30][3:10]` 返回 `[]`——**切片越界不报错**。
2. **左闭右开**。和 `range` 一致，和 `randint` 相反（`randint` 两端都包含）。
3. **`None`**。`sort()` 原地排序，返回 `None`。这样设计是为了给出明确信号：「我改的是你手里那一份」——如果它返回排好的列表，你就分不清原列表到底变没变。
4. `append` 把参数**整个**作为一个元素加入（得到 `[1, 2, [3, 4]]`）；`extend` 把参数里的元素**逐个**加入（得到 `[1, 2, 3, 4]`）。`extend("ab")` 会加入 `'a'` 和 `'b'` 两个元素，因为字符串可以逐个遍历。
5. 可变：`list`、`dict`、`set`；不可变：`int`、`float`、`str`、`bool`、`tuple`、`None`。字符串不可变，所以 `upper()` 只能**创建一个新字符串**返回，没法改原来的。
6. **变了**，`a` 是 `[1, 2, 3, 4]`。用 **`a is b`** 证明，结果是 `True`。
7. 因为 `int` 不可变。`y + 1` 创建了一个**新的** `11`，`y` 这个标签被贴到了 `11` 上，`x` 还贴在 `10` 上。没有任何对象被修改。
8. 浅拷贝（`copy()`、`[:]`、`list()`）只复制**外层**，内层仍然共享；深拷贝（`copy.deepcopy()`）**每一层都复制**。浅拷贝后改内层，**原列表的内层也会变**。
9. `[0] * 3` 只执行一次得到一个列表，外层的 `* 3` 复制的是**对这个列表的引用**，三行是同一个列表。`[0] * 3` 本身没问题是因为 `0` **不可变**——给某个位置赋新值是让它指向新对象，不影响其他位置；只有可变对象被共享才会出问题。
10. `scores.append(100)` 是**修改**，调用方**看得到**；`scores = [0]` 是**重新绑定**，只让函数里的局部变量指向新列表，调用方**看不到**。
11. 默认值 `[]` 是一个列表对象，在 `def` 时创建一次。每次不传参数的调用，都相当于执行 `history = 那个列表`——让参数贴到同一个对象上。`history.append()` 是**修改**，所以每次调用的结果都累积在那个共享的列表里。
12. 删掉位置 0 的 `-1` 后，`-2` **前移到了位置 0**，而循环的位置继续前进到 1，看到的是 `3`——`-2` 被跳过了。
13. `items = [...]` 让 `items` 指向一个**新列表**，原列表不变；`items[:] = [...]` **替换原列表的全部内容**，所有指向原列表的变量都能看到变化。默认用前者（调用方不受意外影响）；只在「调用方明确希望自己的列表被改」时用后者。
14. 用返回 `None` 明确告诉调用方「我改的是你那份，不是给了你一份新的」，和 `list.sort()` 的约定一致。如果返回列表，调用方可能误以为原列表没变，或者误以为拿到的是一份独立的副本。
15. `enumerate` 更短、更直接，**不需要额外的下标访问**——少一次 `items[i]`，就少一次写错下标的机会。`start=1` 还能直接让序号从 1 开始。
16. 实测 10 万个元素查最后一个，`set` 比 `list` 快**几千到上万倍**。因为列表的 `in` 要**从头到尾逐个比较**，集合用哈希直接定位（第 1.8 章讲原理）。
17. 因为 `attempts` 永远等于 `len(history)`，两个变量表达同一件事。同时维护的话，**迟早有一个分支只改了其中一个**（比如新加「重复猜测不算」时漏掉一处），两者就对不上了，而且不报错。同一个事实只存一份。
18. 因为下一行要用 `history[-1]`，**空列表上取 `[-1]` 会报 `IndexError`**。用到索引之前必须先确认列表非空。
